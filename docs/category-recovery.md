# Проверка восстановления названий категорий

Проверка 14 октября 2026 года. **Исходные категории не заменены.** Поздние файлы дают кандидатов на имена, однако часть подписей выглядит семантически сомнительно. Найденный словарь пока нельзя считать проверенным описанием октябрьских товаров.

## Что проверено

По полному октябрю: 624 `category_id`, из них 252 имеют ровно один непустой `category_code`, 372 не имеют ни одного. Все 13 515 609 пропусков относятся ко второй группе. Поэтому словарь, построенный только по октябрю, не заполняет ни одной строки. Разные ID могут законно иметь одинаковый код: всего непустых кодов 126.

Из каждого следующего официального файла [REES46 Marketplace](https://data.rees46.com/) скачаны только первые 16 MiB сжатого потока — всего 96 MiB. Это первые несколько часов каждого месяца, **не полные месяцы и не случайные выборки**. Проверены HTTP Range и SHA-256 каждого сохранённого фрагмента; полный gzip CRC этих частичных файлов не проверяется. Последняя незаконченная CSV-строка отброшена.

В объединении фрагментов нашлось единственное название для **205 из 372 безымянных ID**. Эти ID соответствуют 8 846 277 октябрьским событиям: 65,45% строк с пропусками. Для оставшихся 167 ID, или 4 669 332 событий, названия не найдены в проверенных источниках. Отсутствие в префиксе не означает отсутствия во всём месяце. В ноябрьском префиксе новых имён для октябрьских пропусков не найдено.

## Почему найденные имена пока предварительные

Структурная согласованность ID не доказывает правильность текстовой семантики. Примеры из фактических данных:

| category_id | Поздний код | Октябрьские бренды и число событий |
|---|---|---|
| 2053013553853497655 | `apparel.jeans` | Montale — 30 222, Lanvin — 22 295, Versace — 20 319, Chanel — 17 804, Dior — 16 565, Creed — 14 880 |
| 2053013554524586339 | `kids.dolls` | LG — 51 788, Sony — 24 856, Panasonic — 14 063, Yamaha — 909 |

В первом случае совокупность брендов похожа на парфюмерию, во втором — на электронику. Это **предположение по брендам, не подтверждённые имена**. Не исключены ошибки исходной таксономии или изменения её смысла; проверка не устанавливает причину.

Дополнительная проверка пересечения товаров показывает, что поздние `category_id` часто отличаются от октябрьских. Единица этой проверки — уникальная тройка `(product_id, category_id, brand)` во фрагменте, совпавшая по товару с октябрём; это не число событий. Например, для ноября ID категории совпадает у 43 617 из 43 622 таких троек, для декабря — у 6 986 из 38 095, для января — у 3 719 из 34 620, для февраля — у 1 991 из 35 026, для марта — у 777 из 32 776, для апреля — у 766 из 28 852. Простое соединение по `product_id` также не даёт основания переносить позднюю категорию назад без проверки.

В [карточке автора](https://www.kaggle.com/datasets/mkechinov/ecommerce-behavior-data-from-multi-category-store) `category_code` описан как таксономия, созданная при возможности; пропуски часто связаны с аксессуарами. Это описание не обещает полного или безошибочного словаря. Публичного авторского справочника с именами всех 624 ID в ходе проверки не найдено.

## Политика использования

- Хранить исходный `category_code_raw` и отдельный `category_code_candidate`; не подменять пропуски автоматически.
- Хранить URL, месяц, SHA-256 источника, первый наблюдаемый timestamp соответствия, все обнаруженные коды и статус. Несколько разных кодов для одного ID — конфликт, а не голосование большинства.
- Найденный позднее код не считать автоматически доступным в октябрьском временном эксперименте. Вариант с поздним справочником потребует явно указанного допущения и отдельного сравнения.
- Название, предложенное по бренду, поведению или моделью, хранить отдельно как предположение. Числовые ID и диапазоны `product_id` не декодировать в названия без доказательства.
- Эмбеддинги известных 126 кодов можно исследовать независимо от восстановления остальных. Неизвестные категории сохраняют собственные `category_id` и индикатор отсутствующего текста.

## Воспроизведение

После построения октябрьской DuckDB из EDA:

```bash
uv run python scripts/audit_category_names.py --download
```

Повторная проверка уже сохранённых фрагментов без сети:

```bash
uv run python scripts/audit_category_names.py
```

Фрагменты и provenance находятся в ignored-папке `data/external/category-probes/`. Скрипт записывает все 624 категории со статусами `original`, `candidate_only`, `unknown`, `conflict` в `artifacts/category-recovery/category_name_candidates.json`, а сводку — в `category_recovery_audit.json`. Эти производные файлы также исключены из Git. Ни один статус не является автоматическим одобрением семантики для обучения.

Проверка реализации: независимое read-only ревью и повторный запуск на реальных фрагментах подтвердили 252 исходных имени, 205 кандидатов и 167 неизвестных ID. Синтетическая проверка покрыла конфликт кодов, сохранение исходных значений, длинные ID без потери точности, обрыв UTF-8 в последней строке и отклонение неверного provenance. В JSON длинные `category_id` записываются строками.
