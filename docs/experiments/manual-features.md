# 18 ручных признаков: определения и стоимость расчёта

15 октября 2026. TLAB-005. Код принят независимым ревью после исправлений, 18 проверок прошли. Ниже — фактические результаты двух запусков; coordinator отдельно сверил actual provenance, fixed-C outputs и исходные формулы. Модели на этих признаках пока не обучались.

На фиксированных кандидатах B48h рассчитаны 18 числовых признаков. Полный пилот сохранил все 1 226 268 пар и занял 5,13 секунды. Пик RSS процесса — 2,01 GiB. Это подтверждает выполнимость расчёта на текущем Mac; полезность признаков для качества ещё предстоит проверить.

## Определения

[Реестр](../../configs/features/manual-18.json) задаёт типы, единицы, окна и зависимости. [Материализатор](../../scripts/manual_features.py) переводит ограниченный набор проверенных операций в SQL. Произвольные SQL-выражения в реестре запрещены. Это расчёт вручную выбранного набора; автоматический поиск лучших признаков остаётся отдельным экспериментом TLAB-016.

| Единица | Признаки |
|---|---|
| Пользователь | Число view/cart/purchase за 7 дней; уникальные просмотренные товары за 7 дней |
| Пользователь × товар | Число view/cart/purchase за 7 дней; давность последнего view и purchase по всей наблюдаемой прошлой истории |
| Товар | Число view/purchase за 24 часа; уникальные просмотревшие пользователи за 7 дней |
| Пользователь × category_id | Число view за 7 дней; доля этой категории во всех просмотрах пользователя; давность последнего view категории |
| Товар × category_id | Число view товара в текущей категории за 7 дней; число view всей категории; отношение этих величин |

Итого 18 основных колонок, включая числители и знаменатели долей. Дополнительно сохраняются покрытие источника для окон 24/168 часов, возраст наблюдаемой истории пользователя/товара и флаги отсутствия данных. Признаки источников кандидатов сохраняются отдельным одинаковым блоком для всех моделей. Всего в выходе 45 колонок, включая идентификаторы и служебные поля. Downstream runner должен явно выбрать входы модели; идентификаторы и все служебные поля автоматически в обучение не передаются.

Все окна — `[t−W,t)`, давность использует `[source_start,t)`. Точные дубли увеличивают обычные счётчики, уникальные ID считаются отдельно. У известного ключа пустой набор событий даёт count=0; отсутствие прошлого события даёт recency=NULL с флагом. При нулевом знаменателе доля остаётся NULL. Покрытие источника и возраст с первого наблюдения не являются exposure или датой регистрации.

Категория кандидата берётся из последней глобальной секунды строго до запроса. Несколько строк с одной известной ID однозначны. Все NULL означают отсутствие категории; две разные ID или смесь известной ID и NULL означают неоднозначность. NULL учитывается отдельно: обычный COUNT(DISTINCT) его игнорирует. При неизвестной категории условные признаки остаются NULL, а не нулём. Отсутствие читаемого category_code не исключает заполненную числовую ID.

Исторические события сохраняют category_id, записанную при событии. При переходе товара A→B числитель доли внутри B содержит только прошлые просмотры товара с записанной категорией B. Старые просмотры A не переносятся задним числом. Числитель является подмножеством знаменателя; доли проверяются на диапазон [0,1].

## Фактические запуски

Сначала выбраны 100 запросов по SHA-256 query_id без чтения labels. После проверки стоимости выполнен полный пилот. Для каждой стадии сверены принятые входы, сохранены время, RSS и профиль движка.

| Показатель | 100 запросов | Полные 6 000 запросов |
|---|---:|---:|
| Уникальные пары / строки признаков | 20 477 | 1 226 268 |
| Основные числовые признаки | 18 | 18 |
| Полное время, включая подготовку и экспорт | 3,682 с | 5,128 с |
| Пик RSS процесса | 393 330 688 байт | 2 154 364 928 байт |
| Пик buffer memory по профилю движка | 596 526 184 байт | 3 170 382 952 байт |
| Пик временного spill по профилю движка | 0 | 0 |
| Размер Parquet | 120 878 байт | 3 867 108 байт |
| Сверенные принятые fingerprints | 14 | 14 |

Все стадии завершились. Полное двустороннее EXCEPT ALL идентификаторов `(query_id,product_id)` между принятым C и выходом признаков дало 0 различий. В полном пилоте не встретилось отсутствующих или неоднозначных числовых category_id. Доли и counts проходят проверки диапазонов. Покрытие source-окон полное.

Давность view пары отсутствует у 1 190 690 строк, purchase — у 1 225 318, view категории пользователя — у 892 563. Это ожидаемая разреженность, а не потеря строк при join. Счётчики и ratio-supports сохранены.

Ограничения запуска: две нити, запрошенный memory_limit=2GB, spill=2GB, wall deadline=3600 секунд, кооперативная проверка RSS≤8GiB на границах стадий. **memory_limit не является жёстким потолком памяти процесса:** часть структур выделяется вне buffer manager. Это описано в [официальной документации DuckDB](https://duckdb.org/docs/current/configuration/pragmas#memory-limit). В полном запуске profiler buffer high-water также оказался выше настройки; конкретная причина этого расхождения не диагностирована. Измеренный RSS прошёл отдельный ресурсный gate. RSS и buffer counter не складываются.

Стоимость относится к этим запускам, без независимой серии timing trials. Нельзя умножением числа запросов доказать, что вся будущая обучающая коллекция поместится в память. Для расширения запланированы отдельные небольшие shards и разделённые экспорты.

## Проверки и исправления ревью

18 проверок прошли за 0,690 секунды. Основные 12 используют независимый построчный эталон всех признаков и отдельный SQL-эталон. Проверены истечение distinct с повторными событиями, границы окон, давность по полному prefix, нулевые знаменатели, отсутствие текста при известной ID, конфликты последней секунды, изменение категории, последующее уточнение metadata, перестановка peers, добавление будущего и пустые Q/C.

Ревью воспроизвело две ошибки первоначального запуска: заменённые C или upstream code принимались как новые входы, а ранний сбой подготовки не сохранял частичный отчёт. Исправления сверяют код и содержимое с явной приёмкой TLAB-004; используется принятый verify_accepted_inputs из TLAB-007. SHA файла приёмки входит в identity. Отчёт попытки создаётся до чтения реестра, fingerprint-проверок и открытия соединения.

Шесть проверок запуска покрывают полный synthetic E2E, разную identity для ограниченной выборки, замену C валидным Parquet, изменение upstream code, ранний таймаут и ошибку соединения. Сбои сохраняют failed report и не экспортируют признаки. До прохождения этих проверок расчёт на реальных данных не запускался.
