# Label-blind inference arrays — implementation candidate

This is an additive physical data-loader boundary for future reporting-only confirmation/final inference. Ten small synthetic cases pass after a review-found identity fix; actual held-out Q/C/F/Y, predictions and acceptance writes remain prohibited pending independent review, calendar/decision lock and semantic source acceptance. This module grants no data or execution approval.

`load_inference_data` accepts explicit query/base-feature paths and optionally an exact frozen extra-feature projection. It accepts no Y path, discovers no files, performs no query sampling, training, scoring, ranking or evaluation. `InferenceData` carries query triples `(query_id,user_id,anchor)`, sorted group/product keys, float32 matrix and ordered names. It contains no targets or fake empty-Y field. Calendar maturity is a separate boolean vector, never a feature or outcome-dependent filter. Every explicit query stays, including emptyC and a query whose future evaluation is censored.

The numeric model schema is the immutableB41 prefix plus at most3 chosen automatic columns. Raw IDs/clock metadata cannot be model columns. Query metadata is projected explicitly before a generated group index is created, so optional source columns cannot shadow it. The extra export may contain the already selected union12, but the matrix projects only the final frozen program. Base/extra pair multisets must match exactly; duplicated/orphan/cross-user/wrong-anchor/future retrieval keys fail. The helper validates physical numeric types, finite float32 conversion with NULL→NaN, exact int64 IDs above2^53 and deterministic Q/group/item ordering. It does not prove feature formulas or temporal availability of every value; externally reviewed source/protocol/Q/C/F lineage and final model/program choice remain caller prerequisites.

The explicit caps are14000 queries,3080000 rows,≤220rows/query, estimated arrays≤2GiB and streamed chunks≤65536rows. These are bounds for the proposed25 plus26–31 calendar, not permission to open it. DuckDB requests2threads/2GB memory with spill disabled; actual RSS/wall/CPU belong to the later reviewed caller. Requested engine memory and array caps are not hard OS limits. No accepted producer/helper is modified.

The held-out driver must use only create_queries, calendar-derived maturity annotation, candidate generation and manual/selected automatic feature calculation before prediction sealing. Generic003 build/run and the training loader load/createY and cannot implement label-blind inference. All held-out predictions must be sealed before query-level25Y/evaluation opens.25 purchase EVENTS are legitimate strict-past inputs for26+ features; outcome-based selection, semantic repair or refitting afterwards cannot retain the original prospective claim.

Synthetic cases cover poison/outcome-file changes that leave arrays identical, rejection of a Y-path argument, all query triples/emptyC/censored retention, int64 IDs above2^53, NULL/recency masks, exact three-extra projection, duplicate/missing keys, strict past, raw-ID/Inf/cap errors and empty relations. A separate equivalence case explicitly opens its artificialY through the accepted training loader and compares only Q/key/base arrays; this is not the inference path and uses no real data or native model. No full source, real-clock, throughput or model-output correctness claim follows from these tests.

Independent review of the first candidate found a real P1: an optional query column `_group` shadowed the generated index through `SELECT *`. No actual held-out data was read. The original review and failing fixture are retained; the correction uses an explicit four-field query projection and adds a regression that checks every restored `(query_id,product_id)` pair. A second test rejects caller-declared clock metadata even in the base names. Independent retest is still required before code acceptance.
