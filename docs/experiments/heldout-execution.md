# Heldout execution primitives — implementation slice, not a runnable owner

15 October 2026. `scripts/heldout_execution.py` implements the fixed six-role lifecycle, shared absolute CPU/wall allocation, external gate ordering, normalized paths, exclusive slot/context/launch/child-consumption records, exact allocated output vocabulary, typed child receipt/clock/resource checks, dynamic authority repins, late marker rejection and explicit unknown active work on failure. The23 author methods use only temporary synthetic JSON/files, fake role receipts and resource fault injection. No worker process is spawned, source/CBM/target is read, and no execution approval is issued. No actual source/native throughput or resource sufficiency is established.

This slice deliberately has **no CLI, source generation, model API, metric code, approval issuer, arbitrary entry callback or automatic historical438 acceptance**. `Session` takes a previously authenticated plan/claim/request snapshot and rejects arbitrary worker entry paths. The future outer owner must consume its global claim before paid438 authentication, construct/verify the actual whole-decision lock and exact external approval closures, supervise each issued process with the pinned existing process-group helper, compare actual reaped CPU once, validate role-specific semantic evidence, snapshot actual target-opening time, and close its final exit tail externally. Placeholder fixed worker paths do not yet exist; therefore nothing here is runtime eligible. Session construction alone is not owner consumption or authentication.

Fixed method boundaries: `record_gate` compares an authority's original reference and bytes to the caller's independently constructed expected body; it does not derive semantic approval by fresh hashing. `issue` consumes the next fixed role and creates its original context and durable launch. The future worker must verify the parent-issued context SHA and consume its exclusive execution record before paid operations. `accept_receipt` checks the complete bound receipt, output set, input vocabulary, exact consumed record, known failure markers and shared limits; it does not independently check source formulas or native scores. `finish` requires six complete roles and four ordered gates, repins complete outputs/authority/plan, guards finalization and returns only `verified_reporting_pending_external_lifetime_acceptance`. Exceptions during finish persist failure best-effort; missing receipts retain active/unknown state.

Role-specific native-call counts, all-seven source/prediction schemas, actual physical opening time and raw semantic evidence remain outer-owner/worker/oracle gates, not assertions already implemented by this slice. Label flags for the first four roles are false; the last two are true. Target issuance pessimistically marks targets may have been opened before spawn, so a lost receipt cannot claim absence. W=B output vocabulary reuses only B files. Original4200CPU/7200wall and per-role ceilings are **prospective constants requiring review**, not an extra unused016 allowance.
