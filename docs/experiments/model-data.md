# Порционная подготовка model data

Статус: отдельный загрузчик и 10 синтетических проверок реализованы; [независимый code review](../backlog-reviews/tlab-model-data-independent-review.md) принят. Реальные matrices, native Pool и новые модели этим модулем ещё не создавались. Frozen008 loader и принятый metadata100Q producer не изменены.

`prepare_model_data` получает **уже проверенную** development collection и, при необходимости, paths соответствующей фазы отдельно принятого metadata export. Внешние approval/lineage/source gates обязан выполнить вызывающий runner. Сам загрузчик проверяет преобразование данных и ключи; он не выдаёт source acceptance. Разрешены только development train/selection, confirmation здесь запрещён.

Q выбираются тем же bottom-SHA256/query-ID правилом, что в008, до открытия labels. Полный Y хранится отдельно от C: сохранены покупки вне candidate set, emptyC, allnegative и allpositive группы. Каждый кандидат проходит точный one-to-one join с metadata по `(query_id,product_id)`. Проверены ключи Q/user/anchor, строгий past retrieval, duplicate/null keys и metadata cover. Raw IDs используются для join/evaluation и исключены из числовых признаков.

Count, caps и оценка размера массивов проверяются **до allocation**. Максимум 26000Q/5720000rows, ≤220rows×количество Q, ≤2GiB оценённых numeric/object-pointer/key/label buffers; меньшие caps задаёт конкретный experiment plan. FullY ограничен 1000000 query-item pairs. Connection использует 2threads, requested memory2GB, запрещённый spill; внешний callback контролирует wall/CPU/RSS. Эти лимиты не обещают hard process memory bound и не включают будущую память native Pool/fit.

SQL исполняется один раз; `connection.fetch_df_chunk(32)` последовательно читает до65536rows. Используется API connection, а не повторяющий relation execution. DuckDB reference и conversion contract: [Python API](https://duckdb.org/docs/stable/clients/python/reference/), [Python conversion](https://duckdb.org/docs/current/clients/python/conversion). Новых зависимостей нет: pandas уже входит в accepted lock. Integer group/item keys обязаны передаваться nonnullable integer arrays; float transport для них запрещён. Nullable source category IDs вообще не проходят через pandas numeric representation — nominal имеет namespaced string/UTF8bytes.

Массивы preallocated: numeric float32 с NULL→NaN, group int32, item int64, y int8 и, для mixed schema, object matrix из UTF8bytes. Общий cache повторно использует bytes objects. Проверены точный global `(group,item)` порядок через границы chunks, final row fill, отсутствие Inf, namespace и все price/category/reference missing-mask отношения frozen009. Порт vectorized validator сравнивается с frozen producer на его synthetic edge-case corpus.

`ModelData` совместим с008 accounting/ranking API: `feature_names` относятся к numeric matrix, categorical names/array лежат отдельно. Actual mixed009 должен дать56numeric+3nominal=59features; synthetic fixture содержит меньше base columns, это не изменение production schema. Cardinality gate вызывается **только на actual selected TRAIN** перед Pool: `validate_train_cardinality(...,maximum=4096)`, включая sentinels. Selection unseen values допустимы, encoder на selection не обучается, CTR fallback запрещён.

Перед единственным009fit `assert_base_equivalent` должен точно сравнить новый BASEONLY и base part mixed matrix с unchanged0086000 loader: Q/fullY, group, item, labels, numeric column order и все float32 values с equal-NaN. Shape equality недостаточно. Эта проверка не обучает модель. Subsequent runner должен pin accepted inputs/code/environment, атомарно израсходовать один fit claim перед matrix/Pool preparation и выполнить отдельный exact execution approval. Здесь такого runner/approval ещё нет.

10 scoped tests проверяют old/new exact equivalence, fullYoutsideC/emptyC, NULL/masks, label-independent sampling, selection unseen, UTF8 cache/sentinel namespace, capbeforeallocation, duplicate/orphan/missing addon keys, wrong order, infinite values, explicit cardinality boundary4096/4097 и reserved phase rejection. Real DuckDB chunk test2640rows/2chunks сохраняет IDs1152921504606846977…7196 без округления через2^53. Эти тесты подтверждают transformation correctness, а не качество recommendation или готовность реальных матриц.


Code-only acceptance:26independent synthetic checks и10author tests; overflow-type assertion mismatch вinitialharness сохранён отдельно, product отвергал overflow. Actual matrices/Pool/old008 equivalence здесь ещё не выполнены. Runner обязан закрепить exactapprovedfeatureorder: generic suppliedcolumns не typed-grammar approval.
