# Frozen B/W daily prediction core

This additive core accepts the independently authenticated whole-decision lock,
choice and complete seven-date source snapshot. It opens no model itself, has
no CLI/writer/fit/Pool/Y API and grants no execution permission. A future measured
owner authenticates exact file/code/source bytes, supplies `load_model(ref)`,
consumes one context before paid work, supervises lifetime and writes artifacts.
Returned results still need independent native output replay and external seals.

`score_day` selects one fixed25–31 anchor after validating every source date,
count, path reference and calendar maturity. It reuses immutable
`inference_data.load_inference_data` on explicit Q/B45 paths and only W's separate
three-column extra paths. B has41 numeric inputs; W is B or B+3. All query triples,
calendar flags, exact int32 groups/int64 products and float32 feature arrays are
checked, including emptyC/emptyQ, canonical keys, per-query220 cap and forbidden
infinities. NaN remains the reviewed missing-value representation. There is no
query sampling, target field, fake-negative vector or outcome-based filter.

The loaded model must have300 trees, the exact frozen ordered feature names,
no categorical/text/embedding inputs and the same complete native effective parameter
snapshot. Inherited CPU Logloss/depth6/L2=30/seed2026/Plain/No/Newton10 and other
frozen numeric settings are checked explicitly. Learning-rate serialization is
allowed only within the documented native float32 boundary; missing/additional
or differently typed native fields reject. Validation repeats after prediction
so changing native state cannot return successful output. Before the call the
core retains exact Q/calendar/group/item/preparation snapshots and a guarded
bounded-chunk feature-matrix byte witness. After the call it revalidates and
compares every snapshot/witness, including a structurally valid substituted
item key or finite changed feature. Results use retained keys. These witnesses
do not recover or prove the internal native calculation; independent replay
remains required.

Prediction uses a plain ndarray with explicit `RawFormulaVal`, `ntree_start=0`,
`ntree_end=300`, `thread_count=2`. Only finite native float64 vectors with exact
row coverage are accepted. Empty candidate arrays skip native prediction while
retaining all Q. B/W Q and candidate-key arrays must be identical. If W=B, one
loaded model/data/prediction and the exact same result object are reused; the
future owner must transparently reuse its serialized artifact too.

Each `FrozenScores` contains Q triples, calendar flags, ordered group/item/raw
scores, model/source references and preparation metadata. These arrays contain
private keys and must remain ignored run artifacts; the core prints nothing.
`native_prediction_calls` counts only successful core execution. A failed
caller must retain consumed/unknown work through its own receipt and must not
retry under a new destination. Guards run before/after stages and by matrix
chunks; an outer process supervisor is still needed to interrupt native calls
and account CPU/RSS/close/fsync/exit tail. This module has no independent budget.

Twenty synthetic tests use fake model callbacks and small arrays, not actual
CBMs, source tables, native inference or fits. They cover raw scoring arguments,
large integer keys, exact B/W schemas, W=B reuse, all empty populations, prefix/
order/native-param mutation and embedding rejection, score precision/nonfiniteness, NaN versus inf,
duplicate/orphan/changed domains, closed dates, calendar/target-tuple poisoning,
invalid loader fallback, guarded native identity/feature mutations and input
immutability/no file IO. Their scope is
this interface; source formulas, loaded-model byte identity, actual native replay,
all-date prediction seals and gated fullY evaluation remain separate obligations.
