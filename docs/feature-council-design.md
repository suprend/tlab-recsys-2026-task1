# «Совет над H+»: теневой факториал с карточками механизмов

Проект пайплайна, 21.10.2026. Ничего из него не построено и не запущено; датасет для проверки не выбран.

## 1. Зачем и чем отличается от v2 и H+

Факты из работы:
- Агент v2 видел свои эффекты на половине A и принимал признаки по одному. Его +0.0015 на A сжалось до +0.0004 на B и тесте.
- H+ («всё без отбора»: база, 30 таблиц агента, DFS) дал +0.0022 на B 2019 и +0.0030 на тесте 2020. Плацебо подтверждает, что прирост несёт содержание.
- Узкое место — честная оценка: подгонка занимает 450–1100 с, а предложение LLM стоит 34 с и $0.10.

Отсюда шесть решений.
1. **Нулевая процедура — H+.** Колонки эталона H+r входят во все руки. Совет только добавляет семейства. Вычесть он может лишь собственное семейство с доказанным вредом. Если вычитание не откалибровано или не имеет мощности, итог равен ALL_P = H+r ∪ все семейства совета.
2. **Спорим без меток.** Дебаты, аудит, слияния и курирование идут до чисел и по правилам без меток.
3. **Метки трогает только факторный план** PB24 со складыванием: 48 подгонок, у каждой своё зерно. В план встроены пустые столбцы для калибровки, плацебо-семейство как эталон шумового вреда и близнецы-нокауты.
4. **Роли данных разведены.** Отбор идёт на внутреннем срезе train S0. Val и свежий тест — для подтверждения, по одному чтению.
5. **Компаратор уравнен по объёму.** Главный контраст: SEL против H+r⁺ = H+r ∪ R3 ∪ R4. Это ещё два слепых прогона эталонного агента, по числу колонок совпадающие с советом (±10%). Так «обыграть H+» значит обыграть «столько же колонок без отбора», а не просто добавить колонки.
6. **Состав H+r фиксирован.** Его семейства не являются факторами и не вычитаются. Иначе знание с открытых данных (Hdfs − H < 0) превратилось бы в лазейку.

## 2. Роли

| Роль | Видит | Производит | Модель |
|---|---|---|---|
| Координатор (сессия Claude Code) | Всё без меток; β̂ только после коммита SEL | prereg-0/1/2, очередь подгонок (одна тяжёлая), журнал, запрос «да» перед тестом | Opus |
| Генераторы G1–G4 (`claude -p` без инструментов) | Постановку, схемы, формулы базы, атлас, диагностику пробы без меток. В ветке Π — троичные метки | По 8 карточек за волну, одно опровержение | Opus, ≈$0.5/вызов |
| Перекрёстные критики (G чужих линз, автор скрыт) | Чужие карточки, SQL, пробу | leak_risk, redundant_with (только с ρ_wq/R²_wq), mechanism_doubt, kill_test | Opus |
| Скептик | То же плюс уже испробованное (v2, DFS, брейншторм) | Вердикт новизны по сигнатуре «механизм + предсказание + различающий тест», подпись под слияниями | Opus ×2 |
| Аудитор утечек (read-only) | SQL, песочницу, leakcheck, канарейки | Вето только с красным машинным тестом | Opus ×2 |
| Куратор (код + LLM) | Выжившие карточки, матрицу ρ_wq/R²_wq, квоты линз; меток не видит | ≤12 семейств, 4 близнеца в план, бэклог | Opus ×2 |
| Брокер меток (код) | Единственный читает метки | Разрешённые выходы, журнал взглядов | — |
| Слепые эталонные агенты R1–R4 | Контракт xfer: валидность и покрытие без эффектов | Колонки H+r и H+r⁺ | ≈$1.5–3 каждый |

Линзы: G1 — намерение и сессии; G2 — товар, время, сдвиг; G3 — граф совместности и переходы; G4 — промахи базы. G4 видит таблицу страт ошибок базы на хвосте T_fit: модель обучена до якоря, в каждой ячейке ≥200 запросов, доли до 2 знаков. Это единственное исключение из запрета на числа меток. Оно записывается в prereg-0 и в белый список `prompt_number_problems`.

Отдельных ролей статистика, интерпретатора и красной команды нет. Их заменяют код плана с независимым ревью, шаблон механизмов и фиксированные разбивки.

## 3. Поток данных и разделение выборок

Адаптер набора задаёт роли: зазор равен горизонту метки. S0 строится из последних k якорей train. Если якорей мало, как на H&M (6 недельных якорей, горизонт 7 дней), S0 — это доля пользователей по хешу внутри якорей.

| Раздел | Что это | Кто видит числа | Чтений |
|---|---|---|---|
| T_fit | train без S0 и зазора | Обучение; хвост — страты G4 | — |
| S0-explore | ½ S0 по хешу user_id | Брокер → троичные метки (только ветка Π) | ≤1 |
| S0-select | ½ S0 | Только код правила, имена захешированы | 1 (план) |
| C_val | val | Брокер → вердикты кодом | 1 |
| C_test | свежий период или holdout | Брокер, маркер `test.started`, после «да» владельца | 1 |

- **Метки отделены физически.** На REES46 `label` и `n_targets` лежат в тех же `days6/*.parquet`, что и признаки. Их читают `exp._read`, `read_day`, `placebo.run`, а `extra.compute` делает SEMI JOIN по тому же файлу. Поэтому дни делятся на frame и `sealed/labels` по образцу `SEALED_FILES` в xfer; `_read`, `read_day`, `per_query` и `placebo.run` переписываются. Тест по AST проверяет, что путь к меткам строится только в Брокере. Против координатора с bash это остаётся соглашением, и в prereg так и записано.
- Текст для LLM проходит тест `prompt_number_problems`.
- **Режим логирования (prereg-0).** Доли типов событий по дням в S0 и C различаются не больше чем в 1.5 раза. На REES46 2019 это нарушено: с 8.11 корзин вчетверо больше. Если условие нарушено, проверка режима идёт на двух фолдах; при расхождении знаков SEL = ALL_P.

## 4. Стадии и гейты

0. **Контракт, мощность, Брокер.**
   - До кода считается мощность вычитания по существующим пометрикам (`artifacts/task1/v2020/exp/pl20_*.parquet`, `v2/exp/grid_*`). Оценки: S0-select ≈10.6 тыс. запросов при k=5, SD парной разности 0.02–0.03 для семейства, SE ≈0.0003–0.0004.
   - Нулевая репетиция симулирует план с этими σ.
   - *Гейт:* мощность вычесть посаженное −0.0005 должна быть ≥80% при k=7. Иначе вычитание объявляется описательным: SEL = ALL_P по построению, план служит только для механизмов. Это вероятный исход, оценка критика — 0.2–0.35.
   - Порог SD пустых t-значений берётся из репетиции.
   - Тест AST должен пройти. Коммит prereg-0 со штампом кода и журналом отклонений. Первое отклонение: на REES46 R1 = SQL v2, который видел свои эффекты на A.
1. **Эталон.** R2, R3, R4 работают параллельно по контракту xfer, по 30 предложений. На REES46 R1 = замороженный SQL v2 плюс DFS, пересчитанный на новом периоде. H+r = база + R1 ∪ R2; H+r⁺ = H+r ∪ R3 ∪ R4.
   - Пробная подгонка H+r⁺ идёт отдельным процессом и меряет пик памяти. Сейчас `placebo.peak_gb()` — это `ru_maxrss` за всю очередь: в `runs.jsonl` 2020 значение 25.8 ГБ стоит и у H на 80 признаках.
   - Если пик выше 30 ГБ, ширина режется симметрично у совета и у R3 ∪ R4, чтобы паритет объёма сохранился.
   - *Гейт:* check_sql, leakcheck (§10), заморозка хешем.
2. **Волна 1, слепая.** G1–G4 независимо сдают по 8 карточек (§5).
3. **Доказательства без меток.** Для карточки, близнеца и соперника считаются: валидность, покрытие, инвариантность к срезу и батчу, ρ_wq и R²_wq к базе и H+r, форма близнеца, паритет не-NULL по популяционным стратам (у Tinkoff и Сбера — прокси-популяции Kaggle).
   - *Гейт:* вето Аудитора.
   - Слияние при R²_wq ≥0.9 или max|ρ_wq| ≥0.95.
   - Паритет вне [0.5·min, 2·max] — снятие.
   - Близнец: заполненность ±10% и ρ_wq ≤0.8, иначе TWIN-BROKEN.
4. **Перекрёстный допрос** (§5), затем кураторство без меток.
   - *Гейт:* у каждой карточки ≥2 типизированные критики, простых оконных агрегатов ≤20%.
   - Коммит prereg-1: хеши SQL, предсказания знака и страта, kill_test.
5. **Волна 2** проходит стадии 2–4 с учётом критики и открытых областей атласа. По умолчанию меток нет.
   - *Ветка Π (необязательна).* Прокси Π — CatBoost с `Pool(baseline=OOF-маржа базы)`: маржа по 4 фолдам пользователей T_fit, 100 деревьев. Банк калибровки строится на наборе кампании: ≈15 контрастов × 2 полные подгонки. Π включается, только если Spearman с банком ≥0.6, знак верен при |Δ| ≥0.001 и канарейка (up_ как кандидат-блок) выше q95 нуля. Тогда генераторы получают троичную метку S0-explore с нулём из 20 переставленных псевдокарточек.
   - Чистая волна 1 сохраняется как рука W1.
   - *Гейт:* ≤12 семейств; суммарная ширина совета равна R3 ∪ R4 ±10%.
6. **prereg-2.** Замораживаются семейства, H+r, H+r⁺, матрица и зёрна.
   - 23 фактора: 12 семейств, 4 близнеца, 1 плацебо-семейство (4 колонки совета, переставленные хешем внутри дня), 6 пустых столбцов.
   - Глубина фиксирована: 8, как `RECIPE` в `xfer_common`.
   - Также фиксируются код анализа, правило, δ_min, тексты вердиктов, критерий механизма.
   - *Гейт:* два независимых ревью и коммит раньше первой подгонки.
7. **План.** 48 подгонок через `placebo.run`: `cap`, штамп кода, атомарная запись, `validate`. Очередь `placebo.run_queue` возобновляемая, план идёт две ночи. Брокер отдаёт коду Y[подгонка × запрос] на S0-select. Упавшая подгонка перезапускается с тем же конфигом.
   - *Гейт:* калибровка (§6), иначе SEL = ALL_P. Если D ≠ ∅, подтверждение свежими подгонками. SEL коммитится до раскрытия.
8. **Раскрытие** по шаблону механизмов. SEL не меняется.
9. **C_val, одно чтение.** Руки учатся на всём train (T_fit ∪ S0 ∪ зазор):
   - H+r⁺, SEL, SELpl, H+r, ALL_P, W1 — по 2 зерна;
   - плюс рука-близнец механизма (§7).
   - Если SEL = ALL_P, руки схлопываются. MDE считается до чтения.
   - C_val останавливает тест только техническими гейтами (конечность, паритет, пол Pop). Эффект на C_val тест не блокирует. Так записано в prereg-2.
10. **C_test один раз**, после «да» владельца в чате. Refit на train+val. Руки H+r⁺, SEL, SELpl ×4 зерна; H+r, ALL_P ×2. Квитанция коммитится сразу.
11. **Отчёт.** Описательные разбивки: сегменты, зёрна, сдвиг популяции, коэффициент сжатия, бэклог.

## 5. Механика спора

**Карточка** состоит из пяти частей:
- механизм;
- различающий страт — SQL-предикат по истории до t: где прирост должен быть и где его быть не должно;
- SQL на 1–4 колонки;
- близнец-нокаут той же формы с разрушенным механизмом: время переставлено, соседи перемешаны внутри «категория × дециль популярности», семена убраны. Перестановки делаются только хешем, без `random()`;
- соперничающее объяснение со своим стратом.

**До чисел:**
1. Генераторы пишут вслепую.
2. Каждую карточку критикуют двое из чужих линз и Скептик, автор скрыт. Автор отвечает один раз: правит карточку (стадия 3 заново) или снимает её.
3. Голосования нет, спор разрешается по типу:
   - LEAK — вето с машинным доказательством;
   - DUPLICATE — только число R²_wq;
   - SHIFT — паритет;
   - стоимость — таймаут песочницы;
   - сомнение в механизме и RIVAL становятся kill_test в prereg-1: близнец как фактор, разность разностей по страту, уровень ключа, устаревание на t − 24 ч.
4. Нерешённое остаётся включённым.
5. Предсказания знака и страта пишутся до чисел.

**Куратор** сливает и режет только по R²/ρ и квотам линз. Его правило — код, без меток. Поэтому ALL_P − H+r⁺ измеряет вклад генерации и курирования без обратной связи. В ветке Π к этому добавляется обратная связь, и это отдельно видно по W1 против ALL_P.

**После чисел** работает только код. Spearman предсказанного знака с β̂ — описательный эксперимент «знает ли LLM эффект своих признаков». Квоты линз по нему меняются только в следующей кампании.

## 6. Правило отбора и статистика

**Модель.** y_r — средний NDCG@20 подгонки r по S0-select: y_r = μ + Σβ_g·x_rg + ε, x ∈ {−½, +½}.

**SE.** Пользователи S0-select бутстрапятся совместно по всем 48 строкам Y, на каждой реплике заново считается OLS. Итог: SE = √(SE_boot² + SE_empty²), где SE_empty — разброс оценок 6 пустых столбцов. В PB24 со складыванием главные эффекты и пустые столбцы свободны от двухфакторных взаимодействий: те уходят в 24 цепочки алиасов. Остаток OLS поэтому не используется как оценка шума.

**Калибровка.**
- SD t-значений пустых столбцов лежит в интервале из нулевой репетиции.
- Westfall–Young max-T по пустым столбцам даёт p ≥0.05.
- Плацебо-семейство пустым не считается: истинный β у него, вероятно, < 0. На val 2020 в `placebo-2026-10-21/result.json` P = −0.00036 и −0.00082 по зёрнам, второе с CI ниже 0. Оно служит положительным контролем вычитания: правило должно его номинировать, если мощность есть.

Если калибровка не прошла, SEL = ALL_P.

**Вычитание** (только при пройденном гейте мощности стадии 0):
1. Номинация: D = {g ∈ семейства совета : t_g < −2 и WY p < 0.1 по вреду}.
2. Подтверждение свежими подгонками: ALL_P против ALL_P \ D, 2 пары новых зёрен, оценка на S0-select. Требуется одностороннее t > 1.64 при двухуровневом бутстрапе «запросы × пары». Иначе D = ∅.
3. Это защищает от шума запросов и зерна, но не от дневных шоков: S0 состоит из k общих дней. Ограничение записано.

**Итог:** SEL = H+r ∪ (совет \ D). Добавлений по меткам нет.

**Множественность.**
- На экране — WY; BH q ≤0.1 — только отметка для отчёта.
- На подтверждении — одна главная гипотеза, остальные в фиксированной последовательности.

**δ_min = 0.001.** Это соответствует протоколу «разности < 0.001 не установлены».

## 7. Петля «почему»: эксперименты на механизм

- **Близнец против семейства:** β_g − β_twin. Критерий в prereg-2: «механизм установлен», если t(β_g − β_twin) > 2 на S0-select и знак повторился на C_val. Для этого одна рука-близнец: SEL, где семейство с максимальным t заменено близнецом; семейство выбирает код до C. Иначе ветвь механизмов провалена. Классы: «механизм», «форма без механизма», «не различено».
- **Пары.** PB24 двухфакторных взаимодействий не оценивает. Для 1–2 пар, выбранных в prereg-2, ставится отдельный 2² по 2 зерна — проверка тезиса H+ о совместном сигнале.
- **Меню вскрытия** (описательно, после SEL):
  - M2 — плацебо по ключу (`permute_by_key`);
  - M5 — доза–ответ по окнам 3/7/14;
  - M7 — подстановка ближайшей колонкой базы;
  - M9 — только покупки против корзин и покупок.

Примеры:
1. **REES46, G3.** Двухшаговая диффузия от семян возвратов. Близнец — перестановка соседей с сохранением степеней. Страт — цель вне 1-шаговых соседей (cf_ = NULL). Соперник — популярность категории.
2. **REES46.** «Семена возвратов» против «семян по давности» (r6p1, cf_). Страт — пользователи с ≥2 сессиями-возвратами.
3. **Tinkoff, M4.** Контраст «пользователи как в тесте Kaggle против остальных» по прокси-популяции из static.duckdb. Гипотеза выведена из dev, поэтому якорь внутри dev для неё не свеж.
4. **СберМаркет.** Сужение ценового коридора в последнем заказе. Страт — давность >20 дней. Паритет проверяется до плана.
5. **Источники кандидатов.** ≈48% целей вне кандидатов. Отдельный трек: recall при фиксированном K на хвосте T_fit, ≤2 гипотезы за ночь.

Замена групп базы («убрать cf_») в главный план не входит. Это отдельный 2² в следующей кампании.

## 8. Бюджет

**Ширина** на REES46: база 80, DFS 128, агент 66 → H+ 274. H+r ≈340, H+r⁺ ≈470, SEL ≈470. Средняя подгонка плана — ≈415 признаков.

**Время подгонки** по `runs.jsonl` 2020: fit ≈373 + 1.16 с на признак сверх 80, prepare 44–73 с, predict 19–57 с.

| Этап | Подгонки | ч |
|---|---|---|
| Песочница: ≈220 SQL × 29 с плюс расчёт на днях C | — | ≈2.5 |
| Пробная подгонка, пик памяти | 1 | 0.3 |
| План PB24×2 | 48 × ≈870 с | ≈11.6 (2 ночи) |
| Подтверждение D (если D ≠ ∅) | 4 × 900 с | 1 |
| Пары 2² | 8 × 870 с | ≈2 |
| C_val | ≈13 × 940 с | ≈3.4 |
| C_test (train+val) | 16 × ≈1100 с | ≈5 |
| Ветка Π (необязательна) | OOF 4 + банк 30 + экран 80 × 100 с | ≈8 |

**Итого** без Π ≈26 ч, четыре ночи; с Π — пять.

Не учтены построение нового периода REES46 (скачивание, дни, кандидаты, DFS) и адаптеры других наборов: их стоимость меряется отдельно до выбора.

**LLM:** ≈32 вызова, $10–25. Эталон R2–R4: $5–9.

## 9. Предрегистрируемый критерий успеха

**H1.** На C_test Δ1 = SEL − H+r⁺ удовлетворяет трём условиям:
- нижняя граница одностороннего 95% двухуровневого бутстрапа (запросы × 4 пары зёрен) > 0;
- Δ1 ≥ 0.001;
- Δ > 0 не меньше чем на 3 из 4 пар.

Вердикты:
- «обыгрывает H+» — все три условия;
- «не различено» — CI накрывает 0; это провал цели;
- «уступает» — верхняя граница < 0;
- «не решено» — прочие случаи.

**Вторичные, при H1:**
- SEL − SELpl > 0;
- коэффициент сжатия ≥0.5, если D ≠ ∅;
- ни один пустой столбец не прошёл бы правило.

**Описательно:**
- H+r⁺ − H+r — кривая объёма;
- ALL_P − H+r⁺ — вклад генерации совета при равном объёме;
- SEL − ALL_P — вклад вычитания;
- W1 − ALL_P — утечка обратной связи (только ветка Π);
- H+R2 против H+R3 — дисперсия LLM-генерации;
- классы механизмов.

**MDE.** При ≈44 тыс. запросов в C и SD ≈0.048 на запрос MDE ≈0.0006–0.0008. Порог 0.001 выше MDE, поэтому «не различено» — заранее записанный ожидаемый исход.

## 12. Риски, развилки и требования к датасету

**Риски:**
1. **Мощность.** Ожидаемый SEL − H+r⁺ — порядка +0.0005, ниже δ_min. Вычитание, скорее всего, будет описательным. Ценность пайплайна тогда в кривой объёма, вкладе генерации при равном объёме и механизмах с фальсифицируемым критерием.
2. **Одна реализация совета.** Дисперсия генерации оценивается только через R2 против R3. Второй прогон совета стоит +$8 и +1 ч.
3. **Взаимодействия старших порядков** остаются вне плана.
4. **Общие дни S0.** Дневные шоки не развязаны ни разбиением по пользователям, ни свежими зёрнами.
5. **Одна модель во всех ролях.** Слепые пятна коррелированы; разнообразие меряется числом областей атласа и ρ_wq между линзами.
6. **Знание LLM о публичных решениях.** Эталон R имеет тот же канал.
7. **Брокер против bash-координатора** — соглашение, а не принуждение.

**Открытые развилки:**
- k = 5 или 7;
- train_frac 0.5 в плане (только при согласии с банком);
- включать ли ветку Π.

**Требования к датасету:**
- (а) свежий, ни разу не открытый C_test. У REES46 его нет: тест 2020 открыт, val 2020 прочитан плацебо;
- (б) ≥20 тыс. запросов в S0 и ≥40 тыс. в C;
- (в) один режим логирования в S0 и C;
- (г) зазор между T_fit и S0 равен горизонту метки;
- (д) для наборов с Kaggle — описанная целевая популяция.

**Кандидаты:**
- REES46 март–апрель 2020: нужны скачивание, `period.py` и проверка режима (локдауны);
- H&M: последние недели как C_test, S0 по пользователям;
- Tinkoff и Сбер: якорь внутри dev свеж по меткам, но не по гипотезам, выведенным из dev.
