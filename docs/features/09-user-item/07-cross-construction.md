# Автоматическое конструирование user × item взаимодействий

15 октября 2026. Независимое исследование; ниже предложения, а не результаты обучения. Прочитаны общий brief, user-item brief, `docs/backlog.md` и `docs/task1-requirements.md`; новые записки коллег не использованы. Target, horizon и окончательный split не принимаются за пользователя.

## Основания и область

Task1 требует экспериментально проверить автоматизацию либо альтернативу против хорошо настроенного бустинга. Два smoke fits TLAB-008 недостаточны для статуса сильного контроля B. LLM/API условием не требуются. [AutoCross](https://arxiv.org/pdf/1904.12857) предлагает beam search категориальных crosses, дискретизацию и ускоренный отбор; показанный выигрыш линейных/глубоких моделей не доказывает прирост над нашим CatBoost. Предлагается существенно меньшая, проверяемая грамматика над registry TLAB-005, а не воспроизведение распределённой системы AutoCross.

Строка результата — `(u,i,t)` только для фиксированных candidates. История UTC `[t−7d,t)`, обновление после прогнозирования всей секундной группы. Тип примитива хранит entity keys, event type, окно, grain, unit, coverage, support и fit-cutoff. Разрешены деление совместимых счётчиков, логарифм положительного безразмерного отношения, произведение долей и tuple-cross категорий. Запрещены арифметика ID, смешение events/distinct-users, незаявленные разные окна, автоматическое трактование purchase/view как CTR. Название «любит» означает лишь наблюдаемую активность: показов и отрицательных предпочтений нет.

## P0: минимальная грамматика

Пусть `n_uc` — просмотры пользователя в category_id кандидата, `n_u` — все его просмотры; `n_c,N` — соответствующие глобальные просмотры. Все четыре счётчика имеют единицу «событие», одну историю и политику дублей. `q_c=n_c/N`; предлагается сглаженная affinity `a_uc=(n_uc+αq_c)/(n_u+α)`, α=5 просмотров как заранее заданная константа. Значение безразмерно, supports `n_u,n_c` сохраняются; `N=0` означает missing. При `n_u=0` prior допустим только вместе с cold-history flag. Численный α — предложение, не оценка оптимальности.

Для item `i` в этой же категории `p_ic=n_i/n_c`. Кандидат `z=a_uc·p_ic` — безразмерное соединение пользовательской affinity и локальной популярности товара. Оно действительно меняется по пользователю и кандидату, но не является вероятностью покупки. Сильный B уже содержит исходные shares/counts; поэтому эксперимент проверяет полезность явного взаимодействия сверх доступных деревьям компонент, а не наличие новой информации. Требовать `n_c>0`; известный `n_i=0` даёт настоящий ноль. Supports переиспользовать, не дублировать колонки.

Грамматика глубины один, фиксированное окно, числовые пары из whitelist. Канонизация выражений удаляет `a·b`/`b·a`, константы и уже имеющиеся shares. Категория берётся as-of по ID, без восстановления текстового имени. Аналог по brand — следующая гипотеза, не автоматическое умножение вариантов.

## P1: lift, PMI и categorical combinations

Из того же пространства событий: `lift_uc=(n_uc/n_u)/(n_c/N)`; `PMI_uc=log₂(lift_uc)`, единица PMI — биты. Это event-weighted association, а не сходство аудитории distinct-users. Определение отношения совместной вероятности к произведению маргиналов соответствует [Church–Hanks](https://aclanthology.org/J90-1003.pdf); перенос на user-category здесь предлагаемый. Для устойчивого варианта `lift_s=a_uc/q_c`, с предложенными gates `n_u≥5,n_c≥20,q_c>0`. Недостаточная поддержка — missing, не ноль. Сглаженный логарифм уже не точная эмпирическая PMI; оба варианта одновременно не добавлять. Редкие категории способны доминировать без поддержки; clipping, если нужен, fit только на warmup.

Категориальный кандидат — tuple `(user_past_favorite_category_id, candidate_category_id)`, а не произведение ID. Favorite выбирается по past views, tie-break детерминирован; отдельные EMPTY и unseen tuple. [Документация CatBoost](https://catboost.ai/docs/en/references/training-parameters/ctr) определяет `combinations_ctr`, `max_ctr_complexity` и CPU-ограничение числа листьев `ctr_leaf_count_limit`; последнее снижает память, но может менять качество. Глубину combinations фиксировать ≤2, включение считать отдельной абляцией. Полная пара user_id×product_id имеет огромную кардинальность и повторяет direct history; для первого поиска отклонить.

## P2: rates и временная зрелость

Target encoding `r_g(t)=(Σy_a+βπ)/(m_g+β)` использует только строки группы g, чьи outcome endpoints уже закрылись к t с учётом delay; support `m_g` — число зрелых candidate-anchor rows. β — фиксированная масса псевдострок, π — prior по зрелому warmup; `m_g=0` возвращает prior с флагом. Sampling/weights negatives и query-grain фиксируются: rate зависит от генератора candidates. Наблюдавшиеся purchase counters — другой объект и не требуют ожидания нового horizon.

[Ordered statistics CatBoost](https://papers.neurips.cc/paper/2018/file/14491b756b3a51daac41c24863285549-Paper.pdf) уменьшают target leakage, но случайная перестановка не обеспечивает event-time maturity. Сортировки timestamps также недостаточно при перекрывающихся horizons. Для внешних encoders нужны forward snapshots с mature outcomes либо warmup-fit/freeze до первого downstream anchor; prior, bins, словарь и clipping подчиняются тому же правилу. Обучение supervised модели на зрелом train при fit-cutoff отделяется от построения признаков ранних train rows. Не объявлять встроенные target CTR strict-past без отдельного аудита.

## Проверка, стоимость и решение

TLAB-016 имеет общий, не персональный каждому исследователю потолок: ≤12 новых materialized columns, ≤4 validation fits, ≤2 CPU-часов включая preparation, failures и scoring. Предлагаются четыре заранее фиксированных fits: B, B+ручной блок, B+grammar block, B+random-grammar block; одинаковые размеры блоков, seeds, loss, candidates, anchors и budgets. Численные блоки выбирать без validation labels по provenance/support; это бюджетная генерация, не полноценный адаптивный AutoCross. Флаги также оплачиваются колонками. CatBoost-combinations/P2 не помещать дополнительно без явной замены ветви.

Разработка — 22–23 октября; последние 24–25 заранее резервируются для однократного подтверждения зафиксированного победителя против B, без новых fits/early stopping. Зрелость зависит от H; для H=24h нужна граница 26 октября. Если эти дни уже использованы, подтверждением их назвать нельзя. [Cawley–Talbot](https://www.jmlr.org/papers/v11/cawley10a.html) показывают selection bias от оптимизации критерия: bootstrap на выбранном development winner его не устраняет. Promotion — предзаданные ΔNDCG20/Recall/cost gates backlog; срезы cold/repeat/low-support обязательны.

Материализация sparse observed keys плюс O(candidate rows), без user×catalog; scan/state могут доминировать. Первые 100 queries измеряют RSS, elapsed/CPU, active keys; общий cap не обещает скорость. Пять edge cases: нулевая история; отсутствующий brand при известном category_id; покупок больше просмотров; события одной секунды; редкая категория с lift≫1. Golden oracle и future-suffix invariance должны проверять именно их. Own contribution допустим в event-affinity, но трактовка «другие пользователи» требует вычитания пользователя до маргиналов.

HYP-059 предлагается отклонить как дубль HYP-002; механизм грамматики уточнить в существующей записи. HYP-060 оставить deferred для mature target-rate encoding: новая стоимость и риск, доказательств выигрыша нет. ID не переиспользовать; решение принимает координатор.
