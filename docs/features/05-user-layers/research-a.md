# User affinity layers: фиксировать владельца события, проверять полезность над baseline

Дата: 14 октября 2026. Независимое исследование A; предлагаемые параметры — старт эксперимента, не результат измерения.

## P0: объяснимый слой интереса

Начать с dominant-category, затем отдельно проверить dominant-brand; не перемножать их. Профиль пользователя: `h[u,c](t)=count(view,u,c,[t−7d,t))`, категория — исходный `category_id`, атрибут события as-of. Это сохраняет категории без текстового названия. Числовой ID используется как ключ, не величина. Brand-профиль считает только известные бренды и отдельно хранит долю missing; нельзя объявлять отсутствующий бренд «любимым».

Определить `assignment_u(t)=argmax_c h[u,c](t)`, если суммарно ≥5 просмотров и доля победителя ≥0.6; иначе `UNASSIGNED`. Пороги заранее фиксируются; при равенстве максимумов — `UNASSIGNED`. Здесь слой означает доминирующий наблюдаемый интерес за неделю, не тип личности. Для brand нужны аналогичные условия и достаточная доля известных атрибутов. Короткая история данных делает coverage ограничением, которое надо измерить, а не скрыть.

Все времена UTC. На секунде t сначала рассчитываются назначения и признаки для всех anchors, затем применяются события этой секунды. Текущий просмотр не участвует в назначении до своего завершения. Обновлять/истекать профиль можно по событиям, но перед следующим запросом обязательно удалить всё вне окна.

## Владение историей и признаки

Для события e сохранить неизменяемый `owner(e)=assignment_user(e)(time(e))`, вычисленный до его секунды. Тогда

`C[i,ℓ,k,W](t)=Σ_e 1{product(e)=i, owner(e)=ℓ, type(e)=k, t−W≤time(e)<t}`.

Это event-time membership: пользователь может сегодня сменить интерес, но старый просмотр остаётся прежнему слою. Для P0 взять W=7d и отдельно `k=view,purchase`; cart — последующая абляция. Повторные события считаются событиями, не людьми. Ранние октябрьские окна усечены: добавляется `observed_window_seconds`, ноль не означает полную неделю отсутствия спроса.

Альтернатива `C_current=Σ 1{assignment_user(e)(t)=ℓ,…}` описывает активность людей, состоящих в слое сейчас. Она допустима, если каждое назначение использует только прошлое относительно t, но требует переносить оставшиеся события при каждом переходе. Сегментация по полному месяцу с последующим разнесением ранних событий недопустима. Работа Ji et al. показывает проблему игнорирования общей временной линии в оценке рекомендателей; предложенная здесь политика — конкретный способ её соблюсти, не утверждение авторов о слоях. [Первичная статья](https://arxiv.org/abs/2010.11060).

Минимальные признаки на grain `(anchor user, candidate item,t)`:

- `layer_item_views_7d`, `layer_item_purchases_7d`: C для текущего слоя anchor; вместе с `layer_assigned`, числом просмотров профиля и уверенностью победителя.
- `layer_item_share_purchase_7d=(C[i,ℓ,purchase,7d]+αp_i)/(N[ℓ,purchase,7d]+α)`, где `N=Σ_i C`, `p_i=C_global[i,purchase,7d]/N_global`. При `N_global=0` — missing и флаг отсутствия наблюдаемой массы. α — заранее выбранная псевдомасса, например 20, затем чувствительность; это доля наблюдаемых purchase-событий, не вероятность покупки.
- `layer_purchase_mass_7d` и `layer_item_purchase_support_7d`: соответственно N и C без сглаживания. Малый support должен быть виден модели; сглаживание не создаёт доказательств.

Для `UNASSIGNED` возвращать global-share и флаг, сохраняя сырой C unassigned отдельно для диагностики. Пользовательские события внутри слоя могут дублировать user-item history: проверить вариант с вычитанием собственных событий того же owner и окна. Это предпочтительнее объявлять любую слойную активность сигналом «похожих пользователей».

## P1: TF-IDF и устойчивость

На warmup до первого обучающего downstream-anchor построить user×category count-профили. `x[u,c]=L2normalize((1+log h[u,c])·idf[c])` для h>0; IDF считает пользователей-документы, а не события. Сглаженный IDF `log((1+n)/(1+df))+1` и L2-нормализация документированы в [TfidfTransformer](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfTransformer.html). Обучить, например, K=16 MiniBatchKMeans и заморозить vocabulary, IDF и центры. `predict` выбирает ближайший центр; `partial_fit` меняет центры, поэтому запрещён в freeze-варианте. [Официальный API](https://scikit-learn.org/stable/modules/generated/sklearn.cluster.MiniBatchKMeans.html).

Истории validation/test продолжают обновляться, параметры сегментации — нет. Новому пользователю разрешён predict после достаточного support; пустой/OOV-профиль получает `UNASSIGNED`. При warmup-fit нет признаков для более ранних anchors. Forward-refit — P2: хранить model_version, не смешивать одинаковые номера разных кластеризаций. Измерять переходы между слоями, confidence, coverage и размеры; ежедневная фиксация назначения — отдельная абляция устойчивости с явным лагом, не молчаливое изменение семантики.

## Стоимость и проверка

Материализовать ненулевую таблицу `(item,layer,event_type,count)` плюс журнал истечения событий и sparse user-category counts. Плотный user×624 float32 профиль для 3,022,290 пользователей занимает около 7.54 GB только значениями; CSR хранит `data,indices,indptr`, но изменение структуры дорого. Использовать изменяемые sparse-счётчики для потока и CSR для fit-снимка. [SciPy CSR](https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.csr_matrix.html). Плотный item×625 слоя×2 типа int32 — около 0.834 GB на окно; при 17 слоях — 22.7 MB. Это арифметика без очередей, индексов и runtime overhead, не benchmark.

Абляции: strong baseline с user-category affinity, user-item history и global item popularity → +rule layers → +TF-IDF layers; одинаковые anchors/candidates. Отдельно raw/smoothed и self-included/self-excluded. Проверить cold users, ничью категорий, смену интереса с истечением старого owner, пустые покупки, same-second события. Успех — устойчивый прирост выбранной target-метрики по временным срезам и coverage; target, horizon и split остаются решением проекта.

## Review appendix — 14 октября 2026

Для learned layers с fit cutoff τ event-time-owner counters начинаются в τ; признаки более ранних anchors недоступны. Отдельно хранить layer_coverage_seconds_W=min(W,max(0,t−τ)), truncated flag и model_version, помимо покрытия исходного лога. Применение модели τ к событиям до τ допустимо только как явно названный reclassified_snapshot_at_τ для последующих прогнозов, а не как историческое назначение в момент события. Current-membership cohorts сами по себе не утечка, если все назначения и события доступны as-of t; это иной estimand и стоимость.
