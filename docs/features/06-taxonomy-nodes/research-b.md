# Тема 6B. Геометрия путей и распределение интересов вместо набора счётчиков

Дата: 14 октября 2026. Независимый угол: сходство кандидата с прошлым профилем пользователя, разнообразие и перенос сигнала между соседними ветвями. Это предложения экспериментов, не результат измеренного прироста; исследование 6A не использовано.

## Факты и допустимая иерархия

По переданной диагностике October: 126 уникальных `category_code` порождают 159 уникальных непустых префиксов, по глубинам 13/60/85/1. Это описание полного месяца, не доступный раннему предсказанию каталог. Префикс — последовательность сегментов, разделённых точкой; underscore остаётся частью сегмента. Узел `a.b` принадлежит только своему полному namespace: одинаковое слово под другим родителем не означает один узел. Числовые `category_id` — непрозрачные идентификаторы, из их близости, разрядов или общих цифр дерево не восстанавливается. 31,84% событий не имеют кода; нельзя присваивать им имена из последующих месяцев.

Использование таксономии в рекомендациях имеет исследовательский прецедент: Kanagal et al. объединяли её с факторизацией для моделирования покупок. Это обоснование направления, не доказательство пользы конкретных ручных признаков на REES46 ([оригинальная статья](https://arxiv.org/abs/1207.0136)).

## Минимальный P0

Anchor — пара `(user, candidate)` в момент `t`; кандидат и его текущий код должны быть доступны по правилам выбранной задачи. Окно одно: `[t−7 суток,t)`, UTC. Первоначально только `view`, вес события 1: так не смешиваются разные действия произвольными коэффициентами. `N` — число просмотров; `M` — число просмотров с известным тогда кодом. `T(q)` считает события, закончившиеся ровно кодом `q`; `C(n)` считает события, чей путь содержит префикс `n`.

1. **`path_affinity`**, grain user×candidate. Пусть `d(q)` — число сегментов, `l(c,q)` — длина наибольшего общего префикса. Предлагаю `A=Σq T(q)·2l(c,q)/(d(c)+d(q))/M`. Разные верхние ветви дают 0, совпадающие пути — 1. Это адаптация структурной меры Wu–Palmer; равная длина рёбер здесь допущение о каталоге, не измеренная семантическая близость ([первичный источник, формула](https://aclanthology.org/P94-1019.pdf)). Альтернативный P1 — расстояние `D=d(c)+d(q)−2l(c,q)`; одновременно все эквивалентные варианты в MVP не нужны.
2. **`sibling_mass`**, тот же grain: `[C(p)−C(c)−T(p)]/M`, где `p` — непосредственный родитель кандидата. Это масса остальных дочерних ветвей родителя, исключая саму ветвь кандидата и события, остановившиеся на родителе. Она отличает интерес к соседним категориям от точного совпадения. Для верхнего узла признак отсутствует, поскольку искусственный корень не содержательная категория.
3. **`root_entropy`**, grain user: `H=−Σr p_r ln p_r`, `p_r=C(r)/M`, только настоящие узлы глубины 1. Здесь события образуют непересекающиеся группы. Энтропия и её максимум при равномерном распределении следуют из [работы Shannon](https://people.math.harvard.edu/~ctm/home/text/others/shannon/entropy/entropy.pdf); интерпретация как широты наблюдаемого интереса — наша гипотеза. Вместе нужны `M`, `M/N` и флаг отсутствия истории: одно наблюдение не доказывает устойчивую специализацию.

При `M=0` структурные значения missing; при `N=0` coverage тоже missing. Известный путь без совпадений даёт настоящий 0. Отсутствующий код кандидата получает отдельный флаг и missing для двух парных признаков; fallback — обычная доля прошлых просмотров того же `category_id`, `count(user,id)/N`, с явным признаком режима fallback. Это плоская категория, не восстановленный путь.

## P1 и P2

P1: повторить только affinity для `purchase`, отдельно передав purchase-support; добавить `K` посещённых корневых ветвей либо эффективное разнообразие `exp(H)`. Нормировка `H/ln K` при `K>1` измеряет равномерность, но стирает масштаб разнообразия; при `K=1` задать 0, при `M=0` missing. Не делить на `ln 13`: число 13 получено из будущего относительно ранних anchors.

Сглаживание соседей — отдельная P1-абляция: условная доля дочерней ветви `(C(child)+απ(child|p))/(C(p)+α)`. У родителя обязательна отдельная «остановка на этом узле», иначе дочерние доли не образуют распределение. `π` оценивается только до t, либо замораживается после warmup до первой обучающей строки; α подбирается временной валидацией. Простая подстановка parent-count вместо child-count имеет другую гранулярность и не становится вероятностью. P2: обучаемые расстояния/эмбеддинги дерева; без подтверждённого прироста не приоритет.

## Материализация и проверки

Хранить разреженные user×terminal-code счётчики и очередь истечения событий; обновление префиксов стоит O(глубина), affinity — O(число наблюдавшихся кодов пользователя × глубина). Парные сходства кешируются по мере появления кодов. Полная матрица user×159 не нужна; скорость и память требуют замера.

Один просмотр обновляет несколько предков, но знаменатель остаётся одним событием: сумма счётчиков всех глубин не является `M`. Политика дублей должна совпадать с baseline; повторный просмотр не удаляется автоматически. Все прогнозы одной секунды вычисляются до обновления состояния. Проверить пять случаев: новый пользователь; только неизвестные коды; совпадение слов в разных namespaces; код-предок и код-потомок; несколько событий на t и точное истечение на t−7 суток.

Абляции на одинаковых anchors/candidates: baseline → affinity → sibling → entropy; затем ID-only против доступной таксономии, raw против smoothing. Отдельно оценить пользователей с малой историей и кандидатов без кода. Target, horizon и split остаются открытыми: для user-only conversion парные признаки требуют конкретного наблюдаемого anchor-item, для ranking — известной политики кандидатов.
