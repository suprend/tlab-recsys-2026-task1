# Тема 7B: текст как перенос интереса, а не переименование ID

Дата: 2026-10-14. Независимый угол: нормировка пользовательского профиля, одинаковая гранулярность контролей и стоимость. Прочитаны `docs/text-embeddings.md` и три `docs/nlp-*.md`; записка 7A не читалась. Ниже — предложения экспериментов, без обучения и измеренного выигрыша; target, horizon и split остаются открытыми.

## Факты и границы

По предоставленному аудиту October: 126 непустых category_code соответствуют 252 category_id; ещё 372 ID никогда не имеют имени. Brand содержит 3445 значений; пропуски категории — 31,84%, бренда — 14,40%. Нет title, description, query. Это короткие англоязычные пути классификатора и имена производителей, а не полноценный естественно-языковой контент. Числа взяты из контекста/существующих исследований, повторный DB-аудит не выполнялся.

Вывод: dense-вектор может переносить интерес между словами категорий, но одинаковые category_code получают одинаковый вектор независимо от product_id/category_id. Никакой encoder не восстановит различия товаров с одинаковыми входными строками. Соединение категории и бренда меняет проверяемую гипотезу: потенциальный выигрыш может объясняться точной идентичностью бренда.

## P0: минимальный строгий контроль

Общий baseline уже содержит category_id, brand, иерархию и causal user–category/user–brand affinities. Дополнение — user–candidate скаляры для трёх представлений категории: полного code one-hot; полных префиксов пути; слов после разделения `.`/`_`. Namespace префиксов сохраняет различие `furniture.kitchen.chair` и `furniture.living_room.chair`. Brand остаётся отдельным атомарным каналом: `p.i.t.` и `am.pm` нельзя разрушать стандартным word-tokenizer; sklearn по умолчанию игнорирует пунктуацию и односимвольные слова ([документация](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html)).

Предложенный первый профиль: только view, UTC-окно `[t−7d,t)`, веса событий 1; не полный набор типов×окон. Пусть `z_c` — единичный вектор категории, `S=Σ z_c(e)`, `M` — число событий с доступным представлением. Добавить:

- `text_mean_sim = z_candidate·S/M`;
- `text_profile_cos = z_candidate·S/||S||`;
- `text_coherence = ||S||/M`, `text_support=M`, `text_coverage=M/N_view`.

Это разные признаки: `mean_sim=profile_cos×coherence`. L2-нормировка профиля удаляет его длину, а деление суммы на M перед cosine ничего не меняет. Поэтому cosine один не показывает ни поддержку, ни разнородность истории. Для двух ортогональных категорий и кандидата из одной из них среднее сходство равно 0,5, cosine — 0,707. Это математический контроль, не наблюдение данных. Аналогичные формулы применяются lexical и dense; не сравнивать среднее TF-IDF с max dense.

Для TF-IDF: один документ — один уникальный доступный category_code, `idf_j=1+log((1+n)/(1+df_j))`, затем L2. Это штатное сглаживание sklearn ([руководство](https://scikit-learn.org/stable/modules/feature_extraction.html#tfidf-term-weighting)). `N_view=0`, `M=0`, нулевая норма и отсутствующий candidate-code дают технический 0 с отдельными флагами; отсутствие текста не равно нулевому интересу. Не создавать общий семантический вектор `unknown`.

## P1: проверка dense и дополнительных каналов

Сначала frozen MiniLM: 384 измерения, masked mean pooling и L2 согласно [карточке автора](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2). Comparator multilingual-e5-base использует нормированные 768d-векторы и одинаковый `query:` для симметричного сходства/признаков ([карточка](https://huggingface.co/intfloat/multilingual-e5-base)). Многоязычность здесь не самостоятельное преимущество: текущие пути английские. E5 предупреждает о сжатом диапазоне cosine, поэтому единый порог «релевантности» между моделями некорректен.

Строка — детерминированный путь с пробелами вместо `_`; revision, преобразование, pooling фиксируются. Не склеивать многособытийную историю в предложение: усреднять векторы отдельных категорий. Отдельные P1-абляции: cart/purchase-профили с собственной поддержкой; unique-product-day вместо частоты views; точный brand-profile; категория+brand после category-only сравнения. Не заменять ими молча основной профиль.

## P2: ограниченно полезные расширения

BM25 полезнее проверить как candidate-category query к past-user-profile document: насыщение частот и длина истории действительно меняются. IDF и avgdl требуют past-fit; сравнить с простым насыщением счётчиков. На отдельных путях из 2–4 уровней преимущество этих механизмов менее очевидно ([формула BM25](https://nlp.stanford.edu/IR-book/html/htmledition/okapi-bm25-a-non-binary-model-1.html)). Dense брендов, char-n-grams, Qwen/BGE и сырые сотни координат — после измеренного сигнала P1.

## Доступность, стоимость и решающий эксперимент

Vocabulary/IDF/avgdl: warmup-fit до первой training prediction и freeze либо forward snapshots; конец train недостаточен для ранних training-строк. Полные 126 кодов/5987 пар October — диагностика, не ранний каталог. Frozen encoder не устраняет утечку позднего имени. Атрибуты кандидата доступны по выбранному anchor; прошлые события используют наблюдённые тогда атрибуты. Позднее переименование бренда и восстановление имён — отдельный as-of протокол. Все строки одинаковой секунды прогнозируются до обновления истории.

Оценка памяти, не benchmark: 126×768 FP32 ≈0,39 MB; kernel `K_ab=z_a·z_b` ≈0,064 MB. Но плотные профили 3,02 млн пользователей ×768 требуют ≈9,3 GB на канал. Предлагается sparse история category-counts и lookup kernel; mean-сходство стоит O(k) по k наблюдавшимся категориям, norm требует отдельного расчёта/обновления. Полный event×embedding массив не материализовать.

Сравнить baseline → one-hot → hierarchy/TF-IDF → MiniLM → E5; random-векторы той же размерности назначать по category_code, с теми же масками/агрегаторами. Identity-control по category_id несправедливо различает то, чего текст не видит. Проверить общий результат и сегменты: пустая история, весь текст missing, новый code/OOV, одинаковый code у разных ID, смена brand. Кандидаты/anchors одинаковы; retrieval отдельно: текстовые ничьи внутри категории нельзя скрыть изменёнными негативами. Выигрыш dense над lexical и random при отсутствии точного совпадения категории — осмысленное свидетельство переноса, но не гарантия причинной семантики.

## Review appendix — 14 октября 2026

Общий протокол фиксирует event/unique-product weighting отдельно от representation: профиль 7A уникален по product_id и напрямую не сопоставим с event-weighted профилем этой записки. Identity-control по category_code, metadata channels, агрегатор и masks одинаковы во всех ветках. mean_sim=profile_cos×coherence: все три скаляра не обязательны одновременно. Термин causal в описании baseline означает strictly-past доступность, не причинную идентификацию.
