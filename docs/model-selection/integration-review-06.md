# M06: integration review двухбашенного протокола

15 октября 2026. Read-only сверка [M06](06-two-tower.md) с M01–05, [learned space UI06](../features/09-user-item/06-learned-space.md), [embedding protocol](../embedding-experiments.md), target contract и [backlog](../backlog.md). Это короткая integration note, не review всей model-группы 05–08: M07/08 здесь не проверены. Код, зависимости, данные, Git и Root017 runtime не изменялись; fits/измерений не было.

**Вердикт: дизайн совместим с существующей frozen-encoder ветвью после следующих уточнений; новый execution gate не открыт.**

1. **Target заменить на действующий clock.** M06 задаёт `(t,t+H]`, тогда как [accepted provisional config](../../configs/protocols/clock-48h.json) — `[t,t+H)`. Purchase ровно в t входит в target, но отсутствует в history; ровно t+H исключается. Для right-open labels требуется `t+H+delay≤fit_data_cutoff` при source events строго до cutoff; закрытая правая граница потребовала бы строгого неравенства. Это меняет labels, не только обозначение.

2. **Loss корректен как sampled per-positive contrast, но population нужно назвать явно.** Формула усредняет отдельные positive-versus-shared-negatives softmax по `P′=Y∩V_t`; denominator каждой положительной строки включает только её саму и sampled N. Это не multi-positive full-softmax, не BCE на fixed C и не probability возникновения покупки. Определить итоговый `mean_q L_q` по queries с непустым P′ и negative support; остальные дают нулевой training contribution и остаются в полном downstream evaluation. Сохранять причины пропуска отдельно: Y пуст, Y вне V_t, negatives отсутствуют. Uniform sample без возвращения: `m=min(128,|V_t\Y|)`, seed, support/version и multiplicity policy явные. Другая target-positive не становится negative; позднейшая покупка за пределами H не используется для cleaning.

   Encoder может учиться на warmup positives из V_t вне downstream C: это обычное использование train labels в отдельном upstream objective, не oracle insertion в C. Но тогда нельзя утверждать, что все модели имеют одинаковые training rows/support. Сопоставить encoder-популяцию и периоды отдельно; downstream Q/C/full Y неизменны. [Yi et al.](https://storage.googleapis.com/gweb-research2023-media/pubtools/5716.pdf) действительно исследуют two-tower и in-batch correction; их logQ не переносится автоматически на этот uniform contrast. [TFRS Retrieval](https://www.tensorflow.org/recommenders/api_docs/python/tfrs/tasks/Retrieval) предоставляет отдельные knobs, а не доказательство эквивалентности разных sampling losses.

3. **Freeze включает фактическую availability.** Нужна цепочка `encoder_label_end+delay≤encoder_fit_cutoff≤encoder_available_at≤first downstream training anchor`. Веса, vocab, scaler, UNKNOWN/dropout и sampler statistics относятся к этому checkpoint; history обновляется строго до t. Окончить labels к W недостаточно, если сам fit завершён позже первого downstream anchor. All branches используют те же downstream rows после available_at; encoder нельзя fit на всём B и выдавать scores ранних B-строк за past-only. Selection stopping/tuning не читает confirmation. M01–03 уже требуют внешний full-Y criterion; encoder sampled Recall не заменяет его.

4. **История и metadata нуждаются в точном contract.** M06 задаёт последние 50 all-type events, UI06 ALS — view-only rolling7d; это разные inputs, поэтому сравнение не изолирует архитектуру. Для matched pooling/ALS контроля зафиксировать event types, W, weighting, truncation и missing policy. Общая raw-history policy сохраняет точные дубли; distinct target удаляет повторную relevance автоматически, но не разрешает dedup истории. Для кандидата latest global bucket `<t`: known+NULL/conflicting values ambiguous, без older-clean backoff. Event-token attributes принадлежат историческому событию, а не сегодняшней карточке.

5. **Resource ambiguities закрыть до implementation.** «Максимум50» и «целые timestamp buckets» требуют overflow policy. Если один последний bucket содержит51 событие, нельзя одновременно включить его целиком и обещать cap50. Объявить, например, остановку перед crossing bucket с truncation/empty-by-cap flags; row-order/ID выбор исключён. Pool64 + три counts + empty flag даёт68 входов, поэтому `MLP_user:128→64` требует явно указанной проекции/hidden layer. Числа163 MiB ID-state и6.25 MiB activation верны как арифметика выбранных tensors, но не peak RSS/VRAM: metadata towers, gradients, temporary negative vectors, optimizer и loaders добавляются. Необходимы bounded preparation/fit/scoring ledger, deadline/error partial report и отдельная pinned dependency compatibility; GPU и12 GPU-часов M05 не становятся доступным бюджетом M06.

**Дедупликация и маленькая граница MVP.** M06 сама не формулирует HYP-071/072; упоминание номеров не создаёт записи. Frozen two-tower scores уже входят в embedding protocol/UI06, поэтому повторную общую гипотезу не регистрировать. Это не точный дубль ALS: neural shared towers и purchase contrast отличаются от confidence ALS; HYP-051/056 остаются одной ALS-family с pooling-versus-fold-in при тех же V. При необходимости новый neural контраст следует сформулировать отдельно, например ID-only versus ID+metadata при одинаковом loss/history/support/budget, сохранив counterhypothesis, а не продавать freeze как новизну.

Для условного MVP — один dot-trained checkpoint, diagnostic dot/cos/norms и masks на fixed C. Zero-norm cosine математически undefined; epsilon/0 — явный sentinel с mask, не наблюдённый ноль. Отдельно обученные dot/cos variants требуют второго encoder fit; их предложение не расширяет ledger автоматически. M05 candidate-conditioned pooling — другой, более дорогой reranker; он не кешируется один раз на query и не добавляется обязательным ансамблем. ANN, price, event-separated pools, MLP pair-reranker и forward fitting остаются optional/deferred. Strong tuned B и общий reservation/budget обязательны; два smoke008 fits не подтверждают сильный контроль, а сам architecture proposal не закрывает исследовательскую часть task1.
