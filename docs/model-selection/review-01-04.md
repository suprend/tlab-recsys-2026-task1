## Основные исправления перед fits

**1. Выбор checkpoint должен реально использовать full Y.** Все notes правильно отвергают candidate-only IDCG, но M02 оставляет implementation trap: `first_metric_only=True` не отключает default native NDCG. [LGBMRanker API](https://lightgbm.readthedocs.io/en/stable/pythonapi/lightgbm.LGBMRanker.html) прямо сообщает, что metric из model parameters оценивается вместе с custom callback; default ranker metric — ndcg. Нужны `metric="None"` именно строкой, единственная custom full-Y metric с `is_higher_better=True`, точная Q/group привязка и тест фактического monitored name. [Parameters](https://lightgbm.readthedocs.io/en/stable/Parameters.html#metric).

Для XGBoost явно выбрать callback dataset/metric/direction: стандартный early stopping использует последний eval set/metric, callable cost по умолчанию минимизируется. [API](https://xgboost.readthedocs.io/en/stable/python/python_api.html#xgboost.XGBRanker). Для CatBoost отключить неэквивалентный native overfitting detector либо выбирать frozen iteration по внешнему evaluator на selection. Не достаточно посчитать full-Y метрику только после checkpoint, уже выбранного native score. Fixture: три full targets, один покрытый на позиции1 — NDCG≈0.469, не1; добавить target полностью вне C и mature-empty Q.

**2. All-zero группы различаются по objective, а не только библиотеке.** CatBoost PairLogit и LambdaRank пропускают equal-label pairs; BCE сохраняет negative-only сигнал. У LightGBM XE_NDCG equal-label группа размера>1 может давать обновления: [v4.7.0 source](https://raw.githubusercontent.com/lightgbm-org/LightGBM/v4.7.0/src/objective/rank_objective.hpp) использует `Phi=2^label−random` и skip только singleton. Это проверенный source fact, не полезность random signal. Native LightGBM NDCG all-zero даёт1; [metric source](https://raw.githubusercontent.com/lightgbm-org/LightGBM/v4.7.0/src/metric/rank_metric.hpp) подтверждает необходимость external evaluation.

Для HYP-034 общая train-mask `p>0,n>0` — корректный чистый loss-control; evaluation сохраняет **все** зрелые Q и полный Y. «Нет покупки» и «покупка вне C» не сливаются. Сравнение CatBoost PairLogit против LightGBM LambdaRank меняет одновременно learner и surrogate: допустимо как best-package comparison, но не доказательство эффекта tree implementation. Равное число деревьев не означает одинаковую сложность. Query/object/pair weights не взаимозаменяемы; PairLogit mass1 на информативную Q, BCE row weights1/|C|, XGBRanker weights по queries требуют разных adapters. [CatBoost ranking](https://catboost.ai/docs/en/concepts/loss-functions-ranking), [XGBoost LTR](https://xgboost.readthedocs.io/en/stable/tutorials/learning_to_rank.html).

**3. Native categorical не заменяет временной контракт.** M01 верно различает ordered target statistics и реальные label maturity. `has_time` управляет permutations, не embargo/peers; это следует из [официального описания](https://catboost.ai/docs/en/references/training-parameters/common#has_time). Приёмлемый P0 — numeric manual features плюс available candidate_category_id как categorical со стабильным missing token; без raw user/product ID. `one_hot_max_size=4096` — явный proposal, не обязательный default. [Categorical docs](https://catboost.ai/docs/en/features/categorical-features) подтверждают отсутствие CTR для one-hot features и запрет CPU one-hot у PairLogitPairwise, но не обычного PairLogit. Проверить effective parameters/cardinality actual train, включая missing token.

Brand/category_code ещё требуют собственного accepted as-of extraction: manual18 не поставляет эти каналы автоматически. Нельзя добавить их через последний monthly lookup ради соблюдения M01 P0. LightGBM/XGBoost metadata codebooks должны быть train/past fitted, compact typed и с явной OOV policy; BIGINT ID нельзя превращать в float/int32 с потерей идентичности. Native categorical split сам по себе не target encoder. New high-cardinality CTR/priors — отдельная ветвь, а не скрытая смена baseline features.

**4. Author budgets не складываются в исполнительный план.** M02 предлагает12 trials/8h **на семейство**, M03 допускает24GB RSS, M04 — два encoder и downstream fit. Это предложения, не расширения TLAB-008/016. Одновременный search CatBoost/LightGBM/XGBoost/ALS вытеснит задачу автоматизации и создаст больше selection opportunities. Сначала два CPU CatBoost smoke fits в существующем cap; затем **один** заранее ограниченный tuning plan сильного B на selection, с failed/preprocessing/early-stop costs. Confirmation не участвует ни в выборе objective, ни в эпохах/thresholds. Его нельзя считать независимым после такого использования.

## Разрешение гипотез и компактный MVP

**Принять основной путь M01/TLAB-008:** manual18 + фиксированный retrieval input block, CatBoost PairLogit с явными нормированными парами против query-weighted BCE; те же Q/C/full Y, split, metadata/masks и preprocessing. Никаких defaults, автоматически берущих все ID/labels/metadata columns. Initial fits — smoke, затем tuning сильного контроля по [task1 requirements](../task1-requirements.md). Task1 не требует трёх boosters; main016 сравнивает автоматизацию либо выбранную альтернативу с хорошо настроенным B, а не с заведомо слабым стартом.

**HYP-025 — needs-pilot, optional supervised-prior family.** Это не повтор PairLogit/BCE и не ALS: upstream item-only learner обучается на зрелых warmup candidate labels; контроль — сглаженный item-rate на **тех же** labels/query weights. Ни rate, ни logit не purchase/view conversion probability. До первого downstream anchor требуется `fit_cutoff≤available_at≤t`; upstream predictions не backfill-ятся на собственные ранние training anchors. Warmup support/negative sampling/versioned prior и OOV обязаны быть измерены. Native CTR внутри уже прошлого upstream fit не означает future leakage downstream; это не право выдавать его state за доступный до fit. Дополнительные fits резервируются заранее, без бесплатного бюджета поверх016.

**HYP-033 — deferred optional alternate booster; HYP-034 — вложенная loss-ablation.** После сильного B выбрать максимум один вопрос LightGBM: лучший package под одинаковым time/search cap либо XE_NDCG versus LambdaRank на общей mask. Не считать оба исследования обязательными. XGBoost оставить P1 optional robustness/control, с frozen release вместо mutable master для implementation claims; проверенный [v3.4.2 objective](https://raw.githubusercontent.com/dmlc/xgboost/v3.4.2/src/objective/lambdarank_obj.cc) доступен. GPU/external-memory/ensemble — deferred до конкретного CPU bottleneck.

**HYP-056 объединить с HYP-051 как одну ALS-family**, сохранив авторские formulations: внешний контроль B→B+ALS score/support; вложенный HYP-051 — mean-pooling versus confidence fold-in при **тех же V**. Это разные comparisons, но общие factors, inputs и ledger; два encoder dimensions не оплачиваются заново на каждый HYP. Формулы `c=1+αlog(1+count)` согласуются. [implicit v0.7.2 source](https://raw.githubusercontent.com/benfred/implicit/v0.7.2/implicit/cpu/als.py) масштабирует CSR через library alpha и при fit, и при recalculate_user: передавать готовое confidence с library alpha1 и решать систему, не материализовать обратную матрицу.

Для OOV item/profile score unavailable, не настоящий0: отрицательный dot допустим, поэтому нулевая подстановка без mask меняет порядок. Standalone fallback должен задавать порядок missing versus known scores и popularity tie-break без смешения несопоставимых шкал. ItemKNN/HYP-055 — duplicate HYP-001/TLAB-012; сохранить формульные уточнения. BPR deferred: negative sampling и отсутствие штатного fold-in не эквивалентны ALS; repeats автоматически не фильтровать.

## Source, hardware и cost gates

Repo pyproject/lock сейчас не pin-ят CatBoost/LightGBM/XGBoost/implicit; это не доказательство отсутствия пакета в любом окружении. До execution нужна отдельная minimal dependency/version compatibility проверка. Из primary docs подтверждены LightGBM macOS CPU и отсутствие Windows CUDA-пути, [installation](https://lightgbm.readthedocs.io/en/stable/Installation-Guide.html), и текущий XGBoost CUDA≥12.9, [GPU guide](https://xgboost.readthedocs.io/en/stable/gpu/index.html). Windows/RTX3070 availability/VRAM не проверены; optional hardware не prerequisite MVP. Матрица FP32 не равна peak RAM; сначала100-query shape/cost, затем permitted CPU pilot с process RSS/deadline/failure ledger.

Actual007 сообщает104 positive Q и92/121 targets внутри C; это exploratory support, не обученный strong-B result. До promotion нужны sufficient positive/users support, full-Y four estimands, paired uncertainty, repeat/new/OOV/day slices и locked confirmation. Даже хороший screening CI после model search не компенсирует selection bias. Все предложенные extensions сохраняются, но ни одна не должна обходить prerequisite сильного B или незаметно расширять общий экспериментальный бюджет.
