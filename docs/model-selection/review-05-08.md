## Материальные различия перед сравнением

**1. M06/M07 target приводится к единому clock.** Обе notes предлагают `(t,t+H]`; [действующий provisional config](../../configs/protocols/clock-48h.json) использует `[t,t+H)`. Same-second purchase входит в target после pre-update prediction, но history остаётся `<t`; endpoint t+H исключён. Right-open labels зрелы при `t+H+delay≤fit_cutoff`, right-closed потребовали бы строгого неравенства. Отдельная next-event/conversion постановка допустима только как новый protocol ID. M08 правильно отсылает к согласованному Y вместо принятия своего альтернативного target.

**2. Cap50 в M06 и cap50 в M07 измеряют разные объекты.** M05 предлагает около32 последних events, M06 максимум50 events целыми buckets, M07 последние50 timestamp-buckets с потоковым агрегированием сколь угодно большого bucket. Значит, sequence может получить существенно больше raw history: выигрыш нельзя автоматически назвать эффектом порядка. Общий matched input contract фиксирует W, retained buckets/events, event types, attributes, weighting, gap/count features и overflow policy до архитектурной абляции.

Кроме объёма меняется weighting: bucket с десятью A-events и следующий с одним B-event дают raw-event mean10/11 versus1/11, но mean двух bucket tokens —1/2 versus1/2. Для доказательства порядка нужен настоящий pooling по **тем же bucket tokens/weights**, с теми же временными и type summaries. Удаление positional embeddings из causal Transformer не делает всю модель orderless: разные prefix contexts сохраняются. Last-bucket control агрегируется симметрично. M06 hard cap и целые buckets требуют явного crossing-bucket решения; политика08 candidate-note уже задаёт discard crossing+older, но она не подменяет M07 bucket-cap незаметно.

**3. Loss/support также различаются.** M05 sampled BCE может сохранять все mature C-группы, M06/M07 per-positive sampled contrast обучает conditional item choice только при поддержанных positives/negatives, M08 предлагает pairwise logistic для B/H/N на одном downstream pair manifest. Это допустимые методы, но сравнение сразу architecture+loss+population не изолирует представление. Same-informative BCE — отдельный fit, не default replacement all-mature BCE008.

Для M06/M07 совпадают sampler support, число реально выбранных negatives и replacement law. «256 uniform, затем dedup» M07 не эквивалентно128 unique without-replacement: для последнего `m=min(K,|support\Y|)`, для draws сохраняется multiplicity либо inclusion probabilities. Все target positives исключаются из negatives, позднейшие покупки за пределами H не используются для cleaning. Shared denominator всех positives в full-C CE отличается от contrast каждого positive только с собой и N; не смешивать результаты под названием softmax. Коррекция logQ определяется actual law, не названием API. Пустые/unsupported queries остаются в full-Y evaluation.

## Frozen features и самостоятельный learner

M05 candidate-conditioned attention математически корректен как выбранная DIN-подобная адаптация: softmax weights по истории и pair-dependent z. Он не кешируется один раз на user/query и не является ANN dot-retrieval. Mean versus conditional-pooling HYP-063 требует одинаковых item/metadata/numeric inputs, dimensions и loss; убрать attention, а не одновременно pair-features/time channels. Формула DCNv2 `x0⊙(Wxl+b)+xl` подтверждается [первоисточником](https://arxiv.org/html/2008.13535v2); DLRM dot-crosses не реализуют candidate-conditioned history сами. HYP-064 optional после полезного компактного MLP, не третий обязательный neural family.

Развести два временных эксперимента. Standalone neural ranker может fit на зрелом train и оцениваться позже selection: обычное supervised обучение не требует frozen weights до собственных обучающих примеров. Но если его scalar S становится **признаком ранних B-строк downstream boosting**, нужен более ранний warmup encoder: `label_end+delay≤fit_cutoff≤available_at≤first B anchor`. Нельзя fit encoder на B-labels и backfill S для тех же ранних строк. M06/UI06 и M08 правильно задают этот двухэтапный протокол; M05 standalone versus feature-export должен выбирать его явно. Warmup pair manifest отдельный от B-manifest, даже при одинаковой policy.

Vocabulary, scaler, UNKNOWN/dropout, sampler priors и upstream selection относятся к checkpoint. Frozen weights позволяют обновлять strict-past history/as-of metadata, не параметры. Последний глобальный metadata bucket сохраняет known+NULL/conflict ambiguity без older-clean backoff; history token использует event-time attributes. Brand/code не возникают автоматически из accepted manual18. Model-OOV отличается от catalog-cold; epsilon/zero для undefined cosine только sentinel с mask, а не измеренная совместимость0. Один checkpoint проще forward chain: orthogonal rotation сохраняет dot/cos/norm, но retraining меняет score scales/ranks и OOV; Procrustes не устраняет semantic drift.

## Первичные implementation и resource gates

[Оригинальный SASRec sampler](https://raw.githubusercontent.com/kang205/SASRec/master/sampler.py) действительно выбирает users с минимум двумя событиями и очищает negatives по всему user train-set. Для ранних prefixes это использует позднейшие относительно prefix взаимодействия и меняет population. Его нельзя переносить буквально. [Статья](https://arxiv.org/pdf/1808.09781) мотивирует простые sparse-history controls, но результаты Beauty не доказывают REES46 gain. Timestamp-bucket/query-token encoder07 — наша адаптация, не воспроизведение SASRec. GRU session reset и carry-through-user — разные модели; MIND/multi-interest не доказывает ценности порядка.

FP32 arithmetic M05–07 согласована: item table64≈40,7MiB; weights+gradient+два Adam moments≈163MiB;128×50×166794 logits≈3,98GiB; sampled embeddings128×50×257×64 добавляют≈401,6MiB. Это разные tensor allocations, не peak RSS/VRAM. [SparseAdam source](https://raw.githubusercontent.com/pytorch/pytorch/main/torch/optim/sparse_adam.py) создаёт dense moments через zeros_like; sparse gradient не делает optimizer state разреженным. AMP не гарантирует уменьшение FP32 states; foreach/copies/loaders/attention добавляются. Candidate-conditioned scoring требует примерно Q×C×L работы, pooled/query encoding — другой профиль затрат; batch/cap измерять отдельно.

M07 bucket cap ограничивает token tensor, не число читаемых событий в giant bucket; streaming сохраняет память, но scan/aggregation CPU остаётся в ledger. Windows CUDA/MPS support — API capability, не проверенные driver/kernels/throughput текущей машины. Legacy SASRec TF1/GRU лицензии и версии требуют отдельной compatibility gate; никаких installs этим review не разрешено. Author12GPUh M05 и дополнительные seeds/τ variants не являются принятым бюджетом.

## Матрица M08, дедупликация и компактный MVP

M08 полезно отделяет сильный B, H=тот же CatBoost(X+S) и optional N=MLP(X+S). B/H держат manual/retrieval inputs и нормированную pair policy; H/N держат X+S, но смена learner не доказывает эффект encoder. Learned mean-profile S32 должен уточнить W/caps/type weighting по общей спецификации, не использовать неопределённое «все события<t». Механизм freeze уже есть в embedding protocol: HYP-071/072,077/078,083/084 остаются reserved без новых сформулированных contrasts. HYP-052/066 duplicate protocol сохраняются rejected; ALS051/056 — одна отдельная family, не алиас neural tower.

Минимальный prospective neural опыт — один frozen pooled encoder и B→H на fixed C, diagnostic dot/cos/norms/masks, matched last-item/ItemCF control. Cheap-control refit тоже занимает fit slot; если B переиспользуется, его scoring не бесплатен по CPU. Standalone dot требует0 новых fits, но sorting/evaluator/bootstrap оплачиваются. Optional N, conditional pooling, cross layers, sequence, ANN и forward fitting не добавляются все одновременно. Сначала закончить008 smoke и bounded tuning сильного B; представление должно выигрывать над **сильным B**, а не только ухудшенным support-control.

Full-Y evaluator006 действительно выбирает checkpoint по selection predictions, не только пересчитывает отчёт после native stopping. M08 LightGBM `first_metric_only` дополнить `metric="None"` строкой и единственным custom full-Y criterion, иначе native metric может остаться первым. Native best-model truncation CatBoost отключается при неэквивалентном criterion. Rare checkpoint grid/patience — selection attempts с расходом времени, без confirmation leakage.

Общий6CPUh и016≤12columns/4fits/2CPUh включают encoder, downstream/control fits, preparation, failures и scoring; не суммируются по notes. Decision gap после selection labels24Oct00 и first confirmation24Oct00 остаётся prospective gate, не решается доступностью baseline22Oct. Нужны actual selected-model/metrics availability, versioned schedule и timely freeze; confirmation/final holdout закрыты. Primary full-Y NDCG20/Recall guardrail, paired user-bootstrap, cold/repeat/history/day slices и measured limits определяются до run. Завершена исследовательская проверка модельных рекомендаций, но ни качество новой ветви, ни сильный обученный baseline здесь не установлены.
