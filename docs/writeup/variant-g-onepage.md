# Автоматика признаков дополняет настроенный бустинг, но ручных признаков не заменяет

Отбор T-Lab 2026, RecSys, задача 1. Код и документы сделал Claude Code под руководством автора; роли — в конце.

**Ответ.** Все колонки LLM-агента, пишущего SQL-признаки, и DFS (перебор оконных агрегатов) без отбора дали поверх настроенного CatBoost на 80 ручных признаках +2.0% NDCG@20 на свежем тесте 2020 года, доверительный интервал (CI) выше нуля на каждом зерне [по протоколу]. Ручные признаки автоматика не заменила, а пошаговый приём агента оставил 1 признак из 30 с приростом ниже порога шума ≈0.001 [по протоколу]. На отложенных неделях Tinkoff и СберМаркета колонки агента подняли ручные базы на +2.6…+6.2% [holdout с отклонением], на Kaggle этих наборов и H&M — нет [описательно]; OTTO — разведка [исследовательский].

**Метки:** [по протоколу] — тест впервые открыт один раз по замороженной спецификации, CI парного бутстрапа по запросам; [holdout с отклонением] — открыт без отдельного «да» по контракту, правило чтения записано раньше; [описательно] — Kaggle других наборов и разборы после теста; [исследовательский] — OTTO, недели выбора и Kaggle читали много раз.

**Задача (REES46, интернет-магазин).** Пользователю, активному за 48 ч до момента t, ранжируем ещё не тронутые им товары; цель — первая корзина или покупка за 24 ч, метрика — NDCG@20. Валидация 08–13.11.2019 поделена по пользователям на половину для выбора и подтверждающую; тесты — 18–28.11.2019 и 14–29.02.2020.

Принятый признак агента дал на половине для выбора +0.0013 и +0.0017, на подтверждающей — +0.0004 (CI накрывает ноль): падение поймала подтверждающая половина, а не порог. Идея «всё без отбора» возникла на ней после теста 2019 и записана до теста 2020; почему всё сразу держит прирост, не установлено [описательно]. Плацебо с колонками, перемешанными внутри дня, ниже: прирост несёт их содержание, а не число [описательно: post-hoc, на валидации, не на тесте]. Совет LLM-агентов не вычел ни одного семейства признаков и на тесте 2020 не различён с тем же числом колонок без отбора; этот тест и отложенные недели Tinkoff и СберМаркета он читал повторно, это не подтверждение [описательно].

**Три главные оговорки**

1. **Один магазин и порог ≈0.001.** 2020 год — повтор во времени, а не новый домен. Смена зерна сдвигает NDCG половины валидации до 0.0013 [описательно], меньшие разности не установлены; валидацию смотрели многократно, числа на ней после теста 2019 описательные. Бустинг настраивали по одной оси, проверки после теста выигрыша не дали [описательно]; недонастройка базы помогает автоматике. Отступления от контракта: глубину 8 ручной ветке приняли по одному зерну, агенту требовалось два; ветку агента внесли в тест после неподтверждения.
2. **Перенос на Kaggle не подтверждён.** Переносили только агента — новый запуск на каждом наборе — без DFS и перенастройки бустинга. На Kaggle у Tinkoff его колонки ниже базы, у H&M не различены, у СберМаркета не посылались: непустых значений на Kaggle меньше, чем в обучении [описательно]. Правило Kaggle слабое и такой эффект на двух зёрнах не разрешает; у Tinkoff прирост есть только на отложенной неделе, у H&M её нет, а большинство клиентов Kaggle получают одинаковый популярный список.
3. **OTTO — разведка, а не ответ условию.** Агент строил кандидатов и признаки поверх намеренно простой базы, схему с ранкером и правила выбора задал оркестратор (Claude Code). Private (закрытый лидерборд) у базы 0.4906 [описательно], у лучшей итерации 0.5955 <!--OTTO-BEST--> [исследовательский] — это не вклад агента: базу с поздним ранкером не обучали. Приросты на неделе для выбора и на private совпали по направлению, но порог сравнения с правилом без модели смягчили после чисел, неделю Kaggle прочли 8 раз <!--F5-READS-->, остановку по private сняли после срабатывания, набор агента — один прогон, признаки видят более поздние сессии недели (онлайн их нет), посылки поздние, без места; 46 из 51 предложения лучшей итерации аудитор по памяти счёл общеизвестными — придумано или вспомнено, не различается. <!-- если лучшей станет i3: 64 из 71 (O43) -->

**Кто что сделал.** Claude Code (Claude Opus 5.5) написал код и документы, включая проект ручных признаков, и принял большую часть исследовательских решений в заданных автором рамках. Автор выбрал задачу и цель «первая корзина или первая покупка», предложил 3 из 80 признаков, проверку гипотез, повтор на других наборах с Kaggle, совет агентов и цель OTTO — пайплайн сам строит сильную модель; тест 2019 запустил сам.
