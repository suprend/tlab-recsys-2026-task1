## Общий шаблон варианта

1. Заголовок и абзац-ответ (3–5 предложений): что предложено, главный результат с числом, уровень доказательности.
2. Задача и данные — коротко.
3. Метод: что делает агент, что делает человек и оркестратор (Claude Code), что фиксировано.
4. Протокол и защита от утечек.
5. Результаты: одна главная таблица, при необходимости вторая.
6. Выводы: 3–5 пунктов, у каждого метка доказательности.
7. Ограничения: честно, коротко.
8. Ссылки на приложения (существующие `docs/*.md`) и на воспроизведение.

Длина — до 250 строк Markdown (≈2–3 страницы текста без таблиц). Русский, без жаргона, термины объясняются при первом упоминании.

## Метки доказательности

Вводятся один раз и стоят у каждого числа в выводах:
- **по протоколу** — выбор на валидации, тест открыт один раз по замороженной спецификации, CI парного бутстрапа;
- **holdout с отклонением** — проверка по правилу, но holdout открыт после отклонения от контракта или без отдельного «да» по контракту;
- **описательно** — без проверки по протоколу (Kaggle других наборов, post-hoc разборы);
- **исследовательский** — вся OTTO-2/OTTO-3: dev F3 использован для выбора, F5 прочитан многократно.

## Правила для авторов вариантов

- Числа и формулировки статуса — только из [facts.md](facts.md). Нового числа не вводить; если нужного нет — написать об этом в конце файла в разделе «Чего не хватило», а не подставлять.
- Оговорки из раздела «Обязательные оговорки» facts.md входят в каждый вариант, где упоминается соответствующий набор.
- Писать только свой файл в `docs/writeup/`. Остальные файлы репозитория не менять.
- Не цитировать чужие тексты; источники приёмов называть ссылкой.

## Порядок

1. `facts.md` — сводка проверенных чисел с путями к источникам и списком обязательных оговорок; независимая сверка.

3. Независимые судьи читают варианты как проверяющий T-Lab и ставят оценки.
