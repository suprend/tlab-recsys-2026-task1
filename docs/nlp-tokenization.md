# Токенизация REES46 для NLP-признаков

Дата: 2026-10-14. Исследование и предложение; модели и retrieval не запускались. Источник наблюдений — полный October в `data/processed/october.duckdb`, таблица `events`, read-only DuckDB. Названия/описания товаров и изображения в публичной схеме отсутствуют; семантические поля — `category_code`, `brand` ([описание владельца](https://www.kaggle.com/datasets/mkechinov/ecommerce-behavior-data-from-multi-category-store)).

## Что обнаружено непосредственно в данных

126 различных непустых `category_code`: 41 путь глубины 2, 84 глубины 3, 1 глубины 4. В 22 кодах есть `_`; после разделения по `.` и `_` получается всего 161 различное слово. Примеры: `electronics.smartphone`, `furniture.living_room.cabinet`, `electronics.audio.music_tools.piano`. Поле пропущено в 31,84% событий. По дополнительному аудиту root-агента, во всём October 5987 различных сочетаний category_code+brand (включая пропуски); оба поля отсутствуют в 3 740 475 событиях. Это описательная статистика полного месяца, не готовый ранний каталог.

3445 различных брендов, 107 содержат символы вне `[a-z0-9]`, прописных букв нет. Реальные примеры: `tp-link`, `hotpoint-ariston`, `p.i.t.`, `am.pm`, `oral-b`. Пропуск — около 14,4% событий. Бренды — идентификаторы производителей: делить их как обычную прозу опасно.

Проверка стандартного регулярного выражения sklearn `(?u)\b\w\w+\b` на всех брендах показала:

- `p.i.t.`, `v-t`, `s.a.n.`, `k.k.y.` превращаются в пустые списки токенов;
- разные бренды дают одинаковые списки: `cube`/`g-cube`, `max`/`t-max`, `baby`/`i-baby`, `f-power`/`k-power`, `am.pm`/`am-pm`;
- underscore считается частью слова, поэтому `living_room` сам по себе не разделяется.

Документация подтверждает, что стандартная токенизация игнорирует пунктуацию и выбирает токены длины от двух символов. Поэтому нужны явные правила ([sklearn TfidfVectorizer](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html)).

## Три воспроизводимых представления

Общие правила: сохранить исходные поля; новая нормализованная копия = Unicode NFC → trim → casefold. Не удалять дефисы, точки и цифры бренда; не склеивать внутренние пробелы без отдельного аудита. Не переводить, не исправлять опечатки и не добавлять выдуманные подписи. Например, исходные `toster`, `hammok`, `cartrige` остаются как есть. Любой словарь исправлений — отдельная версионируемая абляция с provenance.

### H — иерархические токены, основной baseline

Разделить `category_code` по точке; каждому префиксу присвоить namespace `cat_path:`. Полный бренд — один токен `brand:`. Внутри документа каждый токен встречается один раз.

```
category_code = furniture.living_room.cabinet; brand = hotpoint-ariston
→ cat_path:furniture
  cat_path:furniture.living_room
  cat_path:furniture.living_room.cabinet
  brand:hotpoint-ariston
```

Это сохраняет точный путь и совместную принадлежность к предкам. `furniture.kitchen.chair` и `furniture.living_room.chair` не смешиваются на уровне полного пути. Этот baseline по природе является кодированием иерархии категорий; его нельзя выдавать за доказательство пользы языковой семантики. Сравнить с категориальными affinity-признаками по тем же предкам.

При пропуске категории никаких `cat_path:unknown`, `cat_path:None` не добавлять: иначе большая группа неизвестных товаров получает искусственное сходство. Оставить пустой категорийный канал и отдельный `category_missing=1` в бустинге. Аналогично для бренда. `category_id` сохраняется отдельным категориальным признаком, но не имитирует семантику числами в тексте.

Для sklearn передавать уже готовые списки через callable `analyzer`, например `analyzer=lambda tokens: tokens`; стандартный word tokenizer повторно не применять. У callable-анализатора настройка `ngram_range` не генерирует n-граммы автоматически, поэтому все признаки строятся явно ([параметры analyzer](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html)).

Для основного lexical–dense сравнения использовать **только категорийную часть H**; бренд оставить одинаковым отдельным baseline-признаком во всех ветках. H с `brand:` — отдельный вариант метаданных. Иначе lexical-ветка получает информацию, отсутствующую у category-only dense-ветки, особенно при пропущенной категории.

### W — слова категорий, контроль пользы лексического пересечения

К H добавить уникальные `cat_word:` из разделения категории по `[._]`. Бренд оставить атомарным, без отдельного word-tokenization.

```
furniture.living_room.cabinet → cat_word:furniture, cat_word:living, cat_word:room, cat_word:cabinet
appliances.kitchen.coffee_machine → cat_word:appliances, cat_word:kitchen, cat_word:coffee, cat_word:machine
```

Проверить H против H+W: помогает ли общая часть `coffee` для `coffee_machine`/`coffee_grinder` или это лишний шум. Стемминг/лемматизацию по умолчанию не применять: словарь небольшой, технические слова и бренды могут пострадать; выигрыш не установлен. Stop words не удалять автоматически. Слова вроде `room`, `tools` могут быть слишком общими, но их важность лучше контролировать IDF и абляцией.

### D — строки для готового текстового encoder

Для dense-эмбеддинга не использовать искусственные `cat_path:` токены. Сделать строку категории: разделитель `.` → ` > `, `_` → пробел. Например, `Category: furniture > living room > cabinet.`. Считать категорийные векторы отдельно от брендов; бренд при первом эксперименте оставить точным категориальным affinity-признаком. Это отделяет семантику типа товара от знания encoder о популярных марках.

Использовать штатный tokenizer выбранной модели вместе с её revision и pooling, не предварительный BM25/tokenizer. Для MiniLM пример model card использует `AutoTokenizer` соответствующего checkpoint. Для E5 при симметричном сходстве категорий/использовании векторов как признаков нужен префикс `query: ` для всех категорий; асимметричные `query:`/`passage:` — только для отдельно объявленного retrieval-эксперимента. У длинной истории лучше усреднять векторы отдельных прошлых категорий, чем обрезать гигантскую склеенную строку ([MiniLM](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2), [E5](https://huggingface.co/intfloat/multilingual-e5-base)).

## Символьные n-граммы — низкий приоритет

Если останется время, отдельный канал `char_wb`, диапазон `(3,5)`, для нормализованных строк категорий с пробелами вместо `.`/`_`. Бренд в первом эксперименте не включать: сходство написания разных производителей не обязано означать сходство товаров. Не создавать символьные n-граммы поверх сериализации `cat_path:` — общие технические префиксы дадут ложную близость. `char_wb` добавляет граничные пробелы и не пересекает границы слов, в отличие от `char` ([руководство sklearn](https://scikit-learn.org/stable/modules/feature_extraction.html#text-feature-extraction)). Одна только устойчивость к опечаткам здесь не оправдывает сложность: исходный словарь категорий всего 126 строк.

## Временной протокол

Токенизация — детерминированная функция, она не обучается на событиях. Vocabulary/IDF/BM25 статистики — обучаются: фиксировать их по каталогу товаров, доступных строго до cutoff, и замораживать для validation/test. Единицу корпуса выбирать явно. Для category-only lexical–dense сравнения один документ — одна уникальная доступная строка категории: совпадающие коды разных ID объединяются. Для отдельного category+brand metadata-эксперимента один документ может быть одним товаром в его as-of состоянии; одинаковые тексты разных товаров тогда сохраняются, а DF отражает распространённость в ассортименте. Это другой способ взвешивания, не единственно правильный корпус. 42 млн событий не использовать как независимые документы: они подмешивают поведенческую популярность. Временной снимок бренда обязателен: в EDA у 137 товаров менялся brand.

Для обучающих строк требуется статистика, доступная на момент соответствующей строки: варианты — один snapshot до начала обучающего окна либо последовательные forward snapshots. Нельзя вычислить IDF по всему training-окну и объявить признаки ранних строк строго past-only. Vocabulary, зафиксированный как внешний полный справочник до начала наблюдения, допустим только при документальном подтверждении его доступности; полный October сам по себе такого подтверждения не даёт. Замороженный pretrained encoder не обучается на October, но доступность названия категории на cutoff всё равно проверяется.

Непроверенные восстановленные подписи держать вне первого baseline. Сначала исходные category_code; затем отдельная ветка с подтверждённым восстановлением, флагом источника, временем первого наблюдения и аудитом конфликтов.

## Минимальные проверки при реализации

1. H для `electronics.smartphone` + `samsung` даёт ровно три токена: `cat_path:electronics`, `cat_path:electronics.smartphone`, `brand:samsung`.
2. H для `furniture.living_room.cabinet` сохраняет `living_room`; W отдельно даёт `living` и `room`.
3. `p.i.t.`, `v-t`, `oral-b`, `tp-link` дают непустые разные `brand:` токены; `am.pm` и `am-pm`, `cube` и `g-cube` не склеиваются.
4. Null/null даёт пустой текстовый вектор, similarity=0 и два missing-флага; отсутствует NaN от деления на ноль.
5. Добавление любого события после cutoff не меняет snapshot, vocabulary, IDF и профиль пользователя до cutoff; события ровно на cutoff тоже исключаются.
6. При одинаковых исходных строках токены одинаковы; токенизации history и candidate используют одну версию правил.

## Порядок абляций

Сначала сильный категориальный baseline с `category_id`, brand, иерархией и past-only affinities. Затем категорийная часть H+TF-IDF cosine и H+BM25 с общей токенизацией и корпусом уникальных доступных строк категорий, после этого категорийная H+W, потом D. Бренд остаётся одинаковым отдельным признаком; добавление brand-affinity и переход на per-product DF — отдельные абляции. Одинаковые cutoff, кандидаты, таргет и бюджет тюнинга; отдельно оценивать строки с известной/пропущенной категорией. Не обещать преимущество NLP: здесь текста мало, простая иерархия вполне может оказаться достаточной.

Независимое ревью: исправлено смешение category-only dense и category+brand lexical каналов; уточнён выбор корпуса. Полный план — [nlp-experiments.md](nlp-experiments.md), особенности BM25 — [nlp-bm25.md](nlp-bm25.md).
