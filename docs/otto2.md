# OTTO-2: попытка поднять уровень Kaggle (исследовательская, после OTTO-1)

Запрос владельца 23.10.2026: «а может агент попробует выбить уровень еще больше?»

OTTO-1 (`docs/otto.md`) закрыт: holdout обоих этапов прочитан, файлы F5 посланы. Средний private BA OTTO-1 равен 0.57878. По §10 это «на уровне публичного ноутбука», до порога 0.580 не хватает 0.0012.

OTTO-2 не меняет ни одной квитанции, обучения или гейта OTTO-1. Код находится в отдельных скриптах `scripts/otto2_dev.py` и `scripts/otto2_pool.py`. Они не входят в замыкание `CODE_MODULES`, поэтому identity кода prereg не меняется. Выходы лежат в `artifacts/otto/otto2-dev/` и `artifacts/otto/otto2-pool/`. Признаки, замороженный агентский набор, sidecars и рецепт берутся из закоммиченного prereg через `otto_model.Context.contract()`. Меняются только объём обучения, обучающий фолд и параметры бустинга.

## Статус результата

Результат исследовательский, это не подтверждение. Метки holdout F4 уже открыты и в OTTO-2 используются только как обучающие (`fold_labels(ctx, 4, 'final')`, тот же путь, что у финальной серии OTTO-1). Оценка на dev идёт по популяции F3: 300 000 сессий, метки открыты. F5 оценивается только Kaggle, это повторное чтение F5 после OTTO-1. OTTO-1 прочитал F5 четырьмя посылками (B и BA, по два зерна). Посылка OTTO-2 — пятое чтение, а условная вторая посылка была бы шестым.

F4-модель OTTO-1 даёт на F3 тот же Score, что F2-модель (0.5633). Поэтому сдвиг истории между фолдами при обучении на F4 и оценке на F3 на сравнение почти не влияет. Ревьюер отметил, что история H_4 содержит неделю меток F3. Это не утечка по сессиям: признаки не несут идентификаторов.

Объём данных почти не помогает: от 12.5k до 50k на тип Score растёт на +0.0012, а переход к всем размеченным сессиям F4 (около 974k для clicks, 169k для carts, 84k для orders) добавляет ещё примерно +0.0003 сверх эффекта деревьев. Ансамбль зёрен даёт +0.0001. Помогает больше бустинга: 1000 деревьев с шагом 0.1 дают +0.0011, 2000 деревьев — +0.0012. Потолок кандидатов BA (до 200 на сессию: до 110 кандидатов B и кандидаты агента) остаётся 0.6039 по Score, и OTTO-2 его не меняет.

## Решение до финального прогона (записано до его результата)

Финальная модель OTTO-2: BA, обучение на всех размеченных сессиях F4, покрытых sidecar (`--source 4:all`), шаг 0.1, 2000 деревьев, остальное по рецепту OTTO-1. Имя прогона — `f4all-lr10-it2000`.

Правило выбора файла для Kaggle:
- если Score на F3 у `f4all-lr10-it2000` не меньше, чем у `f4all-it1000` (0.5644), посылается `f4all-lr10-it2000`;
- иначе посылается `f4all-it1000`.

Посылается один файл, с описанием «OTTO-2 … post-hoc re-read F5». Уровень читается по порогам §10 так же, как в OTTO-1, с пометкой, что это повторное чтение F5.

### Изменение порядка посылок (23.10, 21:34 МСК, до результата `f4all-lr10-it2000`)

Обучение `f4all-lr10-it2000` займёт ещё около двух часов. Владелец написал: «отправляй посылку». Поэтому первой посылается `f4all-it1000` — лучшая модель из уже оценённых на F3 (0.5644). `f4all-lr10-it2000` посылается второй, только если по правилу выше её Score на F3 не меньше 0.5644. Так OTTO-2 читает F5 не более двух раз, и вторая посылка выбирается по dev, а не по результату Kaggle. Этот раздел написан до посылки, но в Git попал только вместе с результатом (22d1932). Время «до результата» подтверждают метки артефактов: оценка F5 стартовала в 21:35, файл собран в 21:57, Kaggle принял посылку в 22:07 МСК. Сам Git этого не доказывает.

Уровень пересечён впритык, а не с запасом.
