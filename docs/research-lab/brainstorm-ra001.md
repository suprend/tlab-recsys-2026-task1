## RA-01 — retrieve past situations and their realized purchase continuations

**Primary mechanism.** [RaSeRec, December2024, §3.2](https://arxiv.org/html/2412.18378v1) stores sequence-representation/next-item pairs, retrieves similar prefix keys and augments the current representation using their target values. Its dual cross-attention and neural training are not prerequisites of the proposed cheap adaptation. [Author code](https://raw.githubusercontent.com/HITsz-TMG/RaSeRec/master/recbole/model/sequential_recommender/raserec.py) precaches POS_ITEM_ID embeddings; `precached_knowledge_val` also includes validation targets. Sequence length filtering supplies no global maturity proof. This is a transfer limitation, not an allegation about the authors’ stated benchmark.

**Adaptation and novelty delta.** Store bounded, mature past daily-query records `(prefix_key, purchased_item_set, source_anchor, horizon_end)`. The key represents the last observed `(user,session)` prefix before that anchor: at most eight distinct timestamp buckets, preserving their order; each bucket is an unordered set of action/item tokens. No arbitrary ordering of peers. Retrieve ≤32 other-user memories by a fixed weighted Jaccard of bucket-unigram and adjacent-bucket tokens; vote for their realized purchase values. Empty purchase sets remain in the memory population and contribute no candidate. This needs no text, image, exposure, orderID or encoder.

The object retrieved is a **situation→later-outcome record**, unlike HYP001 item co-audience, UserCF’s unordered lifetime audience, HYP068 max-over-interest groups, or NB-F01’s context before the same user’s previous purchase of the candidate. It can retrieve a SKU never visited by the query user. A matched control uses the identical memory records, outcome values, support gates and lookup budget but keys only the latest timestamp bucket; it tests context conditioning beyond a last-item transition. An ItemCF reference is useful later, but is not the sole novelty test.

**Time and counterhypothesis.** Memory horizon ends must satisfy `s+24h≤fit_cutoff≤available_at≤t`; every prefix event is `<s`. Future query positives never enter the bank. Exclude query-user memories entirely and retain all purchases in tied outcome seconds. At a midnight query the last observed session may be stale; its age is known, its continuation is not. Counter: keys match generic popularity or repeated browsing and sparse memories add noise; category-token backoff might merely duplicate existing profile retrieval.

**Cheapest gate, then finite pilot.** First use ≤24 literal events: identical last buckets but different earlier buckets must retrieve different continuations; changing an unavailable suffix must change nothing. Future no-Y cost probe:100 queries,≤20k frozen memories,≤1m admitted source rows,≤4096 postings visited/query; stop on overflow. Report matches, distinct supporting users and new-to-user candidates. Require≥20 queries with two differing legal continuation candidates before any quality fit. The memory scan/build and matured-label materialization are paid work even without neural fitting.

## RA-02 — exact conjunctive completion, retaining the itemset rather than its projection

**Primary mechanism and boundary.** [HyperHawkes, WWW2025, §4.1](https://pintonos.github.io/publication/peintner-www-2025/peintner-www-2025.pdf) mines frequent session itemsets with FP-Max and uses them as hyperedges. Its Eq2 linear incidence projection does **not** establish exact conjunction-sensitive completion; [author implementation](https://github.com/dbis-uibk/HyperHawkes) is an inspection lead, not a ready-made implementation of this proposal.

**Adaptation and novelty delta.** Retain supported triples `{a,b,c}` from historical `(user,session)` **view sets**, then produce three two-seed completion rules, e.g. `{a,b}→c`. At query, fire only when both seeds occur in the last observed session prefix; score c by the sum of supporting rule weights. Use distinct supporting users, minimum5; one session supplies at most one support unit. Consequent items must belong to U(t). Triple support and a fixed shrinkage rule are fitted state, available before downstream anchors. Limit distinct items/session≤12; sessions exceeding the bound are explicitly out of source support, rather than silently truncated after seeing labels. No learned substitute/complement label is asserted: a session is not a basket, and co-view completion can describe alternatives or noise.

The delta against ItemCF, NB-F03’s directed pairwise action/category relation and HYP067 walks is preserved **joint membership**. Compare against pairwise projection of the same admitted triples, same weights and seeds: a two-seed rule contributes half its weight for each observed seed. Compute support/weights after subtracting the query user’s session contributions in both branches; retain provenance needed for this subtraction. This is an intentionally discrete adaptation; renaming a hypergraph diffusion source would not qualify.

**Hand counterexample.** World A has historical triples `abc, ade, fbe, fdc`; world B has `abe, adc, fbc, fde`. Both worlds have the same item degrees and every pair count. With observed prefix `{a,b}`, exact triple completion retrieves c in A and e in B; any source depending only on that pairwise projection cannot distinguish them. This is a literal mathematical fixture, not REES46 evidence.

**Time, counterhypothesis, gate.** Training session sets contain only events `<fit_cutoff`; no future tail is attached to a prefix. Query-time peers are excluded, within-second permutations must be irrelevant, NULL session is unsupported. Counter: jointly supported triples are too rare or mostly popular substitutes, and exact firing sacrifices useful partial matches. Cheapest check is the eight-triple fixture plus duplicate/peer permutation checks. Future100Q probe caps1m admitted raw rows,10k sessions,50k stored rules and1024 rule postings/query. Require≥20 queries with a firing rule and≥5 other supporting users/rule; count discarded sessions and consequent coverage. Pair mining costs up to66 seed pairs per admitted12-item session; output20 does not bound discovery cost. This source should be deferred if its support gate fails.

## RA-03 — a delayed intent-return bump over multiple observed episodes

**Primary mechanism.** [HyperHawkes §4.3, Eqs8–12](https://pintonos.github.io/publication/peintner-www-2025/peintner-www-2025.pdf) combines exponential and Normal timing kernels for same-intent events across sessions. The [released model, lines137–166](https://raw.githubusercontent.com/dbis-uibk/HyperHawkes/main/recbole_custom/model/sequential_recommender/hyperhawkes.py) instead selects the latest eligible event; it also scores at supplied TIME. We must not supply a future purchase time or claim that its code reproduces a sum over all past episodes.

**Adaptation and novelty delta.** Use observed numeric category_id as a declared intent proxy, not learned semantic intent. One episode is the first observed purchase timestamp per `(user,session,category)`; missing/conflicting category/session is unsupported. Exclude the latest observed session from recurrence references. For category k, compute

`A_k(t)=Σ_old_episodes ∫[0,24h] ((1−π_k)Exp_k(t+h−s)+π_kNormalPositive_k(t+h−s)) dh`.

NormalPositive is explicitly normalized on nonnegative lags. Freeze at most16 supported category parameter sets plus a global fallback. Score each known item as `A_category×(buyers7d+1)/category_prior_mass`, selecting top20; freeze each category’s top20 postings before query. Candidate category is the latest global metadata bucket<t, with NULL/conflict unsupported. This is a finite-horizon **excitation score**, not a survival probability: it holds history fixed and does not simulate future events. It shares support, episode aggregation, item prior and all parameters except kernel family with an exponential-only control.

Unlike generic session decay, the delayed bump can increase score as a previously observed intent approaches its repeat interval; unlike NB-F02, the source transfers across SKUs of an observed category and sums prior episodes rather than using residual survival since the last repeat of the same pair. Bought SKUs remain eligible. This is observational intent recurrence, not established replenishment or annual seasonality.

**Counter and gates.** A single month may not identify any delayed bump; category mixing and logging repeats can mimic it, and added parameters may simply overfit. First analytically check equal-recency histories with different earlier episodes, positivity, truncated-kernel integration and unknown future-time rejection. Future source-only support probe must count complete observation spans and administrative right censoring; do not fit only completed gaps or impute missing next purchase times. Minimum proposed gate:100 observed category episodes from≥20 users and a covered risk interval extending beyond the proposed bump; otherwise defer. A later likelihood estimate must condition on the observed start and include the integral through cutoff; latest-only versus summed excitation is a separate future contrast, not another free look.

## Shared comparison, costs and decision

Select **one** mechanism after source gates, not three stacked experiments. Proposed native policies are P180+R20+S20 versus P180+R20+matched-control20 and the existing P200+R20 reference; union/dedup without refill, maximum220. Each source deduplicates before its quota. Freeze technical item-ID ties, memory/rule ties and source priority before evaluation. No positive insertion, unsupported-item refill or implicit catalog expansion.

Report actual size distributions, source overlaps, source/universe support and cold targets. Beside native policies, diagnose size effects by label-blind deterministic hash-thinning each union to the per-query minimum of the three actual sizes. This changes the diagnostic policy and does not replace native results. Primary retrieval result is full-Y candidate Recall with gained **and lost** targets; also macro/micro, repeat/new-SKU slices, stale/missing session coverage and zero-Y queries. A downstream comparison uses the same learner recipe, two prospectively budgeted fits and full-Y NDCG20/Recall20; new-C branch fits are not feature ablations on the frozen C.

Future feasibility proposal:100Q,2threads,RSS≤6GiB,30CPUmin including source scans, build, lookup, export, tiny oracle and failures. Stop with partial ledger on cap exhaustion. Later quality allowance, only after a new reservation:≤120CPUmin total, two ranker fits; RA03 additionally allows exactly two bounded kernel estimations, charged inside the same cap. Every failed/abandoned attempt counts. No throughput or coverage is measured here. Priority: RA01 first for direct purchase-target alignment, RA02 only after joint-support admission, RA03 lowest because the observable month poorly constrains recurrence.

Additional static leads were not promoted: [TALE Eq14/footnote2](https://arxiv.org/pdf/2412.07382) explicitly uses symmetric past/future popularity; its causal variant is a changed procedure, and dense item Gram/inverse remains a cost issue. [MiaSRec2024](https://arxiv.org/html/2405.00986v1) sparse intent selection is interesting but too close to existing multi-interest work without a sharper contrast. These rejections preserve discovery effort without inflating the new-mechanism count.
