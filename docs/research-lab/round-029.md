## Что должно стать новым результатом относительно005

Task1 требует воспроизводимый boosting с хорошими ручными history features, предложение автоматизации generation/calculation либо альтернативного метода и экспериментальную проверку с читаемыми результатами/ограничениями. Canonical backlog отдельно требует measured сравнение central016 с хорошо настроенным control;008 two-fit smoke его не заменяет. Длинный literature list или ещё один manual block не закрывают эту центральную работу.

005 уже превращает **вручную заданный registry** в SQL calculation, проверяет ограниченный vocabulary и выдаёт features/masks/coverage. Это реальная calculation automation, но validator сам не выбирает интересные entity/event/window programs. Поэтому prospective016 должен показать новый проверяемый переход `reviewed schema annotations→typed AST candidates→legality/dedup/closure→common legal bundles→fixed I/R selection→same compiler/source calculation`.

Если implementation лишь сохраняет восемь вручную выписанных JSON bundles и выбирает их IDs, честное название — bounded automatic selection из human-designed pool. Этого нельзя незаметно переименовать в автоматическое порождение features из schema. Для generation claim нужны parameterized typed templates/operator catalog, deterministic instantiation по annotations, rejected-signature reasons и воспроизводимый output. Такой узкий generator не обязан самостоятельно изобретать semantics, windows или новые operators; ручной whitelist и восемь разрешённых bundle patterns остаются частью метода.

## Связь с четырьмя первичными методами

[DFS2015](https://groups.csail.mit.edu/EVO-DesignOpt/groupWebSite/uploads/Site/DSAA_DSM_2015.pdf) разделяет relational feature synthesis и полный Data Science Machine/model tuning. Это основание считать generation отдельным artifact, а не отождествлять её с model success. [ExploreKit2016](https://people.eecs.berkeley.edu/~dawnsong/papers/icdm-2016.pdf) отделяет generation, learned ranking и classifier evaluation. [OpenFE2023](https://proceedings.mlr.press/v202/zhang23ay/zhang23ay.pdf) оценивает дополнительные features через обучаемый FeatureBoost/pruning. [AutoCross2019](https://arxiv.org/html/1904.12857v2) выполняет beam search/field-wise LR для categorical crosses. Ни learned selectors, ни categorical hashing, ни full search этих работ у нас не реализованы. Их benchmarks не дают evidence качества, speed или generalization на fixed Q/C/fullY TLAB.

Human prior здесь включает semantic tags/grains/units, vocabulary005, окна24/168h, pool restrictions, I1=L02/I2=L06, source/null policies и известные007/008/009 development результаты. R выбирается из **того же** frozen pool. Label-free primitive evaluation не делает проектирование pool blind; retrospective019→016 lineage и consumed looks раскрываются. Новый генератор не может задним числом объявить собственную availability у старых training anchors.

1. Один methods record связывает task/source interpretation, человеческие annotations/templates, actual generator/calculator границы и поддерживаемые operators. Unsupported price/log/nested/categorical/learned-state operators явно отклонены.
2. Frozen register содержит final019 B/encoding/population/settings/checkpoint/pins, pool signatures/closure relative to fullB, I/R inputs/seeds/draw law, ties/eligibility, no-replacement и timing/decision rules. Ручная правка generated JSON после metrics нарушает этот record.
3. Независимый semantic evidence отделяет ≤32-row synthetic goldens/mutants от будущей actual selected-addition coverage; exact dtypes/NULL transport и every physical keyed row проверяются в заявленном scope. Неисполненный plan не отмечается PASS.
4. Attempt ledger включает preparation/hash/oracle/cache/failed/cleanup CPU/RSS/wall, physical columns, fits/looks, collision reuse и unattempted slots.019 cost и016 cost различимы; unknown historical CPU не0.
5. Results table показывает B и все actual slots, full-Y primary/guards и уже объявленные support/coverage/zero/cold/day limitations; winner selection и reused development history не скрываются.
6. Читаемый conclusion связывает каждый claim с evidence/status и оставшимися gates. GitHub/PDF — допустимые форматы условия, но новый формат или publication сейчас не выполняется.

## Если все legal arms не улучшаютB

При четырёх **действительно complete/source-valid** pipelines отрицательный результат — на данной population, frozen B/settings и ограниченном pool добавочная predictive польза не обнаружена. Если point effects≤0, это observed non-improvement; если положительны, но не проходят fixed practical/uncertainty guards, вывод weaker/inconclusive. PointΔ≥.002 и lower95%>0 не доказывают trueΔ≥.002; selection CI остаётся screening. Нельзя заменитьprimary наB+supports, убрать проигравший arm, сменить C/population или добавить seed.

Корректный generator/calculator, reproducible protocol и bounded negative experiment остаются полезными engineering/research evidence. Но превосходство над tuned B, universal automation advantage и measured quality gain **не установлены**; заявленная цель добавочной полезности остаётся незакрытой. Semantic failure вообще invalid experiment, resource exhaustion — budget-limited, collision — consumed draw, не четыре независимых отрицательных trials. Нельзя обещать, что любой такой итог гарантирует compliance или оценку комиссии, либо оправдывать отсутствие эксперимента формальным чтением слова «либо». Следующее решение принимается по имеющемуся evidence, без автоматических новых datasets, fits, looks или budget expansion.
