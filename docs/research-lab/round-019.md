## Фактический estimand и парность

`paired_user_bootstrap` проверяет одинаковые query IDs, пользователей, maturity и полные targets у двух моделей. Из популяции **всех mature пользователей**, включая пользователей только с пустыми Y, с возвращением выбираются U кластеров. Каждому пользователю соответствует одна кратность kᵤ, общая для обоих scorers; все его daily queries перемещаются вместе. Censored query исключаются, mature query с пустым C и положительным full Y остаётся нулевым ranking результатом. Full Y вне C не исчезает из denominator/IDCG. Tie policy находится у вызывающего кода;008 объявляет product ID ASC.

Для conditional macro-query обозначим nᵤ число положительных mature queries пользователя, sᵤ сумму их metric scores. В каждом draw оценивается `Σ kᵤsᵤ / Σ kᵤnᵤ`, затем разность left−right. Это **не** среднее пользовательских средних. Conditional user-macro вместо этого усредняет `sᵤ/nᵤ` с весом kᵤ среди nᵤ>0. Пользователь с двумя положительными днями имеет двойной query weight, но один user weight. В zero estimands знаменатель включает соответственно все mature queries или mature пользователей; пустому Y назначается0. Эти четыре величины нельзя взаимозаменять ради более удобного интервала.

В принятом008 опубликованы4000 mature Q,3995 mature users,73 positive Q и73 positive users,96 full targets; conditional query/user estimates совпали именно на этой поддержке. Совпадение не универсальное свойство bootstrap.817149 candidate rows не являются независимыми наблюдениями для такого estimand,96 targets не равны96 user clusters. Число positive users важно рядом с общим U.

## Что оценивает интервал

[Cameron–Miller, авторский обзор, §§II.F,IV–VI](https://faculty.econ.ucdavis.edu/faculty/cameron/research/Cameron_Miller_JHR_2014_July_09.pdf) описывает cluster resampling и зависимость внутри кластера при предпосылках о независимости между кластерами; отдельно разбирает few-cluster и multiway проблемы. Его regression результаты не являются готовой теоремой покрытия для sparse ranking ratio. Для006 разумная ограниченная интерпретация — вариация по похожим пользовательским кластерам **условно на наблюдённых датах, eligibility/cohort, source context и двух уже fitted pipelines**. Это требует правдоподобной exchangeability пользователей, которую код не доказывает.

Повторные daily queries одного пользователя не превращаются в независимые копии. Но user clustering не моделирует общий дневной promotion, сбой каталога, смену traffic mixture или взаимозависимость пользователей через популярность/общий item context. Процедура не пересчитывает признаки, retrieval, обучение и выбор pipeline внутри draws. Поэтому она не оценивает variability новых training samples, model seeds, будущих дней или другого датасета. Парность сохраняет covariance двух результатов на одной query, но не устраняет эти ограничения.

Две selection даты не дают надёжной эмпирической модели распределения будущих календарных shocks. Bootstrap по двум day clusters, либо сочетание user/day resampling, не создаёт недостающие дни; при одной prospective confirmation дате временную вариацию вообще нельзя наблюдать между датами. Дневные aggregates полезны как описание, не как гарантированный temporal CI. [Ji et al., авторская работа](https://arxiv.org/abs/2010.11060) показывает последствия нарушения global timeline в recommendation evaluation; соблюдение timeline необходимо для допустимости сравнения, но само по себе не доказывает переносимость на новые дни.

## Sparse draws и Monte Carlo точность

Когда conditional draw не содержит положительных query,006 возвращает `None`, не0 и не повторный draw. Percentile interval рассчитывается по определённым значениям с линейной интерполяцией; при отсутствии определённых draws интервала нет. Это честное сохранение failure evidence, однако исключение undefined draws означает распределение **условно на определённости**, а не автоматически корректный unconditional95% CI. Значительная доля undefined — ограничение доказательности; её нельзя спрятать, добрать успешными draws или исправить zero convention без смены estimand.

008 сообщает200 draws, undefined0, Δ PairLogit−Logloss NDCG20=−.03925032 и interval[−.08499996,−.00089123]. Это опубликованный результат, здесь не пересчитан. Fixed seed воспроизводит результат, но не измеряет Monte Carlo ошибку границ. Код дополнительно зависит от порядка user clusters в left input: одинаковый seed при иной перестановке не обещает те же draws. Нужен порядок/его provenance, а не только seed.

[Hesterberg, авторский текст, раздел о числе resamples](https://arxiv.org/html/1411.5279) различает sampling uncertainty и Monte Carlo variability percentile endpoints, обсуждая существенно больше repetitions для точных границ. Его рекомендации не являются разрешением увеличить наш budget.200 draws дают грубое screening приближение; верхняя граница близко к0 не оправдывает сильную формулировку о стабильном знаке без соответствующей precision оценки. Больше repetitions не добавляют positive users и не устраняют selection bias.

## История выбора и практический отчёт

[Cawley–Talbot, первичная статья](https://jmlr.org/papers/v11/cawley10a.html) показывает, что оптимизация шумного selection criterion способна переобучить выбор модели. Последующий ordinary CI для победителя не включает историю поиска.019 Grid/checkpoints и016 выбор intelligent/random bundles адаптивно используют development feedback; интервалы на той же selection остаются screening, даже при точном bootstrap и заранее ограниченном числе fits. Известные007/008 результаты и отклонённые попытки входят в эту историю. Два random seeds не доказывают превосходство стратегии автоматизации.

Предлагаемый текст финального отчёта: «Парный percentile user-cluster interval описывает фиксированный contrast на указанной популяции и датах; не учитывает temporal shocks, обучение и адаптивный выбор. Confirmation interpretation возможна только при заранее sealed decision до открытия её targets». Реальная2026 audit chronology и simulated2019 availability/positive decision compute gap остаются разными обязательствами;25-only schedule пока не утверждён.

Рядом нужны опубликованные даты, mature/censored/empty-C/positive Q, mature/positive users, повторность queries на пользователя и positive support по дням, full-Y/retrieval misses, четыре estimands, contrast direction, tie rule, seed/order, draws/undefined, input/model pins и полный ledger attempts/checkpoints/cost. Это требование прозрачности существующих evidence, не обязательство нового raw scan. Сохраняется amendment005: pointΔ≥.002 и lower>0 не доказывают trueΔ≥.002; crossing0 и practical threshold — разные выводы. HYP123/124 остаются reserved refinements metric reporting; новых quality mechanisms, бюджетов или обязательных дополнительных evaluations не предложено.
