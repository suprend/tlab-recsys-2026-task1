## Почему GridC защищаем, но не объявляем оптимальным

[Официальный CatBoost tuning guide](https://catboost.ai/docs/en/concepts/parameter-tuning) выделяет tree count, learning rate, depth и L2 как существенные настройки. Depth меняет сложность взаимодействий, L2 — regularization, число итераций вместе с LR — степень продвижения boosting. **Суждение:** два уровня depth и десятикратный контраст L2 дают ограниченную capacity/regularization проверку, а checkpoints — три заранее выбранные длины ensemble. Это осмысленнее одного default-like50tree fit, без требования новой сетки.

Документация рекомендует анализировать under/overfitting и validation iterations, но не гарантирует, что4/6 и3/30 охватывают optimum данного sparse ranking protocol. Фиксированный LR.05 может взаимодействовать с300tree cap; иной optimum вне grid остаётся unknown. Это раскрываемая граница, не повод сейчас менять LR/trees. [Common parameter definitions](https://catboost.ai/docs/en/references/training-parameters/common) описывают iterations как максимум trees и LR как gradient step; поддерживаемый диапазон параметра не является свидетельством его качества здесь.

019не использует eval_set/OD: external fullY checkpoint selection заменяет ограниченную функцию выбора, но не автоматически все практики tuning guide. Native metric внутри C не должно незаметно стать другим selector. [CatBoost2018](https://proceedings.neurips.cc/paper/2018/file/14491b756b3a51daac41c24863285549-Paper.pdf) обосновывает алгоритмические механизмы, а его benchmark superiority не переносится на наши Q/C/Y или fixed Plain settings. «CatBoost» и «ordered» не взаимозаменяемые доказательства temporal safety.

## Какие исходы честно допускает контроль

Если completed eligible configs проиграли incumbent по policy, valid conclusion: ограниченный search не нашёл лучшего eligible pipeline, incumbent сохранён. Это результат tuning attempt, не доказательство глобального optimum или универсального превосходства50trees. Если все new fits resource-failed/ineligible, valid conclusion слабее: новые configurations не дали usable completed evidence в cap. Нельзя написать «четыре configurations проверены качественно», когда scores не получены. Global integrity/unknown-cost STOP не превращается в успешный baseline selection даже при наличии старого incumbent.

Для слова «strong» отчёт должен показать actual feasible attempts/consumed slots, selected spec, support и сравнение с уже предусмотренными heuristic controls на идентичном protocol. В прочитанных008/009notes такого доказательства относительной силы против всех heuristics нет; оно не выводится из library name или правильности artifacts. Здесь не запрашиваются новые heuristic looks. Если существующее evidence недостаточно, формулировка остаётся «bounded tuned manual control under disclosed grid», а не обещание task compliance.
