## MA01: real mechanism, already the same TabM hypothesis

The [TabM paper](https://arxiv.org/html/2410.24210v2) and [official repository](https://github.com/yandex-research/tabm) support separate head losses and inference averaging; MA correctly specifies mean BCE per head and mean sigmoid probabilities. It avoids the `loss(mean prediction)` error. Its mechanism is identical to M001-C3 and MB02: independently supervised predictions with shared MLP parameters. Four versus eight members, mini versus full adapters and an extra initialization control are experimental refinements, not separate novelty IDs.

The proposed tied-adapter **initialization** control does not remove diversity: independent output heads and stochastic training can still produce distinct gradients; adapters initially equal can diverge during optimization. Treat it as an initialization ablation. A no-diversity control would need tied parameters/heads and a common stochastic path, which is a different intervention. Wider parameter-matched MLP controls capacity, but parameter equality is not compute equality. Declare whether the contrast fixes examples/updates or actual CPU; report the other quantity.

Keep a minimal shared TabM-versus-same-width MLP screen unless the initialization question has enough value to consume an attempt. The four-fit MA package is finite, with 80 CPU-minutes allocated to fits and 40 to everything else, but neither total wall limit nor preprocessing shape is fixed. The supplied 5.317m×41 float32 values alone are approximately .812 GiB; masks, imputation, transformed copies and member activations add memory. `k=4` never licenses four copies of the input matrix.

Temporal contract is sound for a standalone learner trained after historical labels mature and served later. Reuse the sealed strong B only if feature schema, allowed training domain and evaluation availability match. Expanding train or changing population makes a fresh B fit paid; the external reference cannot silently remain weaker. Cheapest falsifier: source-free k=1, head-loss and averaging fixtures plus an explicit initialization witness. No quality look or real training is needed to settle these contracts.

## MA02: learned soft label aggregation is distinct from foundation-model ICL

[ModernNCA](https://arxiv.org/html/2407.03257v2) predicts by a learned metric and soft aggregation of training labels. The inspected [author model source](https://raw.githubusercontent.com/LAMDA-Tabular/TALENT/main/TALENT/model/models/modernNCA.py) samples bank rows during training, appends current batch examples, masks only the self diagonal, then applies `cdist → softmax → label matrix product`. It does not implement MA's same-user exclusion, memory query weights or declared bounded bank. Notably, paper Eq4 uses squared Euclidean distance whereas this executable path uses ordinary Euclidean distance; freeze the chosen code/formula, temperature and feature transform rather than treating them as interchangeable.

This is sufficiently different from M001-C4 localized TabICL to preserve a candidate: ModernNCA fits its metric to the permitted labels and uses explicit neighbor-label aggregation; localized foundation ICL uses a pretrained predictor with retrieved contexts, target-aware representations and different support/weight semantics. Their common parent is labeled-row retrieval. Neither is item-neighbor recommendation or insertion of retrieved positives into C.

Two unresolved issues block a pilot. First, “query weights must affect memory aggregation” is not implied by the query-macro estimand. Outer query weights define empirical training risk; adding weights inside neighbor voting changes the predictor's local prior. If intended, specify `p(y=1|x)=Σj a_j exp(-d_j/T)y_j / Σj a_j exp(-d_j/T)`, with a declared `a_j`, exclusion and sampling law. Use the same rule in all NCA controls and call it a weighted adaptation. Do not normalize numerator and denominator on different supports. Shuffling memory labels is useful, but requires a fixed mapping that preserves the same global label mass; query/label association must not leak through retrieval exclusions.

Second, bank size is missing. The supplied full-Y count bounds covered positive rows by 619 among 5.317m. For a uniform label-blind 4,096-row bank, expected positives are at most .47685; Markov gives probability of **no** positive at least .52315. This is a design bound, not a measurement of actual class counts or all deterministic banks. A 32,768-row bank has at most 3.81482 expected positives; nearest-neighbor positive support can still be absent. Label-stratified admission would change the sample law and posterior; it must be an explicit adaptation with correction or an honest uncalibrated ranking interpretation, not a silent rescue. Define absent-class/fallback behavior before training; all-zero memory gives no useful positive aggregation gradient.

Memory alone is not the cost gate: at M=32,768, the supplied 817,149 selection rows require 26,776,338,432 query-bank distances. Full train-bank inference would require 4,344,781,233,000. A 1,024×32,768 float32 distance block is 128 MiB, excluding gradient buffers/embeddings. No claim is made that either fits 120 CPU-minutes. Four arms each pay their bank encoding, training-neighborhood work, exclusions and inference. Cached final embeddings cannot be substituted during training without defining gradient/freshness semantics.

Require a finite bank cap/law, dimension, batch size, blockwise denominator plan, positive-mass/fallback report, CPU/wall ceiling and stop rule before any fit. Mature bank labels, metric, scaler and index are jointly label-bearing state available before prediction; filtering future labels only at the final aggregation is too late. Current batch diagonal masking is insufficient for the promised same-user/query exclusions. Cheapest falsifier: literal bank with no positive, exact self/same-user masks, duplicate rows and weighted denominators; then a separately authorized train-only cost/support gate. Preserve source-free review now; do not promote “nearly all-zero” into an actual finding.

## MA03: acknowledging risk does not yet repair the update

The [SL@K paper](https://arxiv.org/html/2508.05673v1) weights positive softmax terms by sigmoid score-versus-threshold. The inspected [author executable loss](https://raw.githubusercontent.com/Tiny-Snow/IR-Benchmark/main/src/itemrec/optimizer/optim_SLatK.py) uses cosine scores, a cached beta updated under `no_grad`, and a **differentiable positive weight**. Its loss uses sampled-negative logsumexp; the docstring's denominator activation differs from that executable path. Full current-C denominator, exact per-query threshold and arbitrary MLP scores are MA adaptations. The paper's nonzero-hit assumptions do not cover a positive currently ranked 21st at K=20.

MA says to freeze “gradient-through-threshold policy from source” and asks whether gradients demote hard positives. It does not choose a repair, bounded scorer, complete weight detach or precise threshold schedule. Therefore the known failure is still an admission blocker, not already addressed by that wording.

Independent stdlib verification of `L=σ(p−β) log(exp(p)+20)−σ(p−β)p`, with 20 negative scores 0, β20=0 and both temperatures 1:

| Positive p | Loss | Full derivative dL/dp | Derivative with entire weight detached |
|---|---:|---:|---:|
| −.5 | 1.3310604203 | **+.4621028063** | −.3664281727 |
| −1 | 1.0795198718 | **+.5251083930** | −.2640838700 |
| −10 | .0005899787 | +.0005445541 | −.0000453978 |

Central finite difference at p=−1 was +.52510839299. Gradient descent demotes the real positive. The new p=−.5 witness lies inside cosine-style bounds: **score bounding alone does not fix the direction**. It prevents unbounded escape but can still drive the positive toward the lower bound. Detaching beta alone is ineffective here because beta is locally constant. Multiplying by the positive full-Y coverage ratio preserves the derivative sign. At p=−100 the unbounded loss is approximately 3.8315e−42 despite the positive remaining last.

Choose one update before a pilot: for example detached **whole** positive weight, explicitly described as reweighted CE optimization rather than the gradient of the original complete scalar expression. That update still suppresses hard positives and needs its own usefulness test. Do not add bound/detach/temperature variants as free trials. Also define positive normalization: dividing by the sum of weights cancels the weighting entirely for singleton-positive queries, so it may remove the claimed intervention. Exact threshold is undefined for C<K unless an explicit short-list policy exists; ties need deterministic semantics.

After repair, literal ranks19/20/21, ties, partial coverage, C0/1/20, zero/all-positive groups, score bounds and translation behavior must pass. Use identical scorer/normalization with matched full-C softmax; a constant full-Y query-weight contrast is an additional training-risk change and should not be conflated with top20 loss novelty. This is the same SL@K family as M001-C2; preserve the existing candidate with an explicit refinement, not another ID. Its provisional second-place priority is unsupported until this zero-fit gate passes.

## MA04: closure is a separate KD question, but fullC versus top20 changes more than closure

The [ICLR2026 paper](https://proceedings.iclr.cc/paper_files/paper/2026/hash/a92de7efca19f26309a38b3e3fa3dd86-Abstract-Conference.html) supports the closure concern: teacher top items may omit items currently top-ranked by the student. The inspected [author RCE-KD source](https://raw.githubusercontent.com/BDML-lab/RCE-KD/master/modeling/KD/playground.py) constructs teacher and student top lists, samples from student lists and combines losses; it calls full rating matrices and hard-coded CUDA operations. Those operations are not needed or admissible automatically for a CPU fixed-C adaptation.

Novelty differs from M001-C1's teacher-prefix policy and MB03's loss-head routing: keep closure as a separate contrast under the same KD family. FullC contains all student top20 **within C** by construction; this says nothing about student/catalog items outside C. FullC versus teacherTop20 also changes supervision support, renormalization, term count and CPU. A gain supports the whole closed-list package, not closure alone.

A sharper source-free witness: teacherTop20 omits candidate j, while student ranks j first. Softmax normalized only over teacherTop20 has zero derivative on j; fullC KL can push j down whenever student mass exceeds teacher mass there. No source labels or fitted model are required. For a more focused future comparison, consider teacherTop20 versus the deduplicated union of teacherTop20 and studentTop20, using the same teacher soft probabilities renormalized over each declared support, with student-set selection detached. The union restores within-C top20 inclusion with at most40 items. A fixed-size teacherTop40 comparator would additionally test support-count effects, but consumes an arm; do not append it to the existing four-fit package.

Before fits define `Tq=softmax(zteacher/T)`, `Sq=softmax(sstudent/T)`, support, query averaging, KD coefficient and optional T² scaling; same-logit BCE+KL is not binary BCE on sigmoid teacher scores. Teacher logits need not be calibrated probabilities. Zero-Y queries can still receive KD, but dense targets do not create independent observed purchases. The shuffled-teacher control probes soft-signal information, not closure specifically; a closure-focused package should prospectively replace a control rather than accumulate more attempts.

MA correctly permits a final standalone student to learn from a teacher trained after historical row anchors, provided all teacher training labels are permitted/mature and both models exist before later predictions. This differs from the time-aligned freshness treatment in M001-C1; ordinary OOF is not needed merely to compress a final teacher, while a downstream early-anchor feature would require genuine earlier availability. Reusing sealed B is valid only on the unchanged allowed training domain; otherwise teacher/B fits consume attempts. Pay teacher logits and subset construction; storing one float32 per supplied train candidate is about20.3 MiB before keys/masks, not a full cost forecast. Keep the real inference-bottleneck gate: without one, copying B's quality at extra research cost has little practical value.
