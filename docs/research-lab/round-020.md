## Что переносится из первичных работ

[FLAML, Wang et al., §§3–4](https://arxiv.org/html/1911.04706v3) явно связывает trial cost с learner, hyperparameters, sample size и resampling. Estimated cost for improvement направляет адаптивный порядок поиска; авторы признают неточность estimation. Это основание учитывать стоимость **всей оценки**, не гарантия выполнения очередного fit. Его adaptive sample-size mechanism нельзя перенести как разрешение менять frozen population016/019: такой перенос изменил бы эксперимент, а не просто ускорил его. Benchmark improvements FLAML не являются измерениями нашего compiler или CatBoost pipeline.

[ExploreKit, авторский текст, Algorithm1 и evaluation](https://people.eecs.berkeley.edu/~dawnsong/papers/icdm-2016.pdf) ранжирует candidates learned моделью и затем оценивает их через обучение classifier; опубликованный search использовал существенно иной масштаб итераций/времени. Это не бесплатное перечисление AST. В [OpenFE, Algorithms2–4](https://proceedings.mlr.press/v202/zhang23ay/zhang23ay.pdf) FeatureBoost избегает полного refit базового model, но **обучает** дополнительную модель поверх base predictions; pruning многократно применяет такие оценки. Поэтому «no full retraining» не означает0 fits/cost/looks в TLAB. Совместимость подобного proposer потребует отдельного распределения существующего cap, не автоматического исключения вспомогательных models из счёта. Новые библиотеки/компоненты не предлагаются.

## Текущие ограничения и измеряемая единица

Canonical016:2 intelligent+2 seeded random bundles, каждый — 3 физических scalar columns вместе с обязательными support/mask/coverage closure; общий предел12 columns/4 fits/2 CPUh. Invalid/duplicate attempts не заменяются.019 предлагает4 новые GridCfits с checkpoints50/150/300, максимум12 новых selection looks, ≤60 **actualCPUmin** включая gate/prep/failures/oracles/scoring. Это prospective budget, не автоматически принятое расширение008. Incumbent переиспользуется без refit; его scoring всё равно стоит времени. История007/008/009 сохраняется отдельно от новых caps.

[Python time](https://docs.python.org/3/library/time.html#time.process_time) определяет process CPU как сумму user+system текущего процесса, без sleep; разность monotonic clock измеряет elapsed wall. Thread cap2 не превращает wall×2 в observed CPU: ожидание IO, неполная загрузка и разные этапы нарушают равенство. [Python resource](https://docs.python.org/3/library/resource.html) учитывает все threads через RUSAGE_SELF, а RUSAGE_CHILDREN — только terminated и waited-for children. Parent/worker self accounting нельзя складывать поверх уже включённого child aggregate. Живой worker, kill/reap и accounting tail требуют явной границы; неизвестная стоимость не0.

Actual ExecutionAudit создаёт partial report до основных этапов, проверяет CPU/wall/RSS/spill, завершает connection и manifest/summary persistence до terminal checks; его final receipt tail передаётся parent accounting. Это полезная конкретная seam, **не** доказательство корректности ещё не реализованных019/016 runners. В текущем primitive process CPU относится к самому процессу: будущий executor с subprocess должен отдельно закрыть child scope. Потерянное измерение или невозможность сохранить обязательный receipt не могут дать complete acceptance.

## Минимальный переносимый ledger

Предлагается append-only register со связанными четырьмя уровнями: experiment policy, shared preparation, arm attempt, stage/checkpoint. Policy содержит exact plan/source/config/code/environment pins, AST/physical schema, train population и Q/C/Y identities, incumbent, fixed order/PRNG, caps, chronology и stop rules. Attempt ID резервируется до работы project-wide, не переоткрывается другим output root. Stage хранит start/end clock, measurement scope, observed CPU/wall/RSS/spill, completion status, dependency/cache identities, consumed columns/fits/looks и evidence pointers. Итог ссылается на все failures и unattempted slots; суммирование не теряет предыдущий failed root.

Четыре класса cost должны оставаться различимы: **declared cap**, **estimate**, **observed measurement**, **unknown/censored remainder**. Timeout сохраняет затраты до остановки и причину цензурирования, не fictional completed runtime. Старый008 production CPU не измерялся: известные wall/RSS и два fit attempts сохраняются как история, но не позволяют вывести «остаток6CPUh». Нельзя вычесть неизвестное как0 или заменить его wall×threads. Measurement failure означает закрытую execution gate, а не бюджетный успех.

Полный bill включает enumeration/materialization, dtype conversion, labels/weights, source hashing, provenance проверки, независимые source oracles, Pool construction, fit, checkpoint predict/full-Y metrics, cache IO, exports, cleanup и failed attempts. Train-only selector тоже расходует fits и CPU; materialize сотни candidates ради выбора12 нарушает column scope даже без финального обучения. Ledger различает physically produced closure и символические неисполненные definitions.

## Shared cache и справедливость

Общий source preparation может оплачиваться один раз, если реально переиспользован. Предлагаются две прозрачные проекции: end-to-end experiment total и per-arm marginal costs плюс shared bucket; заранее объявленная attribution weights суммируются в1, без двойного списания shared cost. Дополнительный diagnostic standalone cost нельзя выдать за выполненный rerun. Одинаковые cache permissions, warmup/hash policy и общий frozen B нужны intelligent/random arms; common context запрещено дарить только intelligent arm. Порядок arms раскрывается: поздний arm может получить тёплый OS cache.

Cache hit не бесплатен: lookup, hashing/validation/read и независимая проверка включаются. Key связывает source prefix/availability, protocol/endpoints, AST/adapter/registry, exact QC population, encoding/dtypes и relevant code/environment. Timestamp или filename недостаточны. Semantic expected values нельзя брать из producer cache как independent oracle. Будущие labels или post-selection выбор cache contents недопустимы; integrity mismatch означает STOP, не «пересчитать и забыть». Более дешёвый arm не получает дополнительный bundle из освободившегося остатка.

## Stop policy и граница прогнозирования

Unavailable dependency/approval до fit — blocked/unattempted, с фактическим prep cost; resource failure после старта — consumed attempt с partial cost; semantic/schema/lineage/API failure — integrity STOP.019 допускает единственную заранее заданную26000→6000 развилку только по resource/cardinality gate, при собственных checks и остатке бюджета. После PASS все новые arms используют26000; неудачный Newton fit не разрешает population switch, retry, refill или fallback по увиденным scores. Exhausted aggregate cap не финансирует rescue.

Matrix/Pool PASS проверяет ingestion, а не будущие quantization, Newton/backtracking allocations или300-tree runtime. Cost forecast может ошибаться; cooperative checks могут заметить peak позже. Cleanup/report failure не превращает run в accepted. Полный grid и partial grid различаются; отсутствующие attempts не получают проигравший score, а screening winner не доказывает лучшую cost-quality стратегию. Новые pay-cloud/LLM calls, performance claims, framework и обязательные дополнительные evaluations здесь не предложены.
