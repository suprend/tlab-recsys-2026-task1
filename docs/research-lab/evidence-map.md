## Сила текущих доказательств

[Symbolic/tiny016 acceptance](../experiments/feature-programs.md) подтверждает ограниченную генерацию, closure и выбранные numerical witnesses:21 independent cases,180 scalar comparisons, включая60 literals. Остальные четыре bundles проверены символически. Это не реальный throughput или ranking gain. «24→12» означает allocation целых bundles по fixed policy, а не выбор лучших12 признаков после оценки всех24.

Человеческие annotations, templates, окна и static prior остаются явными. Генерация отличается от ручного manualJSON005, но не является полной реализацией DFS, ExploreKit или OpenFE. Typed validation доказывает допустимость программы в declared contract; source oracle проверяет значения на закреплённых данных; ни один из этих этапов не заменяет measured comparison.

[Отрицательный009 result](../backlog-reviews/tlab009-model-output-verification.md) — завершённый тест: whole metadata block снизил NDCG с.41444755 до.40041404 и Recall до.54500978. Fixed point predicate сохранил base41. Один whole-block fit не атрибутирует эффект отдельным category/price subfamilies; CI через0 не доказывает эквивалентность. Addon009 проверен exhaustively отдельно, а исходный B numeric source proof остаётся sampled. Every-row equality старого B в новом export доказывает preservation, а не новое exhaustive source recomputation B.

## Какому методу можно приписать будущий gain

Published003 допускает winner из I1/I2/R1/R2, включая random; bestI−bestR остаётся secondary screening. No-changeB, tolerance и tie proposal027 должны войти в prospective quality contract до scores. Если победит R, gain относится к bounded typed automation со смешанным allocation, а не к превосходству rule-guided выбора. Если победит I, двух opportunities стратегии всё равно недостаточно для универсального вывода. Если выбран B, лучший loser нельзя подобрать заново по holdout.

019 и016 должны сохранить одинаковые final B, training population, weights, trained iterations и scoring prefix. Quality failure, неопределённый effect, resource partial и integrity STOP имеют разный смысл. Неизмеренный расход не считается нулём; failed output не становится cache hit после свежего reseal. Эти границы не вводят дополнительных fits или metric looks.

## Что даёт литература

[OpenFE](https://proceedings.mlr.press/v202/zhang23ay/zhang23ay.pdf), [FeatLLM](https://arxiv.org/html/2404.09491v2), CAAFE и LLM-FE подтверждают empirical feasibility в своих tabular setups. [047](round-047.md) уточняет transfer limits: Microsoft у OpenFE оценивается как Regression/RMSE, а сам метод признаёт отсутствие past-only time constraint. ExploreKit error reduction основан на AUC. Leaderboard ranks, API latency и минуты мощной workstation не предсказывают наш full-Y NDCG или двухпоточный CPU ledger.

[Source audit043–046](rounds043-046-source-audit.md) сохраняет поправки: negative point estimate не исключает true positive effect; recency merge использует MAX timestamp/MIN non-NULL recency; CAAFE prompt показывает train labels; FeatLLM имеет дополнительный LLM parsing stage. Это важно для information/cost accounting, но никаких calls сейчас не разрешает.

Минимальная report chain: contract/programs/allocation → independent source/export evidence → frozen strong B → matched attempts и полный ledger → primary contrast, uncertainty/support → ограничения. Passing tests не являются source approval; source correctness не является quality gain; gain одной cohort не доказывает скорость, causal impact или cross-dataset generalization. До остающихся019/016 и reproduction gates task-complete claim не выдаётся.
