## Первичные факты и пределы гарантий

Featuretools описывает index как уникальный идентификатор строк, relationship — parent/child связь по ключам. OneBM отдельно классифицирует one-to-one/multiple joining paths и различает scalar/multiset transformations. Следовательно, collection после join имеет тип и multiplicity; произвольный COUNT поверх него не обязан означать число исходных событий. Это вывод для нашего compiler, не утверждение, что библиотеки автоматически доказывают бизнес-grain. [Featuretools EntitySets](https://docs.featuretools.com/en/stable/getting_started/using_entitysets.html), [OneBM, III-A](https://arxiv.org/html/1706.00327v1).

RelBench `Table` хранит optional pkey/time и FK→table declarations. В просмотренном constructor эти metadata присваиваются; наличие `pkey_col` само по себе не является доказательством enforced SQL constraint. Более того, `upto` использует inclusive timestamp, а таблицу без time_col возвращает целиком: это нельзя автоматически переносить на наш strict-past metadata join. Это наблюдение конкретного опубликованного main-кода, не аудит всех RelBench preprocessing paths. [Авторский Table](https://github.com/snap-stanford/relbench/blob/main/relbench/base/table.py), [paper, §2](https://cs.stanford.edu/people/jure/pubs/relbench-neurips24.pdf).

SQL INNER JOIN возвращает каждый matching pair. Поэтому две дочерние ветви длиныm/n даютm×n rows; это корректная SQL semantics, но часто неверная единица feature. DuckDB SEMI JOIN не увеличивает число left rows, ASOF даёт максимум один right match. Последнее ограничивает cardinality, однако не доказывает правильный выбор timestamp bucket или conflict policy. [PostgreSQL table expressions](https://www.postgresql.org/docs/current/queries-table-expressions.html), [DuckDB JOIN](https://duckdb.org/docs/current/sql/query_syntax/from).

## Минимальные proof obligations — предложение

Каждый leaf/edge хранит source/version, keys, output grain, multiplicity и temporal predicate. Для leaf событий: raw-row **bag**, exact duplicates сохраняются, event_type/window/availability явно заданы. В T-Lab нет достоверного eventID: DISTINCT полного payload не исправляет fanout, а удаляет допустимые повторы. `rowid`/ROW_NUMBER не создают достоверного порядка peers. Все queries одной секунды читают глобальное прошлое до обновления shared states.

Для обычного enrichment разрешить many-to-one join только к relation, уникальной по **реальным join keys** после temporal resolution. PK(product,version) не доказывает уникальности product на anchor; нужны validity/availability и resolution полного latest bucket. Либо full sealed-input check/реально enforced constraint удостоверяет ограничение на данный snapshot, либо это unverified annotation. Уникальность в100Qsample, низкий estimated fanout и отсутствие найденных orphan — только observations, не universal proof. Проверка будущего input выполняется заново; hash закрепляет snapshot, не истину бизнес-семантики. SQL PK запрещает NULL, UNIQUE отличается этим; FK membership не заменяет temporal overlap checks. [DuckDB constraints](https://duckdb.org/docs/current/sql/constraints).

Две one-to-many ветви сначала агрегируются независимо до одного declared key; их scalar results затем соединяются. SEMI JOIN подходит для membership-фильтра без размножения bag, но фильтрация всё равно может изменить population: category denominator обязан включать продукты вне C. Явные ON keys предпочтительнее зависимости от случайно совпавших названий столбцов.

Оператор COUNT сохраняет raw multiplicity; DISTINCT хранит explicit projected entity key/null policy, а не произвольный joined row. RATIO требует одинакового event/window/availability и numerator⊆denominator **в одной measure space**. Raw-event share, distinct-buyer share и taxonomy-membership share — разные units. Denominator0→NULL+mask; unknown conditional key→NULL, known empty count→0. SQL count(*) считает строки, count(column) — только non-NULL, DISTINCT считает уникальные значения; это отдельные операции. [DuckDB aggregates](https://duckdb.org/docs/current/sql/functions/aggregates).

## Пять минимальных counterexamples

Все числа ниже — hand-computed synthetic expectations, не измерения REES46.

1. **Bag против sibling fanout.** Уu две полностью одинаковые view-строки товараp и две cart-строки. JOIN view↔cart поu даёт4rows; правильные independent counts равны2/2, distinct viewed products=1. SELECT DISTINCT source payload уменьшает viewcount до1 и тоже неверен. Корректный compiler сохраняет повторения, агрегирует ветви доu и соединяет scalars.

2. **Metadata history против «одного match».** Три view товараp: categoryA в секунду1; в секунду2 global peers содержат categoryB и NULL. Query3 получает ambiguous/missing current category, не A и не выбранный B. Historical counters сохраняют A1/B1 и отдельную NULL-row; user viewcount=3. ASOF к сырым peers может выбрать один row и потерять ambiguity. Сначала строится unique resolved `(query_anchor,product)` relation; feature-condition при unknown category остаётсяNULL. Новая metadata в query-time или будущем не backfill прошлого. Поздно известное поле с event_time1/available_at4 не доступно query3.

3. **ID→code не обратим.** Два view: ID10 иID20, оба с доступным code `a.b`. Exact-ID10 share=1/2, code-share=2/2: это разные grains, не alias одной feature. JOIN черезcode обратно к обоим ID размножает каждое событие. Повтор dictionary pair также не может размножать raw bag. Unnamed ID остаётся отдельным ID; code, впервые найденный после query, не восстанавливает старый каталог. Recovery из уже доступного словаря требует явной policy: event-time annotation и reclassified snapshot atquery нельзя смешивать.

4. **Ancestors — намеренное membership.** Два view одного пользователя: terminal `a.b.c` и terminal `a.b`. Тогда M=2, C(a)=2,C(a.b)=2,C(a.b.c)=1; сумма5 не равнаM. На родителеa.b disjoint partition — childc1 плюс STOP1. Distinct users этих двух частей равны1+1, а union parent=1: складывать uniques нельзя. Membership каждого события в каждом canonical full-prefix node ровноодно; повтор bridge edge не добавляет массу. STOP — annotation окончания пути, не выдуманное purchase/action. DAG с несколькими путями требует отдельного approved membership contract, текущий forest его не доказывает.

5. **LEFT JOIN создаёт пустую строку.** Query известногоu без history сохраняется; LEFT JOIN даёт одну NULL-extended row, поэтому count(*)=1, хотя raw count=0. Count nullable product также неверен для source-row count, если событие без product допустимо. Надёжный путь — агрегировать source bag до join и coalesce только declared known-empty count. Unknown category и denominator0 сохраняютNULL+flags; generic fillna0 запрещён.

## Один prospective adapter test

Предлагается объединить пять fixtures в ≤24events/12metadata-or-membership rows/6queries/12candidate pairs; фиксированные COUNT/DISTINCT/RATIO definitions и independent expected tables. Это capability/correctness extension, не заявление о поддержке taxonomy005/018. Проверить exact keys/types/integers/nulls/masks и frozen float tolerance; diagnostic join cardinality/multiplicity включить в evidence.

Metamorphic checks: перестановка peers/физических rows и future suffix сохраняют past values; duplicate event увеличивает raw counts, но не distinct entities; duplicate right-side membership либо отвергается, либо canonicalizes согласно explicit set policy, сохраняя event multiplicity. Candidate reorder не меняет keyed outputs; удаление off-C category events обязано изменить полный denominator, демонстрируя чувствительность oracle. Numeric-ID→string bijection сохраняет equality-based результаты. Удаление последней активной копии меняет distinct, предыдущей — только count.

Prospective cap:≤5CPUминут/≤5wallминут,2threads,RSS≤512MiB,0fits, включая preparation/faults/cleanup; часть будущего согласованного adapter/oracle ledger, не автоматически новый бюджет. Semantic mismatch/непроверенная cardinality→failed/unsupported, без sample-based «proof» и free retry. Реализация и independent review нужны отдельно. Main016 по-прежнему generation/selection typedAST+correct calculation против frozen tuned B; новый framework, speedup и quality gain этим раундом не заявлены.
