## Проверка оснований и граница переноса

Это next-item задача с sampled-negative оценкой. Наши view-only множества за24h, Jaccard scalar и purchase-границы — собственная адаптация. В HTML есть шаблонная conference-строка CIKM2023 с placeholder DOI; безопасная библиографическая формулировка здесь — arXiv v1 от10.06.2025, без установленного conference acceptance. Указанный anonymous repo доступным reader не прочитан; code correctness не подтверждена. [Первичная статья](https://arxiv.org/html/2506.08531v1), [author-linked repository](https://anonymous.4open.science/r/TSRec-2306/).
2. **Timing-Aware Repurchase Prediction:** censored outcomes, AFT и discrete hazards подтверждены. Исходные данные — proprietary grocery,84 признака, в том числе order/channel/payment/availability; одна snapshot date и customer-heldout, наблюдение30days, оценочные горизонты7/14/28days. Это не daily temporal fixed-C/full-Y испытание. Непараметрический category/global residual prior из REES46 spells не является воспроизведением статьи. [Первичная статья, §§2,4](https://arxiv.org/html/2608.28393v1).
3. **HiFIRec/SCRM:** graph, multi-behavior weighting, non-sampling и multi-task в HiFIRec подтверждены; точный directed category contingency из F001 статья не предлагает. SCRM явно строит undirected graphs из хронологических click/purchase правил и затем denoises их. Поэтому «directed association» — наше предложение; complement/substitute truth ему не приписывается. У HiFIRec §4.5 также есть числовое расхождение: падение двух Beibei метрик названо улучшением. На опубликованные gains этой статьи не опираемся. [HiFIRec](https://arxiv.org/html/2509.25755v1), [SCRM, §§3.2,4.1](https://arxiv.org/html/2312.14957v2).
4. **FAM:** time-conditioned scale/bias/Yeo–Johnson coefficients подтверждены. Бумага изучает learned modulation, а не source-only bundle selection или доказанную связь стабильности с utility. README показывает100trials/15seeds; Appendix B уточняет25trials для FT-Transformer/TabR. Ссылку на этот protocol нельзя превращать в обязательную цену нашего probe или эмпирическое подтверждение proposed selector. [NeurIPS2025 paper](https://proceedings.neurips.cc/paper_files/paper/2025/file/ddc20f403d0d296c87940393838d5971-Paper-Conference.pdf), [author README](https://github.com/LAMDA-Tabular/Tabular-Temporal-Modulation).

Авторский [каталог REES46](https://rees46.com/en/datasets) подтверждает происхождение Multi-category behavior data. Kaggle reader вернул пустой текст: девять полей и локальный October-only scope сверены по существующему `docs/data.md`, без открытия CSV/БД. Все четыре идеи используют доступные IDs/time/action/session/category. Inventory, order IDs, exposure и received_at отсутствуют; истинная replenishment/causal complementarity ими не идентифицируется. Строгая event-time симуляция не доказывает измеренную delivery latency.

## NB-F01 — accept-needs-pilot с ограниченной новизной и проверкой редкости

**Новизна.** HYP045 задаёт candidate-category-bound nested popularity reference; HYP051/052 — learned/pooling/sequence семейство; HYP063 уже исследует candidate-conditioned против mean pooling. Общая «зависимость от кандидата» поэтому не нова. Дельта F01 конкретна: candidate задаёт прошлое purchase-время, вокруг которого извлекается отдельная reference history. В прочитанной прежней очереди такого оператора нет. `09-user-item/05-item-audience.md` хранит профиль *другого пользователя до его действия по item*; здесь сравниваются два собственных временных контекста одного query-user. Это тоже содержательное отличие.

Независимый literal replay исходного20-row двухмирового примера дал specific J `1→0`, generic J `0→0` при одинаковых all-prefix per-item view counts/last-view times. Он подтверждает различимость механизма, не его пользу и не равенство любого мыслимого temporal feature. Зафиксированы часы, а не неявные секунды.

**Ограничение применимости существенное.** Уже опубликованный manual005 summary имеет1,226,268 C-строк и1,225,318 отсутствующих pair-purchase-recencies: всего950 строк с наблюдаемой прошлой покупкой. Следовательно, в том smoke не более950/6000≈15.8% Q могли иметь хотя бы один такой кандидат; полные контексты и два различных значения встречаются ещё реже. Это старый source summary, без нового data scan; будущий warmup может отличаться. Gate≥20/100Q нельзя считать заведомо достижимым. Не менять threshold после просмотра результата.

**Обязательные уточнения.** Обе ветви получают общий eligibility: i ранее куплен; `[t−24h,t)` и оба reference-окна полностью покрыты source; union/nonempty/missing semantics едины. No prior purchase, empty union и incomplete source — разные причины missing. Generic reference также исключает i. В no-Y receipt отдельно нужны (a) Q с eligible pair, (b) Q с ≥2 различными numeric cores, (c) Q/pairs, где `s_ui != last_any_purchase_u`, и (d) изменение specific против generic. Если один прошлый SKU всегда является последней любой покупкой, оба arms совпадают и pilot не проверяет механизм. Source-only coverage не означает достаточную мощность будущей quality проверки.

Cheapest falsification: существующий literal case плюс last-any==specific, empty union, source-start boundary, purchase/view peers и suffix invariance. Затем лишь отдельно рассмотренный100Q feasibility/cost gate,≤30CPUmin/2threads/6GiB **включая оба reference joins и oracle**. Идентичные Q/C/Y, baseline recency, learner и physical delta; конкретно J/support/missing можно уложить в3 model columns, reason counts хранить в receipt. Если support не проходит, **defer**, без quality fit. Если проходит, отдельный two-arm proposal и новая reservation; accept-needs-pilot не является этим разрешением.

## NB-F02 — defer до полного statistical/clock контракта

**Новизна** относительно cooldown/TARS/recent-repeat и HYP025/060 есть: наблюдаемые spells, right-censoring и условная residual horizon probability. Это не новый target-rate encoder и не доказанная вероятность нового заказа. Формула `1−S(a+24h)/S(a)` корректна для объявленной waiting-time модели, если условная survival определена.

Literal arithmetic подтвердил пример автора: одинаковый F(1d)=1/6, но residual at2d равен1/2 и1/3. Дополнительный четырёх-spell пример `(event1d,event2d,censor3d,event4d)` даёт при сохранении censored member S(2d)=1/2 и residual1→2d=1/3; при удалении censor —1/3 и1/2. Таким образом, «не считали непокупателей» меняет сам risk set. Это арифметика заданных risk contributions, без оценки по проекту.

**Почему пока defer.** «31-day October history» — верхняя граница архива, а не доступное warmup ранних downstream rows. Для train, начинающегося8Oct, causal warmup не может включать последующие23дня. Для нового будущего study нужны конкретные даты; ни название warmup, ни feature lag не исправляют backdating fitted state.

До source probe следует зафиксировать:

- Incident spell начинается с observed purchase; неизвестный prior до source не объявляется первым lifetime purchase. Включаются все начатые spells, включая последние censored. Непрерывная активность/выход пользователя не наблюдаются и не дают отдельную известную censor date.
- Category — атрибут начального purchase bucket с NULL/conflict policy. Переклассификация по конечной покупке использовала бы будущее относительно начала spell; current-category assignment задаёт другой cohort. При unknown category global backoff должен быть заранее определён.
- Tie convention, особенно event и censor в один elapsed age; timestamp dedup выполняется лишь для этого оператора. Запись curve version включает fit cutoff, source coverage и available_at после фактического вычисления.
- Repeated spells одного user/item зависимы; administrative cutoff создаёт censor durations, связанные с календарём начала. Independent censoring/stationarity внутри cohort — непроверенная предпосылка. User-level uncertainty и чувствительность к календарным cohort нужны для последующих claims.
-≥50 completed category spells и≥20 risk members в используемом диапазоне — предложение threshold, не precision guarantee. Отдельно показать completed/censored/at-risk по age bins, query-age coverage, неподдержанный tail, global fallback. Наличие censor members после последнего event не доказывает истинный нулевой hazard.

Контроль unconditional group F(24h)+существующая age/recency в B разумен, если cohort, data cutoff, category base rate, common supported-age mask, missing/backoff и physical columns одинаковы. Full-Y primary сохраняет new/outside-C targets; repeat-only диагностика не заменяет denominator. Curve estimation и любое grouping/backoff selection — платный fitted state, хотя native classifier не запускается. Поэтому сейчас только контракт/literal evidence; future100Q probe и две downstream модели требуют отдельного решения. Непроходящий tail support — defer, не подбор новой distribution family на том же quality feedback.

## NB-F03 — refine, затем условный needs-pilot

**Новизна** ограниченная, но реальная: ordered action-role/category transitions отличаются от audience ItemCF001/061 и walk-length067. Ранний `04-interest-profile.md` уже обсуждает направленный покупательский контекст и один contextual cross; broad claim «впервые учитываем direction» неверен. Новым является конкретный historical transition table и normalized fixed-C scalar.

Literal two-session worlds с bags `{cart A,purchase B}` и `{cart C,purchase D}` различаются порядком первой пары. Selected cart→purchase A→B score меняется `log(4/3)=0.287682→0`, а pooled symmetric score остаётся `log(1.6)=0.470004`. Так изолируется различимость composite mechanism. Минимум5other-users в этом toy намеренно не выполняется: тест формулы не выдаёт production-support acceptance. Проверена только неоднозначность двух peer predicates, не полный temporal materializer.

**Что надо исправить до любого source probe.** «Последняя category/action seed» и «одна relation cart→purchase» ещё не задают поведение, когда последнее действие view. Нужно заранее выбрать: last event только при matching source role либо last eligible cart с отдельным age; это разные populations. Также определить multiple same-time seeds и отсутствие session. Статистическая unit — уникальный `(user,session,t1,t2)` с однозначными buckets; duplicate raw events не создают переходов. Важно выбрать **соседство всех observed buckets**: нельзя удалить неоднозначный middle bucket и соединить ранее несоседние крайние события без явного другого контракта.

Предел20buckets/session должен означать явный prospective overflow outcome, а не усечение длинной сессии после просмотра её будущего tail. Решение опирается только на prefix до snapshot W. Cap1m **admitted** rows и10k sampled background users не ограничивает physical rows, прочитанные для их нахождения. Receipt оплачивает scans/hash-sampling/user-list construction, исключение собственного вклада, metadata resolution, requested lookups, oracle и failures; уменьшение domain после overflow — новая попытка/план, не бесплатный refill. Будущая100Q проверка должна иметь минимальный заранее заданный nonconstant supported-Q gate; одного условия≥5users/edge недостаточно, чтобы оправдать fit на почти полностью missing matrix.

Pooled symmetric control допустим для **совместного** action+direction contrast. Он одновременно меняет две оси; результат не идентифицирует каждую отдельно. Не добавлять ещё два ablation fits: либо честно назвать composite, либо внутри тех же двух fit slots выбрать typed-directed против typed-symmetric для направления, или typed-directed против pooled-directed для action-role. Control использует тот же admitted transition bag и common typed support mask; вся population mass N и marginals определяются одинаковой политикой единиц. Self-exclusion удаляет u из cell,row,col,**N**, а не только count поддержки. Аудит должен охватить это явно.

После этих правок literal oracle обязан проверить middle-ambiguity, peer permutation, category change, own-only edge и изменение N после удаления u. Затем возможен отдельно рассмотренный≤100Q/≤30CPUmin/2threads/6GiB probe при предложенных10kusers/1m admitted rows/20buckets caps. Сначала freeze одну relation и все overflow правила; выбирать канал по quality или делать девять бесплатных looks нельзя. C остаётся фиксированным, никаких retrieval/graph-walk claims.

## NB-F04 — refine, материал counterexample к score уже получен

**Новизна** — source-adaptive allocation policy поверх существующей typed grammar002. HYP013 выбирает по supervised residual utility, HYP046 — semantic equality/cache; эти механизмы не совпадают. Однако новая policy не превращает сам legal pool в новые feature groups. FAM мотивирует temporal representation, а его learned labels-informed modulation не подтверждает наш stability penalty.

`(x−median)/(IQR+1)` не инвариантно к единицам. Независимый permitted literal: day1 `[-2,-1,0,1,2]`, day2 `[-3.6,-2,0,2,3.6]`, IQR2/4. Bins, замороженные на первом блоке, различают in-range и overflow. В единицах1 drift JS=0.16389659, score=0.85918286; при семантически эквивалентном `x×100`, с bins снова от соответствующего первого блока, JS=0, score=1. Четырёхдневное повторение A,B,A,B имеет ту же среднюю adjacent-day JS. Даже какой bundle получит преимущество, может зависеть от счётчика в единицах1/100. Это один разрешённый first-block binning, а не доказательство поведения всех возможных bins. Именно поэтому незаданный binning и additive1 нельзя оставить implementation choice после данных. Frozen units делают правило воспроизводимым, но произвольность reliability ranking остаётся до обоснования/исправления.

Для refine нужен scale-aware/dimensionless contract и literal scaled-alias test; IQR0, constant core, outliers, missing, overflow bins должны иметь разные определённые outcomes. Median/IQR по Q не сохраняют query-only level shift — это сознательный ranking-oriented выбор, его надо указать. Назвать точную bundle coverage (all/any cores), nonconstant predicate, support-only core policy, JS base/bin edges/weighting и aggregation нескольких cores. Равное число hash-selected Q в день не означает равное candidate-weighting: для query-macro цели разумно сначала нормировать histogram каждого Q, затем дать Q одинаковый вес. Иначе размер C/активность меняют score.

Второй literal дал JS0 для стабильных day histograms `[.5,.5]` и JS0.19274476 для чередующихся `[.8,.2]/[.2,.8]` при одинаковом pooled histogram. Значит temporal rule может отличаться от pooled filter; это не означает predictive usefulness. Stable nuisance может выиграть полезный emerging signal без какой-либо реализации ошибки.

**Fair control надо связать с claim.** Один frozen random draw проверяет всю policy против одного draw, не пользу drift. Если claim — дельта temporal reliability сверх coverage, самое дешёвое сравнение — reliability selector против deterministic coverage-only selector из того же8bundle pool; это **замена** comparator в тех же двух fit slots, не добавочные fits. Если оставить random, явно сузить claim и no-Y показать, отличается ли выбранный bundle от coverage-only. Collision не перерисовывать; одинаковые выбранные bundles могут использовать одну identical matrix/model procedure, но не образуют независимого подтверждения.

**Есть бюджетное несоответствие:** common ledger говорит pilot_queries100, а F04 требует4×100=400 warmup Q. При C≤220 это до88k Q–C пар и704k bundle-pair evaluations для8bundles; до24unique pool columns и2.112m scalar values, до выбора3column bundle. Shared DAG может уменьшить вычисления, но не объявить их бесплатными. До approval выбрать100Q total (например25/day с иной мощностью) либо явно вынести400Q exception с общей ценой≤30CPUmin, которую ещё не измеряли. Полная source coverage максимального окна на **всех четырёх днях** и завершение selector до первого downstream anchor обязательны. Текущие016 slots не переотбираются.

## Итоговый шлюз, фактическая работа и пределы review

Для всех кандидатов одинаковы будущие Q/C/full-Y, query weights, learner, train population, scoring prefix и physical feature accounting; cold/outside-C targets и empty mature Q сохраняются. Новая reservation и положительный compute/decision gap нужны до labels. Старые22–25 screening и закрытые25–31 нельзя превращать в новый независимый выбор. Предложенные30CPUmin no-Y и120CPUmin two-fit stages — ceilings одного выбранного будущего pilot, не4× разрешения. RSS/CPU/wall/source scans/failed attempts/oracle оплачиваются отдельно и полно; throughput в этом review не измерен.

**Выполнено фактически:** read-only docs/web; один standard-library literal arithmetic script `brainstorm-f001-literal-review.py`, его результаты `brainstorm-f001-literal-results.json`. F01 —20 вымышленных event rows в двух мирах; F03 —8 вымышленных rows в двух мирах; F02 —заданные curves/risk fractions, без curve fitting; F04 —10 чисел в двух днях и короткие histogram vectors. Ни project imports, real data/source hash streams, БД, Y, native models/fits, API inference/jobs, Git или shared edits не выполнялись. Tool reported wall≈0.1s для literal run; CPU/RSS не измерялись и resource benchmark не заявляется. Ошибок/assertion failures в literal run нет.

Финальная read-only проверка JSON/files/decisions прошла. Её первый inline-checker завершился SyntaxError из-за пропущенной закрывающей фигурной скобки до исполнения; исправленный checker прошёл. Это диагностический сбой проверки reviewer, не failure literal script или проекта; исходный сбой не выдаётся за успешную проверку.

Эти примеры проверяют различимость/недостаточную спецификацию. Они не проверяют будущий materializer, support на REES46, бюджет сканов, causal assumptions или quality. Canonical IDs и publication decisions остаются координатору; структура review ledger сохранена рядом как `brainstorm-f001-review-ledger.json`.
