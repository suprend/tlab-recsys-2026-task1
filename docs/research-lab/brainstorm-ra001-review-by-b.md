## RA-01: the memory value is a historical label and needs global maturity

The paper's §3.2 pairs sequence representations with next-item embeddings; the author's `precached_knowledge_val` actually appends `val_dataset` POS_ITEM_ID embeddings (lines201–226). Retrieval filtering permits other users' entries regardless of sequence length and only requires shorter length for the same user (line465). These are independently confirmed source facts; neither proves chronological availability across users. RA correctly treats the code as a transfer warning rather than an accusation about its leave-one-out benchmark. [RaSeRec paper](https://arxiv.org/html/2412.18378v1), [author model](https://raw.githubusercontent.com/HITsz-TMG/RaSeRec/master/recbole/model/sequential_recommender/raserec.py).

RA's genuinely new object is a **prefix paired with a later realized purchase set from another user**. NB-F01 instead conditions on the query user's own previous candidate-specific purchase context; ItemCF/UserCF do not retain the situation/outcome boundary. The cheap non-neural adaptation therefore has a defensible novelty delta. Keep the same bank records, historical outcomes, empty-outcome population, weighting and user-exclusion policy in full-prefix and last-bucket controls.

The proposed inequality `s+24h≤fit_cutoff≤available_at≤t` is necessary but must include actual bank/index completion and apply to every downstream row. Seeing an early purchase does **not** mature the rest of the source record's 24h window. Excluding the query user does not make another user's later outcome legal. A single end-of-training bank cannot be backdated to early training anchors. A daily bank whose last horizon ends exactly at midnight still needs build/availability evidence before that query; otherwise use an older available snapshot, record its age, or define a later anchor explicitly.

**Minimal decisive fixture:** memory anchor0h, horizon24h, one purchase12h. At query23h it is unavailable even though that purchase is known. If build completes24.1h, query24h still cannot use it; query25h may use the complete record. Changing an event at23.5h may change the mature memory later, but never query23h's output. Add two memories with identical latest buckets and different older buckets/continuations; only full-prefix matching should distinguish them. An empty mature continuation stays a legal record with no candidate vote.

Three refinements are needed before calling the pilot ready. First, eight timestamp buckets do not bound tokens: cap total items/actions or reject an oversized key using a declared past-only support rule. Second, define weighted-Jaccard weights, missing-key behavior, score ties and vote grain. Multiple daily records from one prolific external user must not silently become many independent supporters; use explicit record weighting and report distinct users, or one contribution per user/item in both controls. Third, distinguish key postings visited, memory similarities scored, fetched memory records and continuation item edges. Twenty-thousand records can still contain unbounded value edges. A “no-Y probe” here means no **downstream query Y** or quality look; constructing historical continuation values necessarily reads past purchases and is paid estimation/materialization.

The proposed≥20 queries with differing legal continuation candidates is an applicability gate, not a relevance result. Also require a nonempty difference after final union/cap against the matched control, before opening new query labels: new-to-user items can already be in global P200 and add nothing to C. Keep at most32 matched memories and the same lookup/score budget in both branches; if different key posting lengths change actual work, publish that cost instead of claiming equality from a shared maximum.

## RA-02: the same mechanism as RB2, with useful refinements

HyperHawkes mines session itemsets with FP-Max and projects incidence as `D^-1 H W B^-1 H^T`; the authors' mining code uses gap-derived subsequences and a TransactionEncoder/DataFrame before `fpmax`. Thus the paper supports high-order itemset discovery, but exact conjunction-sensitive retrieval is RA's adaptation. Logged `(user,session)` view sets and minimum distinct-user support are separate choices from that implementation. [Original paper, §4.1](https://pintonos.github.io/publication/peintner-www-2025/peintner-www-2025.pdf), [author mining code, lines79–148](https://raw.githubusercontent.com/dbis-uibk/HyperHawkes/main/recbole_custom/model/utils.py).

RA's Pasch-trade fixture and RB2's fixture are relabelings of the same information-loss argument: equal degrees and pair counts do not determine three-way membership. RA-02/RB2 should be one canonical hypothesis with both primary motivations. Do not count NPA versus HyperHawkes citations, an alternative naming or SKU labels as another mechanism.

Keep RA's strongest operational delta: both branches use the **same admitted triples, weights, user-subtracted supports and seed set**, while the projection gives half a rule's weight per observed antecedent. The exact branch requires both. This isolates conjunctive firing rather than a larger/different dictionary. A conventional independently built ItemCF graph is an additional reference, not this isolating control.

Clarify the units: minimum5 means five other **users**, not five sessions. Repeated sessions from one user may affect an explicitly separate session weight but cannot satisfy that gate. Subtract query-user membership before support threshold, shrinkage and top-K; subtracting after truncation can leave unavailable rules or lose legitimate ones. Session membership/admission is evaluated only on the prefix observed at the snapshot cutoff. A thirteenth item after that cutoff must not retroactively classify a previously legal twelve-item source as oversized; same-second membership is a set, not an ID-ordered sequence. Query-prefix cap and NULL/overflow behavior need the same explicit support contract.

The stated66 seed pairs for twelve items bounds pair probing, **not triple discovery**: there are220 triples and660 rule orientations per admitted twelve-item session. Across ten-thousand sessions that is up to2.2million triple updates before distinct-user bookkeeping. Fifty-thousand stored rules bounds output state, not attempted updates, preprocessing scan or dense transaction encoding. Use a sparse exact-triple implementation for the proposed operator, with separate attempted-triple, provenance-key, global-scan and lookup ceilings; do not import the author's dense encoding as a cheap default.

**Minimal falsifier/control:** run either eight-triple trade on literal sets with equal weights. Replicate each world's support across five distinct external users to exercise the actual admission gate; repeating one user's five sessions must fail it. The projected branch stays identical between worlds while exact completion changes. Add query-user-only support, same-second peers, duplicates and cutoff-crossing thirteenth item. If both branches collapse to the same projection, reject that implementation; if real supported firing is too sparse, defer practicality rather than claiming the mechanism mathematically false.

## RA-03: a real delta, but the estimator and support need narrowing

The paper's Eq8 sums past same-intent contributions and Eq10 mixes exponential/Normal kernels. The released model instead takes the latest eligible lag (lines148–149), uses supplied TIME in prediction (242/265), and reverses which mixture component receives `pi` relative to paper notation (163). Those paper/code differences are real; RA's horizon-integrated sum is a new discrete-category adaptation, not a faithful code transplant. [Paper, §4.3](https://pintonos.github.io/publication/peintner-www-2025/peintner-www-2025.pdf), [author model](https://raw.githubusercontent.com/dbis-uibk/HyperHawkes/main/recbole_custom/model/sequential_recommender/hyperhawkes.py).

Novelty survives versus NB-F02: RA transfers category-level episodes across SKUs and sums past-trigger contributions; NB-F02 is conditional residual waiting time after the last repeat of the same pair. Neither interpretation establishes replenishment. The truncated positive Normal, fixed24h horizon and observed query time avoid negative-lag mass and future purchase TIME. However, `A_k` is only integrated **past-trigger contribution with history frozen**. It is neither event probability nor full expected count of a self-exciting process that generates additional future events.

The equal-recency/different-earlier-episodes fixture tests summation, not specifically the delayed bump. Isolate kernel family first: two categories with equal item priors, one old episode each, horizon24h; use ages0h and36h, exponential mean24h, Normal mean48h/sigma6h with a fixed sufficiently dominant Normal weight. Exponential integrated mass decreases with age, whereas the delayed kernel is larger for36h than0h. Admission should switch categories. Then test summed versus latest-only separately; do not fund two quality looks under one contrast. A one-category pool can change all scores without changing any candidate admission.

Before estimation, define whether fitting inter-episode gap densities or a point-process intensity likelihood. These require different risk/conditioning terms; “include the cutoff integral” alone does not specify a valid estimator. First observed purchase is left-censored history, administrative cutoff is known, last user activity is not known exit, and completed gaps alone are insufficient. The proposed100 episodes/20users gate can still have no repeated timing information across users. Require observed repeated intervals and exposure through the candidate bump, with unknown support causing defer/global fallback under a frozen rule, never a fitted zero-return probability.

Collapse multiple same-category purchases in one global second to one episode under the declared operator. Multiple categories in that second stay a set; conflicting category attachments are unsupported. If several session IDs tie for latest observed time, exclude all tied latest sessions or mark that reference unsupported, not an ID-chosen “last session.” Daily category-item postings, buyer priors, denominators and metadata must share one available snapshot and age; midnight query must not read a just-finished same-day build retroactively. Known-but-unnamed category IDs remain usable.

Sixteen parameterized categories plus a global kernel does not cap the number of fallback categories, episodes or item postings examined per query. Record/cap each quantity, as well as kernel evaluations, estimation attempts and scan/state. Two kernel-family estimates plus two ranker fits are four estimation/fit operations inside a future shared cap, not two fits with free preprocessing. Until likelihood and real timing support are specified, **defer fits**, retain the literal falsifier and low priority.

## Common fairness and accounting refinements

P180+R20+S20/control20 and current P200+R20 are valid distinct prospective native policies with maximum220 and no refill. RA's label-blind deterministic thinning to the minimum actual size is a legitimate **separate diagnostic** if the same key/seed is frozen and exact size enforced; it need not preserve protected recent slots. Native results remain primary. Freeze source output dedup, extraction depth, ownership, tie order, source-empty behavior and support exhaustion; do not inspect deeper lists until enough unique candidates appear. Share source selection and support gates across each mechanism/control.

Equal C-size is different from equal lookup calls, equal scanned postings and equal fitting budget. Report all four. Retrieval Recall can be tested before any ranker fit after a separately reserved label look; later two fitted rankers answer a changed-C learner question. RA's primary should explicitly choose **conditional query-macro full-Y Recall**, with micro target-pair Recall alongside it. Gained/lost count `(query,item)` pairs; query hit-rate counts `1[|Y∩C|>0]` and must be separate. The published65/96 is target-pair coverage, not65 positive queries. Keep full Y outside U/source/C, mature empty-Y, and full-Y IDCG for downstream NDCG.

Recommended publication: one merged RA-02/RB2 family; RA-01 as a new research hypothesis with maturity/key/value/cost refinements; RA-03 deferred until exact estimator and repeated-risk support are credible. No new canonical IDs, current fits, heldout looks or throughput claims follow from this review.
