**Механизм/counter.** Профили других view-users seed-товаров могут дать endpoints вне original C0. Cosine может убрать head-популярность либо полезный спрос относительно shrunk co-count. Предсказание — непустые новые списки и различие top20 **множеств**. Пустота/одинаковые sets/дорогой complete build оставляют вариант infeasible/inconclusive; покупки/NDCG не обещаются.

**Входы.** Reuse accepted B48h Q/C0 из [таблицы schema/provenance](EVIDENCE-TESTS.md): только Q `(query_id,user_id,anchor)` и C0 source fields. Y/label columns/outcome reports/models не открывать. Root связывает Q/C0 с тем же immutable DB либо принятой equality bridge; одного raw hash недостаточно. Конкретные DB/Q/C SHA/доступность UNKNOWN.

**1. Заморозить Q100 до графа.** На всех 6000 уникальных Q8–10Oct2019 взять глобальные первые100 по `(SHA256(b"tlab-hyp061-q100-v1\0" + query_id.encode("ascii")).digest(), query_id.encode("ascii"))`, ascending unsigned-byte lexicographic. Query IDs — ровно64 lowercase hex, не decode-to-bytes; Q identity проверяется как SHA256 ASCII `query|2026|YYYY-MM-DDTHH:MM:SSZ|canonical_user_id`. Не отбирать по покупкам, seeds или дням; все100, включая пустые, сохранить. Q100 digest записать до scoring.

**2. Complete graph, один anchor за раз.** Для каждого представленного b=00:00UTC8/9/10Oct построить все distinct `(v,i)` view edges на `[b−7d,b)`; NULL user/product исключить, повторные события не добавляют голосов. По полному профилю вычислить m(v); m>32 исключает **весь** профиль. Получить G_b, полные item degrees d и profiles. Для q удалить все рёбра u: G_q=G_b\{u}; d_j(q)=d_j−1[(u,j)∈G_b], также когда u не видел seed. Удаление u перед admission эквивалентно этому, поскольку m остальных пользователей неизменно. Усечения32/512 запрещены.

**3. Общий discovery.** H — первые4 canonical R20 (all view/cart/purchase, latest timestamp DESC, signed product_id ASC), до guards и без добора. Seed допустим при 1≤d_h(q)≤512; остальные дают `seed_view_empty`/`audience_guard`. Обойти **все** ≤512 профилей ≤32 items, исключая j=h. Support c_hj — distinct других users; c≥3. Общий G_q/D/support: a=c²/(c+10), S_count(j)=Σ_h a, S_cos(j)=Σ_h a/√(d_h d_j). Нормы global внутри G_q, не локального seed expansion. Без activity weights.

**4. Выдать source.** Из полного D сначала удалить **весь original C0=P200∪R20**, затем ранжировать и взять до20 distinct. Scores binary64, `math.sqrt`, сумма в фиксированном порядке H, без epsilon/rounding; нечисловые/неположительные scores — ошибка. Ties: score DESC, SHA256 ASCII canonical signed-decimal product ID `.digest()` ASC, exact signed64 ID ASC. Decimal без `+`, leading zeros/`-0`. Endpoint имеет strict-past view witness, значит принадлежит U. Неполная adjacency — ошибка; confirmed empty — пустота. C_count/C_cos=dedup(P180∪R20∪S20), без refill, ≤220; купленные items не удалять. Вне C0 ≠ новая user–item пара. Сохранить ranks/support/rejections, actual |C|, graph/input identities; Y-метрик нет.
