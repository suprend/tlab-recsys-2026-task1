## Exact semantics and output preservation

A leaf's filter includes its own lower-inclusive boundary and common strict upper boundary. Every user/global peer at a is excluded irrespective of scan order. Mask aggregation is commutative and idempotent, so duplicates and reordered peers do not change DISTINCT; summing row masks is incorrect. Raw COUNT elsewhere still retains every duplicate. The mask is transient executor state, never a model column. Native bit type, OR aggregate, integer SUM and overflow handling remain untested;≤8 leaves keeps the logical mask finite, but does not prove a backend API.

The item-stage projection is independent of candidate category: unknown/ambiguous category does not erase item DISTINCT. Existing conditional category fields remain NULL for unknown current category; known empty counts remain0, zero-denominator ratios remainNULL, missing recencies remainNULL, and existing coverage flags remain identical. Metadata still uses the entire latest global past timestamp bucket, including other users and known+NULL mixtures; older-clean fallback is forbidden. Historical categories stay on events, and off-C category denominator rows are retained. The fused stage cannot replace those upstream global relations or authorize filtering every grain by C.

Source schema declares user/item nominal keys. The tiny NULL-projection witness tests COUNT DISTINCT's skip-NULL behavior; an actual adapter declaring user_id non-NULL must reject malformed source rows rather than silently repair the whole dataset. Predicate UNKNOWN contributes no bit only where the reviewed input contract allows it.

Rebuild the mask table separately for each anchor. Reusing an OR mask through expiry/retractions is unsupported: OR loses timestamps and multiplicities, so deleting an old occurrence or moving the lower bound cannot safely toggle a bit. A multi-anchor persistent implementation would need another reviewed state contract and is excluded here. Rows do not require chronological sorting for this fixed-anchor membership aggregate, but all common metadata/recency/first-seen work retains its own paid ordering/state requirements.

## Executed literals and finite cost

An invented12-row universe contains lower7d and lower24h equality, a duplicate view, three actions, repeated users, a NULL projection, upper-bound peer, expired event and an empty requested item. Every4096 sub-bag selection was evaluated at three anchors:12,288 snapshots and147,456 scalar values per path. Direct sets, mask fusion and per-action clocks all agreed. Peer reversal, future suffix relative to the earlier anchor and empty source preserved expected values. Replacing OR with addition was detected. A view from2d ago plus a recent cart gives view24=0; one pooled action clock would incorrectly make it1.

Two6-row worlds have identical leaf outputs `[0,2,2,2]`. With two shared users across actions, separate leaf sets and per-action clocks each retain6 keys, while fusion retains2. With six disjoint users they retain6 and fusion also retains6. Assuming only two8-byte nominal keys and a1-byte mask, logical payload is96 versus34 bytes in the overlap world and96 versus102 in the disjoint world. These exclude hash slack, alignment, table headers, thread-local copies, second-stage grouping, spill and sink. They are an arithmetic counterexample to guaranteed memory savings, not measured RSS or a benchmark.

Let E be examined raw rows in one anchor's item scope, L≤8 leaves, U the union `(item,user)` cardinality, M=Σ_j distinct memberships and I requested items. Simple execution evaluates≤L·E predicates, performs≤E union-key updates, reads U masks for up toL·U membership tests, and emits L·I integers. U≤M≤L·U. Encoded union state needs U·(keybytes+ceil(L/8)) **before** allocator/hash/thread overhead, plus I·L integer reducers. There are two blocking stages; during transition, union output and downstream aggregates may coexist. Parallel partitions can duplicate keys locally before merge. Spill may read/write intermediate pages repeatedly. No cardinality-independent bound or physical-IO reduction follows from fewer keys.
