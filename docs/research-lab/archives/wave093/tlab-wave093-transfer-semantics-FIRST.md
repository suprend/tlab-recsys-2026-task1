**Decision-changing obstacle.** Wikimedia Wikipedia Clickstream is a public event-derived relational counterexample to admitting an adapter merely because two entity-like columns and a numeric value exist. Its documented release projection removes low-count edges and aggregates the surviving requests over a month. Neither strict-past filtering nor a weighted count can recover discarded clock/actor information.

**Exact source boundary.** The official [Meta documentation](https://meta.wikimedia.org/wiki/Research:Wikipedia_clickstream), observed footer oldid **31171776**, describes four fields: `prev` mapped referrer, `curr` article title, `type` (`link`/`external`/`other`), `n` occurrence count. Requests are mapped through redirects; only main-namespace resources enter; pairs with ≤10 observations are removed. `other-empty` represents an empty HTTP referrer, not an empty behavioral history. The documentation explicitly warns that release preparation changed. This paragraph states the documented logical schema, not verified physical types or raw-file contents.

The [publisher README](https://dumps.wikimedia.org/other/clickstream/readme.html) identifies a monthly aggregate from Wikipedia request logs and declares Analytics datasets CC0. The [official index](https://dumps.wikimedia.org/other/clickstream/) lists **2019-10**, directory timestamp 11-Nov-2019 04:47. That timestamp is neither event time nor certified availability. **Mechanism and hand counterexamples (reasoning only).** For an otherwise eligible edge, histories with monthly counts 0 and 10 both project to no row: absence cannot certify mathematical zero. Histories containing 11 requests early versus late in the same month project to the same `n=11`, but their exact count in a specified 24-hour window differs. Counting projected rows yields one edge, while summing `n` yields 11 requests; neither identifies 11 distinct actors. No actor key or within-month timestamp is among the four documented fields. Mapping `prev` to user would turn a referring article or special bucket into a fictitious actor. These witnesses concern information lost by this projection, not an observed compiler failure.

**Counterhypothesis / narrower capability.** A correctly typed adapter could still support a declared **published-month, thresholded, weighted edge** task. Then sum(n) over published edges is meaningful; it is not complete traffic, user personalization, exact 24-hour recency, or REES purchase fullY. Missing edge means suppressed/absent/out-of-domain unknown unless an explicitly narrower estimand resolves it. A certified complete empty event window remains count0; this proposal does not redefine that case. A separate publication clock is required before any past-month feature is called available.
