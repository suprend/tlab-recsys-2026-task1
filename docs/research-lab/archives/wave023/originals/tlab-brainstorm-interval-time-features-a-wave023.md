**mechanism.** One observable contract property selects operators: `time_kind=instant` versus explicitly supplied **bounded occurrence-time support** `[L,U]` in exact UTC ticks. Storage dtype or a midnight timestamp pattern cannot establish this meaning. Human review supplies the semantic declaration; schema/value checks can reject it. Arrow distinguishes semantic types, physical layouts and timestamp parameters; it does not infer occurrence uncertainty. [Arrow specification](https://arrow.apache.org/docs/format/Columnar.html).

For this first production, allow only raw action-counts on user/item/pair grains and human-listed windows. Require known row availability A and a declared post-occurrence reporting contract `L≤U≤A`; admit rows only when `A<a`, excluding all availability peers. For window `[b=a−w,a)`, generate two integer fields:

`C_lo = Σ 1[b≤L and U<a]`

`C_hi = Σ 1[U≥b and L<a]`

Both sums use the same available qualifying raw bag. They conservatively bracket counts over supported occurrence times; they are not confidence intervals or corrections for unseen events. Duplicates contribute separately. Point supports `L=U` recover exact counts. Empty observed bags give 0/0 with existing source-coverage information. Unknown availability rejects the binding; malformed/missing bounds in the available prefix reject that anchor, never silently zero/drop rows. Future unavailable malformed rows cannot alter an earlier output. Open/unbounded intervals are unsupported. Category-as-of, exact recency, DISTINCT and ratio productions remain unavailable in this branch; do not fabricate them. PostgreSQL documents explicit range endpoints and distinguishes unbounded bounds; it supplies representation semantics, not our feature algorithm. [Range documentation](https://www.postgresql.org/docs/current/rangetypes.html).

**prediction.** Explicit interval support crossing a window boundary produces `C_lo<C_hi`; identical names with instant semantics produce exact counts. Example expectation, not a run: at `[10,20)`, support `[9,11]`, A=12 contributes 0/1, while point10 contributes1/1. An event available exactly20 contributes neither.
