## Existing work removes most apparent novelty

Rounds018/028/045 already require independent literal gold, list semantics, preconditioned metamorphisms, semantic mutants, every-row keys/types/NULLs and honest limits. They explicitly identify constant-zero/scaled/wrong-window survivors and common transport bugs. Duplicate insertion, off-C denominators, future suffixes and “use an independent oracle” are not new proposals here.

The remaining question is narrower: **does the acceptance procedure falsely approve a known-wrong producer when its supposedly independent oracle has a correlated fault?** A good score against producer-only mutants with a perfect oracle does not answer that. This is an audit of existing verification/AST acceptance under a fault model, not a new feature/operator or a claim of universal independent specification synthesis.

## MB7-R01 — correlated-oracle fault matrix for AST acceptance

**mechanism.** Treat the verification/admission procedure G as the system under test. For a small declared legal AST, independently implement producer-side and oracle-side toy variants; include correct versions and named non-equivalent faults in both. Evaluate pairs, including the *same semantic fault implemented separately on both sides*. Compare G's accept/reject decision with an independently written literal specification table. A common normalization/window helper is prohibited between variants and literal gold.

The matrix labels only cells for which a concrete literal witness establishes wrong semantics. Correct/correct must accept; wrong/correct should reject; wrong/wrong agreement must not be accepted merely because outputs match. Equivalent/no-witness variants are uncovered/irrelevant cells, not conveniently counted kills. Wrong source/capability contracts require explicit rejection; a missing result is not numeric zero. An oracle disagreement indicates investigation/STOP, not an automatic accusation against the producer.

This does not generate a new relation portfolio. Its difference from TB1 is the *assurance-system fault axis*: TB1's primary mutant fitness varies the tested implementation against semantics, while this audit also challenges that semantics implementation and final adjudicator. It refines their evidence/decision gate. If existing gold/transport gates reject all registered pairs, keep that negative result and do not manufacture a new HYP.

**testable_prediction.** A differential-only calibration gate will accept some correlated known-wrong pairs that existing absolute gold rejects. The useful future prediction is stronger: auditing correlated pairs can expose a false acceptance not found by an equal-budget producer-only challenge of the **fixed018/028/045 semantic policy's pure decision adapter**, or establish no additional finding. The first statement is demonstrable arithmetic, not a production-bug claim or sufficient novelty. Counterhypothesis: the existing independent gold bank already defeats every relevant common fault, so the matrix only restates documented obligations.

**nearest_source_free_experiment.** Freeze two existing legal count/DISTINCT ASTs and four tiny bags per AST, with at most8 invented rows/bag and at most2 keyed output rows×3 physical fields. Before any variants, independently author their eight complete literal expected records. Use six predeclared applicable fault families per AST, plus the correct producer and oracle: at most7×7 pairs. Candidate families are boundary, window, action, grain, bag/set multiplicity and source/transport faults; an inapplicable or unwitnessed family remains untested, without replacement search.

Use a separately reviewed, zero-native pure decision adapter for G's frozen semantic policy. This is not a replay of the current production runner; inability to isolate that boundary defers the test. The simple control is its correct-oracle slice, using the same ASTs/bags/variants, then compare with the correlated-fault cells. It is a coverage/false-acceptance contrast, not a claimed timing speedup. A deliberately weak differential-only checker is a **calibration negative control**, never the strong baseline. Fresh oracle-fault families cannot be used to tune G then called independent confirmation. No production compiler/oracle or current accepted artifact is executed by this proposal.

**benefit_task1.** When a new typed AST is proposed, report whether its verification procedure rejects explicit common-mode defects and which semantic obligations remain unchallenged. This improves the meaning of “accepted on bounded synthetic evidence”; it neither proves every input nor adds predictive information, dataset completeness or heldout access.

## MB7-N01 — structural mutation consistency cannot replace semantic gold

Generated-source checks could catch an action/window binding omitted during code emission before an engine run. They are a different observation seam from TB1's event-edit numerical relations. However, faithfully emitting a systematically wrong bag policy, lower boundary or shared normalization can preserve all expected structural changes. Likewise multiplying every count by2 preserves additivity/scaling and many structural response checks while violating an absolute count. Such a source check has no independent business specification merely because it avoids the numerical oracle.

Therefore do not admit “MCP passes ⇒ AST correct.” At most retain it as a separately scoped compiler-emission rejection preflight, with author-code/access and actual emitted-IR obligations still unverified here. The existing literal/direct-list/transport gates remain necessary. This is a negative boundary finding, not a second ready proposal.
