The main negative finding is that rare positive users do not make an AST's utility uncertainty identifiable from a few validation looks. A Bayesian surrogate prior, many candidate rows, many bootstrap repetitions and an anytime-valid library cannot supply missing independent information. A stop rule may save work, certify a property of a fixed finite validation set, or support a population claim under assumptions. These are different results and must have different evidence.

## Primary grounding and a counterexample to naive uncertainty

[Waudby-Smith and Ramdas, Estimating means of bounded random variables by betting](https://arxiv.org/pdf/2010.09686) constructs time-uniform confidence sequences under explicit stochastic assumptions, including a constant conditional mean; its without-replacement setting specifies random sampling of a fixed population. The inspected manuscript is2022; the [journal issue is February2024, with online publication2023](https://academic.oup.com/jrsssb/article/86/1/1/7043257). This is not a newly invented2024 AST selector. The paper links [author simulation code](https://github.com/WannaBeSmith/betting-paper-simulations) and the confseq implementation. I inspected the simulation repository's scope; no implementation was installed or run, and failed direct code fetches are not counted as verification of a particular API.

These results show why optional stopping needs a valid process, not why any clustered temporal ranking stream is valid. Moving from candidate rows to user clusters removes one obvious pseudo-replication but does not establish constant conditional mean, exchangeable days, or a sound ratio confidence sequence for conditional query-macro NDCG. Estimating AST utility after repeatedly adapting the AST on the same feedback introduces another dependency. No confidence-sequence transplant is admitted here.

**Own literal counterexample.** Draw one user's latent paired ranking difference Z uniformly from {−0.1,+0.1}; all ten positive queries of that user have difference Z. The population query mean is0. In either realized sample, empirical query variance is0 and ordinary query bootstrap returns the singleton interval {Z}. Resampling the one user cluster also returns {Z}; coverage of0 is exactly0 in this constructed population. Ten queries or thousands of candidate rows did not create independent positive users. The same construction with a shared day shock can defeat an independence claim across users. After the first observation, the next conditional mean is Z rather than0, explicitly violating the cited process assumption. This is an analytic example, not an estimate about our users or an execution of bootstrap on real data.

## A008-01 — stop evaluating a fixed candidate when remaining mass cannot rescue it

**mechanism.** For a separately authorized future *selection* block, freeze a finite AST list/order, all model/prediction identities and the incumbent W before its first outcome read. Evaluate candidate A and W on the same fixed Q/C, complete mature fullY and ranking/tie policy. Process whole user clusters in a label-blind fixed order. For every positive query q, let d_q=NDCG_A(q)−NDCG_W(q)∈[−1,1]. Queries whose targets all miss C remain positive queries with the proper zero scores. EmptyC and no-purchase queries are not silently removed from the population manifest.

Suppose an authenticated target-owner prepass supplies N, the total number of mature **positive queries**, not users, targets or candidate rows. After complete processed users contain n positive queries with difference sum S, let M=N−n. The exact eventual finite-set mean lies in

`L=(S−M)/N, U=(S+M)/N`.

Retire this candidate only if U is strictly below a predeclared necessary point-improvement threshold δ; equality continues. This cannot discard a candidate whose final finite-set difference reaches δ. It is a deterministic worst-case certificate, requiring no user independence and no variance estimate. A real controller must additionally bound the reference evaluator's floating arithmetic outward; NaN/range/integrity failures stop, without clipping or roundoff-based retirement. The literals use exact rational arithmetic. This is not a confidence interval or a generalization claim. Do not promote a candidate early: any remaining candidate needs full evaluation and the separate complete frozen decision rule, including Recall/support/cost guards. N=0 has an undefined conditional metric and yields no promotion certificate.

If N is unavailable, use the count R of remaining mature queries, all potentially positive. For n+R>0, the conservative envelope is `[(S−R)/(n+R),(S+R)/(n+R)]`. It maximizes/minimizes over every possible remaining positive count; it does not pretend the observed positive rate is known. When no positive has yet appeared, it is [−1,1]. At complete processing with n=0, the metric remains undefined. Reading a full target table merely to obtain N is label-derived work and feedback, not a free metadata lookup.

This controller emits a retirement reason/bound, not a new model feature or AST operation. All strict-past AST typing, physical closure, raw/distinct semantics, global peers, metadata/NULL and candidate contracts are prerequisites inherited unchanged. A valid retirement of A says nothing about an unseen AST, a different seed, a future day, or a whole grammar branch. Global AST search still stops at the prospectively fixed fit/feedback/resource caps; saved work grants no replacement candidate.

**testable_prediction.** If some already-fitted candidates are strongly harmful early, the controller can avoid their remaining metric processing while making the same practical-threshold accept/reject decision as full evaluation. For weak/zero effects and sparse support, bounds will often be too loose. If fitting, prediction sealing or target authentication dominates, total savings may be negligible or negative. It cannot save the fits already spent and must not be advertised as finding better ASTs with fewer fits.

**matched simplest control.** Evaluate the identical frozen candidate list, models and incumbent fully, using the same metric/target/candidate definitions and practical predicate. Compare terminal decisions and complete process cost; keep an untouched full-list oracle in a source-free test. The treatment's denominator prepass and internal prefix checks are charged only where actually performed; do not add unnecessary work to the full-evaluation control. Both have the same prospective maximum fit and feedback opportunity ceiling, but their actual look counts differ and must be reported. No extra candidate or refit is funded by either policy's saved time. If the existing look ceiling cannot accommodate even one prefix check plus a final look, the treatment is unavailable.

**nearest_source_free_experiment / cheapest falsifier.** Exhaustively enumerate bounded difference sequences in {−1,0,1} for N≤6, every prefix, and unknown-denominator completions up to six total queries. Verify each envelope contains the final mean and every retirement implies final mean<δ. Repeat at whole-cluster boundaries and with many no-positive queries. Include N=0, all-zero differences, a late rescue, unequal positive-query counts per user and ties at δ. Compare against the full finite-list oracle; construct an artificial operation ledger where fits/prediction sealing dominate to test whether claimed savings survive those common costs. No labels, SQL, model fitting or actual prediction is required.

**benefit_task1.** It can make a limited automatic evaluation stop auditable without inventing calibrated AST uncertainty. A successful result would concern finite validation-decision preservation and saved metric work. It supplies no recommendation-quality advantage and does not establish when to stop untested feature generation. In the present rare-support regime, a useful outcome may be a reason to retain the fixed-budget full-evaluation procedure.
