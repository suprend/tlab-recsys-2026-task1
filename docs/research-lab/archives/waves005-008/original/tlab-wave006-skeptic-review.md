## A006-01: what must be proved, and what the literals do not prove

The ideal `MustNew(p)` intersection is a sound lower bound when completions are nonempty and NewCols is computed **after the same canonicalization and fixed physical emitter relative to the full base**. A conservative subset remains safe. Empty completion sets need an explicit infeasibility case, not an undefined intersection. An intersection obtained by exhaustively completing every branch may consume the search work it aims to save; the draft correctly does not claim that implementation exists.

The crucial remaining artifact is a transformer for each constructor, including support/coverage/masks and alias lowering. “Committed leaves cannot cancel” alone is insufficient if later canonicalization can merge their names or reuse base outputs. The bound must refer to actual unavoidable physical identities. An empty lower bound is sound but may never prune. A three-column cap also needs exact completed closure; a lower bound cannot certify that exactly three columns will be emitted.

Shared dependencies `{a,m}` and `{b,m}` need three physical outputs, not additive four. Distinct actual mask names require four, not an assumed shared three. The given completion intersection `{a,m}` has cardinality two while both completions have three. These witnesses are correct and defeat bad accounting; they do not prove every proposed transformer sound.

The matched control is appropriate: same typed grammar, canonicalization, emitter, structural order, quota and final checks, changing only early rejection. Before claiming efficiency, freeze a concrete grammar and check every proposed partial bound against an exhaustive completion oracle; require no valid program to disappear and the same legal ordered prefix. A cap produces a censored prefix, never a global optimality/exhaustion claim. Count abstract-state, queue, alias, serialization and failed-branch work, not only fewer completed terms.

The arithmetic `4096×16×7×32 = 14,680,064` is correct for the stated naive complete-term interpreter envelope. It excludes queue/type/closure overhead, as the author discloses. The proposed60CPU-s/128MiB caps are stop proposals, not measured affordability or hard limits implemented by this draft. No full pruner, search scheduler or speed comparison was executed.

## R006-E1: raw syntax, semantic identity and information

Root relayed the author's post-freeze clarification: **202 means raw ASTs, not 202 distinct functions**. Preserve the frozen “202-function envelope” wording as a finding; interpret it as ≤202 semantic identities. Our independent exact enumeration sharpens that bound to **60 semantic classes** for precisely the declared grammar.

For terminals x,y and ordered binary Add/Mul with depth≤2: N0=2, N1=10, N2=202 and maximum expanded size7 are correct. Canonical rational polynomial coefficients plus strict-NULL dependency sets give60 classes. Alias-class sizes vary, so uniform syntax is not uniform semantic sampling. `(x+y)²` has four raw aliases in this universe. The 11-node cube macro correctly fails a common7-expanded-node cap; compressed token count cannot admit it for one arm.

The36 rational/NULL assignments yield7,272 scalar evaluations; the conservative node upper50,904 is correct. Exact traversal without early NULL short-circuit uses44,712 nodes in our check. For this *bounded* polynomial language, five distinct non-NULL points per coordinate separate degree≤4 polynomials, and NULL probes expose dependency patterns. Thus this grid separates all60 classes. That restricted fact does not license sample-output dedup for arbitrary division, temporal aggregation or protected arithmetic; the authors' broader counterexamples remain valid outside this bounded language.

The held family still needs an exact membership predicate. If the intention is the square's equivalence class, all four spellings must be excluded before archive induction. If it is a broader compositional family, define it by semantic structure/proof, not whichever spelling is easiest to remove. Freeze the archive algorithm, proposal policy, utility oracle, tie rules and allowed feedback. Search agents/library builders must not infer a hidden utility from privileged held-family/oracle access. A declaration that an artificial oracle will be supplied is not an implemented acquisition policy.

Same complete identity bank and same initial feedback, with separately observed later scores and potentially different visited subsets, is the correct allocation contrast. Forcing identical evaluated subsets would erase it. Conversely, providing a complete bank measures allocation over known identities, not discovery of a larger language. Report reachability/library influence and acquisition regret or best oracle value separately. None of those experiments was run here.

The deterministic-information statement is valid only when f uses the incumbent **input feature vector** and no new observations: `I(Y;f(W)|W)=0`. If a future grammar reads new raw predicates/windows, that premise must be revisited. “Both arms improve” would support representation usefulness, not newly observed behavioral information. Bind toy x,y to explicit source inputs before translating this toy recipe into a real feature experiment.
