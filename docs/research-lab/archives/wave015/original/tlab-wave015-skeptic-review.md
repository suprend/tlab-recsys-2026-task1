## One concrete permissions refinement

MB's narrow `chmod` statement is correct: Windows `chmod` sets the read-only flag and ignores the other conventional mode bits. However, Python3.12.4+ specifically handles **`mkdir(mode=0o700)`** by applying an ACL for the current user and administrators. Thus “all0700/0600 calls are ignored” would be false. Do not infer ACL equivalence for existing parents, inherited file ACLs, every creation path, symlink/case behavior or directory durability from that exception either. The actual patch, filesystem and creation APIs matter. This correction adds precision to optional native-Windows research; no permission experiment or ACL edit was performed. [Python chmod and mkdir](https://docs.python.org/3.12/library/os.html#os.chmod).

For Linux tools Microsoft recommends the WSL Linux filesystem over mounted Windows files. The recommendation is not measured project speed or an ext4/DrvFs equivalence proof. Git text/eol/autocrlf settings can change working-tree bytes at the same commit; original code/fixture pins still need truthful byte identity. Reissuing a local seal cannot authenticate changed bytes. A future host-specific authority may name different accepted environment binaries while retaining the same semantic/procedure lineage; it must not reuse an already consumed original attempt as a retry. [Microsoft filesystem guidance](https://learn.microsoft.com/en-us/windows/wsl/filesystems), [Git attributes](https://git-scm.com/docs/gitattributes).

## WSL and Windows lifecycle claims are correctly limited

Microsoft documents `.wslconfig` as global WSL2 VM settings, with default memory50% of Windows RAM and processors equal to Windows logical processors. Nominal32GB→16GB is arithmetic, not observed allocation or a new job allowance. Interop can launch Windows processes, and `wsl --shutdown` stops all running distributions; neither is the job's own Linux process fence. The target Windows build, WSL/distribution/libc, actual Python/disk/permissions and execution endpoint remain unobserved. No global configuration or shutdown was performed. [WSL configuration](https://learn.microsoft.com/en-us/windows/wsl/wsl-config).

Windows Job Objects do record associated terminated-process accounting and support termination/kill-on-close, subject to association/breakaway rules. They are a plausible separate native backend, not an implemented WSL/Linux adapter. `ProcessMemoryLimit`/`JobMemoryLimit` constrain committed virtual memory, so assigning the original RSS number silently changes the measured resource. These API facts do not prove an entire process tree is contained, or that a missing notification means no event occurred. No Job Object or process test was run. [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects), [memory fields](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information).
