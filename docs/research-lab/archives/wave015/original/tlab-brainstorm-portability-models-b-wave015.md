## Clean clone versus WSL2: unsupported boundaries

The Windows32GB/i7-10700K/RTX3070 description is user-provided context, not observed host inventory. Windows build, WSL availability/version, distribution/libc, Python, free disk and permissions remain unknown. No remote computer was inspected or configured.

Microsoft's `.wslconfig` memory/processors settings apply globally to the WSL2 VM; they do not provide this job's per-process RSS accounting. Default VM memory is50% of Windows memory, so a nominal32GB machine suggests16GB by arithmetic, not a measured allocation. WSL interop can launch Windows processes: any future Linux-only descendant accounting needs an explicit refusal or independently validated treatment of that escape. DrvFs metadata and case behavior also require examination. No global WSL setting was changed. [WSL configuration](https://learn.microsoft.com/en-us/windows/wsl/wsl-config).

Microsoft recommends the Linux filesystem for Linux-tool projects; a future reviewed WSL profile should name an actual filesystem, not merely “a Windows path.” That recommendation is not a throughput measurement here. [WSL filesystems](https://learn.microsoft.com/en-us/windows/wsl/filesystems). Native Windows `chmod` ignores mode bits except the read-only flag, so Unix0700/0600 calls do not establish equivalent Windows ACL privacy. Claims, symlinks/case aliases, newline conversion, exclusive creation and directory durability need platform-specific proof. [Python os.chmod](https://docs.python.org/3.12/library/os.html#os.chmod).

Windows Job Objects are a possible future native lifecycle backend: documented controls include accounting associated terminated processes, termination, kill-on-close and breakaway behavior. That is an implementation direction, not an implemented adapter or proof covering Linux descendants inside WSL. [Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects). Job/process memory limits in the extended-limit structure measure committed virtual memory, not RSS; assigning the same number would silently change the policy. [Microsoft memory-limit fields](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information).
