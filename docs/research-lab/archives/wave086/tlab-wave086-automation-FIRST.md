## Одно уточнение, ноль новых механизмов

**Предложение: конструктивный pivot-witness generator для существующего TB-B001 / rounds028/045 / TLAB-005/016/018.** TB-B001 уже предлагает AST-specific relations и portfolio synthesis; повторно регистрировать это как новый HYP нельзя. R3 принял89 targeted methods, rich all-eight и selected-F57/batching, но не exhaustive literal gold всего B45 или correctness каждого будущего AST. Обязательный native lifecycle и основной результат остаются приоритетнее этого optional пилота.

**Механизм.** Из reviewed semantic signature брать grain, action, projection, interval и explicit context. Независимая спецификация конструктивно создаёт одно включаемое и одно исключаемое событие: исключаемое нарушает ровно одно условие. Для count дополнительно строить удаления каждого pivot; для distinct удалять все копии одного projected key; для recency обеспечивать единственный последний timestamp и известный second-latest. Fixed Q/C/source bounds сохраняются. Генератор создаёт проверяемое предсказание влияния, а не объявляет producer output эталоном. Неясный unit, nullable key или неподдержанный context означает abstain с причиной. Category shares пока вне этого первого среза.

**Первичные основания и пределы.** [PQS, OSDI2020](https://www.usenix.org/conference/osdi20/presentation/rigger) конструирует запрос с заранее известным включаемым pivot row: это inspiration для constructive input generation, не готовый aggregate oracle. [Csmith, PLDI2011](https://users.cs.utah.edu/~regehr/papers/pldi11-preprint.pdf), §2, требует однозначной семантики генерируемых программ: valid AST и typed event contract должны предшествовать fuzzing. [GenMorph, 2024 author paper](https://valerio-terragni.github.io/assets/pdf/ayerdi-tse-2024.pdf), §2–3, оптимизирует false alarms/missed mutants и отдельно предупреждает о различии implemented и intended behavior; его Java machinery не переносится автоматически. Наш deterministic constructor — собственное ограниченное предложение, не воспроизведение этих систем. Новых dependencies не предлагается.

**Бумажный falsifier.** E содержит по одному past view и cart одной пары. Правильный view-count=1; wrong-action cart-count тоже1. Одно aggregate golden этого поля не различает их. После удаления view правильный результат0, mutant1; после удаления cart правильный1, mutant0. Это не обнаруженный production defect и не доказательство, что текущие89 methods пропускают mutant. Для exact distinct копирование существующего eligible события всегда даёт delta0; delta1 требует нового projected key. Удаление одной копии не заменяет удаление последней копии.

**Проверяемое предсказание.** Такой constructor на заранее выбранных legal signatures даст zero false alarms по независимым literal/list semantics и отличит хотя бы одну свежую held-out compensation/interaction mutant family, которую fixed и seeded-random portfolios пропустят при равном числе actual calls. Контргипотеза: он лишь воспроизводит round045/TB-B001 bank; production и oracle разделяют неверный predicate; специальные fixtures не дают новой различающей способности.

**Ближайший эксперимент — только предложен, UNRUN.** До выполнения freeze шесть legal AST: три raw-count grains, user/item distinct и pair cart-recency; до16 synthetic events/input. Сравнить fixed89-relevant bank, seeded random и constructive portfolios. Независимый скептик после freeze portfolios задаёт held-out mutant family; никакого feedback redesign. Каждый arm≤768 actual producer/reference executions; общий≤2304, включая generation/filtering/shrinking, не2304 pairs. Proposed inclusive caps:60CPU-s/90wall-s/256MiB/50MiB temporary outputs,0 labels/fits/API. Стоимость и adequacy UNKNOWN; authority отсутствует. Cap exhaustion означает incomplete, не PASS.

**Accept/reject и польза Task1.** Accept bounded reliability mechanism только при zero false alarms, заранее проверенной достижимости мутантов и новом discrimination при равных calls; reject novelty, если различия только старые или вызовов больше. Любой настоящий producer mismatch сначала диагностировать отдельно. Полезный результат — автоматически выдаваемый witness вместе с новым feature AST и явная граница поддерживаемой семантики; это повышает проверяемость feature automation, не доказывает quality gain, full-raw leakage freedom или универсальную корректность. ID, очередь, grants и deadlines не меняются.
