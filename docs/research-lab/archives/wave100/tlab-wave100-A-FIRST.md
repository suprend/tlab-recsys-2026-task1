## One proposed refinement: bind observation semantics before category portability

**Mechanism.** Keep the property observation clock and the feature's claimed measure together. A feature may mean “events assigned to the last property value observed strictly before each event,” or it may claim “events whose item actually belonged to category B when they occurred.” Weekly observed values identify the former under an explicit availability assumption; they generally do not identify the latter. No amount of typed count/window composition can recover information absent from the release.

**Literal counterexample, reasoning only.** Set query time `T`; snapshot time `t0=T−3d`; next weekly snapshot `t1=T+4d`. Released relations contain five synthetic source rows: property `(X,category,A,t0)`, property `(X,category,B,t1)`, property `(Y,category,B,t0)`, view `(U,X,T−24h)`, and externally fixed query/candidate `(U,Y,T)`. Availability equals observation time only for this invented fixture. There are no other events and the 24h source interval is declared complete. Candidate Y's observed category is B.

Two latent histories yield exactly that release: in early-change world E, X changes A→B at `T−2d`; in late-change world L, it changes at `T+1d`; Y remains B throughout in both. Both agree with the two weekly observations. The raw 24h view count is 1 in both. Last-observed-at-event category assigns X's view to A in both, so the observed-policy user-B view count is 0. The actual-state B view count is 1 in E and 0 in L. At query T, using the later snapshot B to relabel the old view would also use information outside the strict-past prefix. This is an identifiability witness, not an assertion that either trajectory occurs in the real corpus or that current production code commits that error.

**Counterhypothesis.** Exact continuous state is not needed for Task1: last-observed assignment is the intended source-local estimand, and existing policy identity already expresses it fully. Then this witness requires only honest wording; neither a new adapter nor an uncertainty operator adds demonstrated value. A future publisher contract explicitly guaranteeing effective change timestamps would invalidate this particular information-loss premise; no such guarantee was observed.
