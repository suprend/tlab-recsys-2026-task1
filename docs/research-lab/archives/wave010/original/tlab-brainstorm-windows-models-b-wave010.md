## Three executed literal counterexamples

Own Python stdlib arithmetic used21 invented rows, not project source or fitted models. In days since S=0, each day d=0…6 has A events at d+.25 and d+.75, and a B event at d+.5. At t=2, counts for W=(1,7,30) are A=(2,4,4), B=(1,2,2), with E=(1,2,2). At t=7 they are A=(2,14,14), B=(1,7,7), E=(1,7,7). Every available-span rate is A=2/day, B=1/day. A raw30d count has grown3.5-fold without an intensity change. It is a plausible calendar-age confound, not evidence that actual demand is stationary.

At each query, division by the common positive E preserves the rank A>B. So does any nonzero nonnegative window mixture here. Coverage is query-constant; it cannot independently reorder candidates for a monotone single-count scorer. In a multifeature tree it can still change cross-query thresholds/interactions, and different windows can have genuinely different candidate orderings. The witness therefore refutes a universal adaptive-window benefit, not all learned-window utility. It also prevents claiming that normalization alone repairs ranking.

Second, let t=4 and the only supplied event be at+.5. Hidden worldA has no earlier event; hidden worldB has events at−10 and−9.
