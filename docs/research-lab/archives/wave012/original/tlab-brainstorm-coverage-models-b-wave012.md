## Four explicit fields

**Mechanism clarified.** Give the existing purchase learner a feature's raw value, exact support and missing/coverage context before proposing a separate support-to-benefit gate. A fixed shrinkage transform is another existing simpler control. A separate gate chooses whether to acquire/use the feature or route between fixed rankers; it needs paid evidence that support predicts incremental purchase benefit, and a cost model separating shared source work from avoidable acquisition. None of these is newly proposed here.

**Prediction.** Two worlds can have identical past support descriptors and acquisition costs but opposite conditional feature benefits. Therefore no support-only policy has a universal purchase-ranking guarantee. A fixed shrinkage representation can reproduce a hard support gate's decisions on a simple literal, without an extra gating model. Skipping90% of row-level feature use need not save90% of the physical pipeline cost.

Compare a base ordering, all-feature ordering, fixed support threshold and fixed shrinkage. Separately distinguish five NULL/acquisition states and audit a dimensionless shared-source cost equation. These are16 tiny metric calculations, not actual Y, model inference or a quality experiment. Existing FB04 is the nearest later learned-router experiment.

## Executed opposite worlds and simpler representation

Own stdlib arithmetic uses fixed base scores `(A=.6,B=.3)` and a nested observed share `z=(0,1)`. There are two queries: rare support n=1 and common support n=100; both have complete supplied7d span. Raw augmentation `base+z` ranks B first. The simple threshold uses the augmentation only for n≥2. Fixed shrinkage uses `z̃=(n*z+κμ)/(n+κ)`, κ=4, μ=.5, then `base+z̃`; it ranks A for rare support and B for common support, exactly matching that threshold on this fixture. κ/μ are invented constants, not fitted priors or recommended settings.

In worldA the rare query purchases B and the common query purchases A. Base and all-feature query-macro NDCG20 are both.81546488. The support gate and fixed shrinkage both score.63092975: support-dependent use is harmful. In worldB the rare query purchases A and the common query purchases B. Formal purchase-target semantics and C are unchanged. This is a finite nonidentifiability counterexample, not evidence about how real rare users behave.

The example does not establish that shrinkage generally equals a learned router, that support is useless, or that incumbent W has those literal scores. With enough timely purchase evidence a learner can discover conditional benefit; a separate gate needs to justify its extra estimation and acquisition cost over an existing tree receiving raw value/support.
