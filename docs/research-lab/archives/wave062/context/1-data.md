# REES46 Multi-category: данные и происхождение

## Выбранный источник

- Авторская [карточка на Kaggle](https://www.kaggle.com/datasets/mkechinov/ecommerce-behavior-data-from-multi-category-store).
- [Каталог REES46](https://rees46.com/en/datasets) и [сервер данных](https://data.rees46.com/).
- Фактически скачан [2019-Oct.csv.gz](https://data.rees46.com/datasets/marketplace/2019-Oct.csv.gz) из `datasets/marketplace/`.

Это многокатегорийный товарный магазин, **не Cosmetics**. В текущем EDA анализируем только октябрь 2019 года, а не все месяцы авторской коллекции. Официальная карточка указывает бесплатное использование с атрибуцией страницы и REES46; обозначение прав `Data files © Original Authors` не является стандартной открытой лицензией. Здесь сохраняются ссылки и собственный код, исходные данные не перераспространяются.

Скачивание и проверка завершены 14 октября 2026 года. Контрольная сумма относится к сжатому архиву, а не к распакованному CSV.

| Целостность gzip | CRC и размер проверены полной распаковкой потока |
| HTTP Last-Modified | `Mon, 22 May 2023 11:56:43 GMT` |
| HTTP ETag | `"646b587b-67d3b85c"` |

Локальная запись проверки — `data/raw/2019-Oct.download.json`; она исключена из Git вместе с данными. ETag и дата изменения характеризуют ответ сервера при скачивании, а не период событий.

Для восстановления при отсутствии файла создайте `data/raw/` и скачайте архив по прямой ссылке, например:

```bash
curl --fail --location --continue-at - --output data/raw/2019-Oct.csv.gz https://data.rees46.com/datasets/marketplace/2019-Oct.csv.gz
```

До анализа проверьте SHA-256 скачанного файла. Команда работает через зафиксированное Python-окружение и читает файл порциями:

```bash
uv run python -c "import hashlib; from pathlib import Path; p=Path('data/raw/2019-Oct.csv.gz'); f=p.open('rb'); h=hashlib.file_digest(f, 'sha256'); f.close(); print(p.stat().st_size, h.hexdigest())"
```

Если размер или SHA-256 отличаются, это другой файл: не смешивать его результаты с текущими и не заменять молча контрольную сумму в протоколе.

## Схема

Проверенный заголовок содержит девять полей:

| Поле | Значение по описанию автора / политика EDA |
|---|---|
| `event_time` | Время события в UTC; проверяем парсинг и реальные границы периода |
| `event_type` | Тип действия; фактический набор и частоты определяем по полному файлу |
| `product_id` | Идентификатор товара |
| `category_id` | Идентификатор категории |
| `category_code` | Текстовая иерархия категории; может отсутствовать |
| `brand` | Бренд; может отсутствовать |
| `price` | Цена при событии; проверяем нули, отрицательные и нечисловые значения |
| `user_id` | Постоянный идентификатор пользователя по описанию автора |
| `user_session` | Идентификатор сессии; проверяем пропуски и структуру |

## Ограничения для будущего эксперимента

1. Просмотр карточки не равен показу рекомендации. Для задачи ранжирования потребуется отдельно определить допустимые кандидаты и отрицательные примеры; для конверсии — условие наблюдения и горизонт исхода.
2. Октябрь слева и справа обрезает истории. Первое событие в файле не доказывает регистрацию нового пользователя. Для горизонта покупки последние строки месяца могут не иметь полного наблюдения результата.
3. Цена, бренд и категория из позднего события не должны подставляться в признаки раннего прогноза. Нужно измерить изменчивость свойств и выбрать временную политику.
4. Частоты и длины историй из первых часов файла не являются статистиками месяца. Основной EDA использует полный файл; любое последующее подмножество описывается отдельно.
5. В EDA допускаются агрегаты по всем данным для диагностики. Они не становятся автоматически допустимыми признаками обучения: будущая модель получает только информацию, доступную к моменту прогноза.
