**Fresh primary facts.** The served official stable documentation identifies Featuretools1.31.0; this is a documentation observation, not a claim about an installed runtime. DFS accepts explicit relationships, primitive/column/path restrictions, depth limits, manually supplied seed features, and definition-only generation. Its default feature-count cap is unlimited. These are controls on enumeration; the API does not establish superiority of the generated features. [Official DFS API](https://docs.featuretools.com/en/stable/generated/featuretools.dfs.html)

The documented time index means when a row's information became usable. Default cutoff includes events at t; `include_cutoff_time=False` gives the event-window endpoints [t−h,t). A secondary index can delay individual columns. Approximation deliberately reuses aggregate values across cutoff buckets, so it is inappropriate as an exact temporal-parity control. [Official time guide](https://docs.featuretools.com/en/stable/getting_started/handling_time.html)

The published `_handle_time` code applies `<t` with cutoff exclusion, `>=t−h` at the lower bound, and masks secondary-index columns when their secondary clock is `>=t`. This is source inspection only. It does not invent missing availability clocks or restore overwritten historical metadata. The latter is an inference from the filtering/masking operation, not a promised library feature. [Official code](https://docs.featuretools.com/en/stable/_modules/featuretools/entityset/entityset.html#EntitySet._handle_time)
