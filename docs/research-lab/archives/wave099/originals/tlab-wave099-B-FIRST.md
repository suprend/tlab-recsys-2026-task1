## Одно уточнение: certificate одинаковых feature vectors для разных порядков

**Механизм.** Все текущие B18 и8 additions читают ограниченные counts/distincts/latest recencies/ratios с соответствующими mask/coverage; они могут отождествлять разные последовательности событий. Отдельный cross-action primitive HYP-142 различает такие истории. Это информационная граница текущего представления, а не обещание predictive gain. Новый ракурс к существующему семи-событийному FB-01 witness — удостоверить равенство именно *всех восьми фактических физических closure*, включая B41 и automatic flags, а не только нескольких вручную названных counts.

**Точный source-free witness / prediction.** Фиксировать один вымышленный query `(u,T)` и один внешний candidate `i` с категорией `c`; все metadata, candidate-source поля, source bounds и наблюдаемые ages заданы одинаково. Source coverage начинается в `T−200h`. Шесть строк относятся к тем же `(u,i,c)` и секундам `T−6h,…,T−1h`. В мире H1 actions `V,C,V,C,V,C`; в H2 `C,V,V,C,V,C`. Все view/cart counts равны3/3, purchase0; projected distinct для непустого action1; последние view/cart —T−2h/T−1h; earliest observation совпадает. Ни одно перемещение не пересекает24h/168h boundary. По source-inspection предсказываю одинаковые keyed44 model inputs для каждой из L01–L08, включая NULL/masks, source coverage и B41; это пока НЕ исполненная equality-проверка.

Для уже определённого FB-01 `A_VC=Σ_{s<r}(V_s C_r−C_s V_r)` ручной расчёт даёт H1:6−3=3, H2:5−4=1. Это та же antisymmetric area, без деления на2. Единицы — пары raw event occurrences, не «уверенность покупки». Идентичное значение current representation означает, что любой deterministic scorer только этих полей отдаст одинаковый score при одинаковых остальных inputs; stochastic fit может дать другой scorer, но не восстановит различие внутри пары одинаковых inputs. Никакие Y или искусственные разные purchase labels для этого вывода не требуются.

**Контргипотеза / возможный counterexample.** Возможно, в актуальной physical closure есть забытый order-sensitive компонент, coverage/age меняется или последний metadata bucket связан с исходными временами так, что H1/H2 уже различимы. Тогда equality prediction неверно; надо напечатать первую различающую колонку и ограничить certificate, а не выкинуть колонку ради успеха.
