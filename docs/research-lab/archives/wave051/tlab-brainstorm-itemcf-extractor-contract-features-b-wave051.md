# Wave051 FIRST A — один контракт будущего extractor

Уточнение существующего TLAB-012, без нового ID или runtime-допуска. Pure kernel принимает полные postings, но их полноту оставляет caller ([контракт:11](/Users/mdpospelov/tlab-recsys-2026/docs/experiments/itemcf-projection.md:11)).

**Механизм:** будущий extractor сначала строит конечный read-plan из аутентифицированного source descriptor, неизменных Oct22 Q/C/window043 и числа проходов. Лимит относится к посещённым исходным строкам, включая отфильтрованные; без доказанного pruning учитывается полный источник. Только допустимый план вызывает переданный opener. Отсутствующие/непривязанные сведения означают отказ, не «пустую аудиторию».

**Предсказание/ближайшая UNRUN проверка:** один fake-opener контракт имеет два сценария. Descriptor42 448 764 строк при старом отклонённом30m лимите обязан отказать **до opener**; два полных прохода требуют84 897 528 посещений. Это отрицательная проверка прежнего плана, не увеличение разрешения. [Root043:67–81](/tmp/tlab-root-wave043-research-readback-v1.json:67).

Положительный сценарий содержит ≤12 выдуманных view-строк: query-user и три других посетителя видели два товара; добавлены duplicate, lower-bound, anchor-peer и NULL-ключи. Независимый ручной/set-reference должен дать после own-exclusion степени3/3, common3, score3/13; неизвестный в snapshot требуемый item получает известный empty posting. Фильтрация аудитории только до query-users или преждевременный EOF должны провалить проверку. Реальные значения не извлекались.
