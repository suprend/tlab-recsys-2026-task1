# Wave042 — конечный потолок деревьев

**Решение:** сейчас сохранить 1200, без дополнительных экспериментов. Нулевая новизна: уточнение существующих 019/013 и собственных wave037/039/040, не новая гипотеза.

**Механизм.** Для будущего исследования выбирать один жёсткий потолок из полного вычислительного бюджета до очередного feedback; одинаковый потолок и правило выбора prefix для B/W. Близость выбранного prefix к границе может мотивировать отдельное конечное предложение, но не запускает удвоение автоматически. Выбранные 1189/403 — лучшие только среди проверенных prefix на данном selection.

**Предсказание.** Правило «лучшее около границы ⇒ надо продолжать» не гарантирует полезной отдачи. Общие принятые факты уже опровергают монотонное улучшение B: .460208 при 1189 против .455152 при 1200; W имеет максимум .465646 при 403 и .463815 при 1200. Это не исключает последующего восстановления и не доказывает оптимальность 1200.

**Ближайший конечный эксперимент — НЕ ЗАПУЩЕН и НЕ РАЗРЕШЁН.** Если когда-либо отдельно выбран бюджет: один потолок 2400, два свежих полных fit с прежними features/train/selection, собственный argmax каждого B/W среди всех 1…2400. Сильный контроль — тот же selector, одинаковые пространства поиска и сравнение максимумов prefix≤1200 внутри каждого нового fit. Совпадение прежних prefix — проверка переноса; его нельзя предполагать для продолжения через init_model или исправлять допусками. Если оба новых максимума остаются ≤1200, расширение не дало даже selection-выигрыша. Если максимум сместился, это только описательное свидетельство на повторно использованном selection, без нового heldout-утверждения. Повторное попадание в границу не разрешает следующий запуск.

**Польза task1 и стоимость.** Политика отделяет проверку вместимости от обещания улучшения автоматических признаков. Будущее предложение добавляет два fit-сегмента по 2400 и 4800 зависимых prefix-оценок; вместе с уже принятыми — четыре fit, 7200 выращенных деревьев и максимум 7200 selection-оценок. Оплачиваются preparation/source authentication, полные candidate predictions каждого prefix, точный fullY NDCG, сохранение моделей, память и проверка результатов; CPU заранее неизвестен. Все просмотры используют те же 73 положительных query: их число не увеличивает независимую информацию. Текущие 015, финальный результат, ресурсы и сроки неизменны.
