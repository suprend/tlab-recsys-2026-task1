**Mechanism.** Under an explicit offline timestamp-as-availability assumption, map view→view, addtocart→cart, transaction→purchase, preserving the event bag and observed actor identity. Resolve each (item,property) independently, strictly before the event for historical category and strictly before query for candidate category; retain latest-bucket NULL/conflict. Property revisions never count as interactions. Unsupported price/brand capability stays NULL, distinct from a supported known-empty count=0. Observed catalog remains event-derived; available-state neither establishes continuous stock nor silently filters C/fullY.

**Narrow refinement / falsifiable prediction.** Age since the last retained property row is neither time since the last observation nor exact stock-change time. Compression discards refresh timestamps. A future-property append must preserve earlier Q/C and supported feature values/masks under the declared as-of policy; whole-file metadata backfill fails this prediction.
