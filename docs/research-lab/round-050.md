# Round050 — replay ranking claims без локального approval state

**Read-only source audit; предложение к итоговому reproduction interface.** Нового материального дефекта принятых ranking primitives не установлено. Выделены два пользовательских пробела: самостоятельный replay сохранённых scores/full targets и явная привязка повторного inference к схеме. Это дополнение к README/018 phase2, а не повторение задачи выдачи source acceptances. Реальные данные, модели и live019/016 outputs не открывались; запусков нет.

## Уже существующий контракт

[Evaluator006](../../scripts/ranking_metrics.py) получает готовый ordered ranking, не сортирует ties и не восстанавливает targets из C. Recall и AP делятся на полный distinct Y; IDCG использует `min(K,|Y|)`, включая cold/outside-C purchases. Mature zero-Y и censored queries различаются. [008 runner](../../scripts/train_baselines.py) сортирует `group ASC, raw_score DESC, product_id ASC`, сохраняет все Q, использует float32 для признаков и int64 для product keys. Это согласуется с порядком ключей [numpy.lexsort](https://numpy.org/doc/stable/reference/generated/numpy.lexsort.html): последний переданный ключ — главный.

Соответствующие synthetic checks уже есть в [tests006](../../tests/test_ranking_metrics.py), [tests008](../../tests/test_train_baselines.py). [Independent loader audit](../backlog-reviews/tlab-model-data-independent-review.md) отдельно проверил IDs выше2^53, int64 limits, full Y outside C, empty C, порядок и NULL. Здесь эти тесты не исполнялись и их опубликованные результаты не расширяются до новых datasets или всех source formulas.

Общее слово «NDCG» недостаточно для replay. Например, официальный [sklearn.ndcg_score](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.ndcg_score.html) по умолчанию усредняет tied positions. Это допустимая другая метрика, но не наш deterministic product-ID tie contract. Настройка `ignore_ties=True` тоже не задаёт product-ID ordering. Аналогично evaluator на векторе relevance только для C вычислит другой IDCG, если Y\C непусто. Поэтому generic library name нельзя использовать как единственное описание принятого estimator.

## Пробел1: отдельная команда claim replay, не запускающая fit

Фактически [архив008 oracle](../backlog-reviews/tlab008-output-oracle.md) — audit record, не hardened CLI. Он требует существующие accepted collections/models и локальные approval/claim files. [CLI008](../../scripts/train_baselines.py) запускает весь training runner с обязательным fit approval; у006 отдельного file-based CLI нет. Опубликованный aggregate сам по себе не позволяет восстановить ranking. Это конкретный интерфейсный пробел сверх source-bootstrap018.

Предлагаемый минимальный read-only вход после разрешённого получения reproduction data: Q с query/user identity и maturity, полный Y отдельно, C и keyed finite raw scores, declaration K/estimands/ties плюс hashes этих файлов. Команда проверяет exact C↔scores key multiset, unique Q и Y, orphan keys, удержание empty-C/zero-Y Q; затем воспроизводит фиксированные aggregates. Позиционный `group` в NPZ должен связываться с exact ordered Q mapping, иначе перестановка Q переназначит scores другим пользователям. Само наличие одинакового числа строк недостаточно.

Для проверки механики без ignored state достаточно поставляемого literal fixture с заранее записанными ответами. Одна query: Y={a,b}, C={a}, ranking=[a]. Тогда Recall20=AP20=1/2, NDCG20=`1/(1+1/log2(3))`. Удаление b из target universe должно изменить результат и поэтому обнаруживаться. Вторая query с empty C и непустым Y даёт нули, третья mature zero-Y — undefined individual metrics и zero contribution только в соответствующем all-query estimator. Это упаковка существующих правил, не новый metric look.

IDs должны проходить транспорт точно. [RFC8259 §6](https://www.rfc-editor.org/rfc/rfc8259#section-6) гарантирует согласованное целочисленное значение между распространёнными реализациями лишь в указанном диапазоне около2^53. Поэтому arbitrary JSON/CSV→float→int маршрут неприемлем. Для synthetic replay нужны `2^60` и `2^60+1`, exact int64/decimal parsing и числовая ID-сортировка; decimal strings нельзя сортировать лексикографически как числа. Raw scores тоже нельзя округлять перед ranking: выбор winner с tolerance1e−12 и равенство prediction scores — разные правила.

## Пробел2: воспроизводимый inference schema gate

[CatBoost predict documentation](https://catboost.ai/docs/en/concepts/python-reference_catboostclassifier_predict) требует соответствия feature order, если имена не предоставлены с обеих сторон; при именованных входах поддерживается сопоставление по names. Здесь текущий008 `predict_scores` передаёт ndarray. В принятом runner это ограничено upstream ordered schema и train/selection equality; отдельный reviewer, загрузивший CBM и произвольный массив правильной ширины, такого контракта автоматически не получает. Это не finding против уже проверенного008 run.

Минимальный reproduction sidecar должен связывать model hash с ordered feature names, physical types/float32 conversion, NULL→NaN, nominal encoding при наличии, feature-definition/context identity, tree count и scoring prefix. До predict необходимо сравнить actual loaded model names с ordered inference schema и отклонить missing/extra/duplicate/reordered columns либо выполнить заранее объявленное name alignment. Нельзя незаметно разрешить оба режима. Native prediction type также явный: raw formula, а не classes по умолчанию; prefix задаётся независимо от общего числа обученных деревьев.

Проверка без нового fit: литеральная schema permutation должна отвергаться до native call; разрешённый named alignment проверяется отдельно. Replay сохранённой модели возможен только по отдельному разрешённому execution path и учитываемой стоимости. Для конкретного historical claim нужны соответствующие model/input bytes или независимо полученные rerun artifacts новой identity. Synthetic fixture доказывает поведение интерфейса, опубликованные hashes — связь с историческим запуском; ни одно из них отдельно не доказывает historical numeric result.

Эти два gap не требуют нового search, seeds, holdout opening или framework. Source approval generation остаётся существующим018 bootstrap gate. Итоговый README должен отдельно назвать contract-only smoke, metrics replay и native model replay, указать их необходимые входы и пределы доказательства. Если исходные артефакты reviewer недоступны, честный итог — проверяемые механика и агрегатная audit trail, но не independently replayed numerical claim.
