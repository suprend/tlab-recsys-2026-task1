## Primary-source and code verification

The algorithm also evaluates candidate transformations through downstream cross-validation. Public `src/iife.py` constructs every parent pair, calls a KNN information estimator, and invokes candidate model evaluation; it later applies `nan_to_num`. Therefore a discretized, NULL-preserving two-final-fit adaptation must not silently run that code path or claim to reproduce IIFE's full procedure. [Paper, §III](https://arxiv.org/html/2409.04665v1#S3), [author implementation](https://raw.githubusercontent.com/tomoverman/IIFE/main/src/iife.py).

FA02 accurately labels its local typed/proxy version an adaptation. The current abstract page has a September2026 v2 and changed title; version1 should remain the claim pin. I did not locate or inspect a TopoFE author implementation from the cited v1; implementation reproducibility is unverified, rather than disproved. [Version1 mechanism](https://arxiv.org/html/2607.23286v1#S3), [submission/version record](https://arxiv.org/abs/2607.23286).

## FA01 — conditional pair synergy

**Novelty accepted relative to backlog, conditional on the contrast.** Pair-level lookahead before expansion differs from HYP002/059's generic grammar and HYP013's joint residual predictor. F001's source reliability allocation uses no labels; FB mechanisms concern event structure, audience shape, episode reset and query routing. None performs this pair preselection. However, retaining weak marginal parents is a general motivation; the actual new mechanism is the explicit synergy-first versus marginal-first expansion policy under a common legal grammar.

The XOR literal is a valid mechanism check: balanced binary parents have zero marginal information and one bit conditional synergy. A duplicate-parent check should state its target: for `z=x`, synergy is `−I(x;Y)`, so it can be0 or negative. This verifies the formula, not the choice of transform. Require at least one allowed emitted expression that makes XOR accessible, such as a same-unit difference with values−1/0/1, and test its NULL closure. A zero-marginal pair score alone does not certify that a dimensionless ratio grammar can express a useful child.

**Required repair to accounting.** Twelve parents imply66 unordered pair scores before the32 expanded programs, multiplied by the chosen context cells and every shuffle/estimator repeat. Thirty-two is not the number of total outcome-aware looks. Freeze bins, context partition, weighting, sparse-cell policy, pair tie order, number of scanned pairs and allowed child operators. Candidate-row frequencies must use an explicitly declared weighting population; variable candidate counts and repeated users otherwise alter the selector objective relative to the ranking task. Do not represent all these dependent statistics as66 independent trials.

**Minimal proposal.** First≤16 literal rows,12 parents at most,66 pair scores,≤32 children,0 fits,≤5 CPU minutes/256MiB; no real data permission implied. Only afterwards propose the original100-query source gate and two B+3 fits inside60 CPU minutes/6GiB, paying all entropy estimates, generated closures, failed operators and scoring. Strong current incumbent and the marginal-first arm are both needed; exceeding the cap stops the experiment instead of dropping support silently.

## FA02 — directed family migration

**Defer, not reject as duplicate.** A stateful donor policy is distinct from static016 and the semantic/blinded/random comparison. Cross-family reachability is a legitimate symbolic property. It must be described as a property of the chosen restricted grammar; deliberately forbidding the target within each island does not by itself demonstrate quality or search efficiency.

The literal instruction to compare routing “using the same evaluated children” needs qualification. If each policy receives identical children, identical scores and simply takes their best, there is no measured discovery advantage left. Match the *legal universe* and paid opportunity count while allowing different logged visited subsets. Alternatively replay one common observation history solely to test updates, and label that a mechanics test. Adaptive policy gets only scores for visited children; uniform control cannot be denied a cache visible to the learned policy. With three families there are six directed edges; an eight-evaluation pilot may spend nearly everything on initial evidence, so any general strategy claim would be weak.

**Minimal proposal.** At≤64 literal ASTs and0 fits, prove reachability, legality, finite expansion and update/tie behavior. Freeze whether six initial edge probes plus two adaptive decisions fit the eight-opportunity cap, and pay the same initial information for uniform routing. Before real data specify the contextual-information reward, negative gains, stagnation threshold, replacement policy and exactly what archive state is shared. Then the original24-program universe/eight evaluations per policy/two final B+3 fits/90 CPU minutes/6GiB can be considered. If a predictor or downstream validation becomes feedback, count every fit and metric look; the two-final-fit ledger no longer covers it.

## FA03 — shared search and local adaptation

**Refine: the proposed incompatibility falsifier fails mathematically.** Let X be a balanced bit. A task with Y=X and another with Y=1−X both have `I(X;Y)=1bit`; one-to-one sign inversion likewise preserves mutual information. Conditional information within a fixed context has the same invariance. Therefore the suggested third task with an opposite sign does not expose negative transfer to the stated information-score selector, and a sign-flip local mutation cannot improve that proxy. A downstream learner may or may not handle the reversed relationship; that is a different test.

**Constructive repair.** Use balanced independent X,Z on the four binary combinations. Tasks1/2 have Y=X; task3 has Y=Z. Programs X and Z have shared mean information2/3 versus1/3bit, while task3's local replacement X→Z changes its information0→1bit. This creates the intended shared preference and task-local repair without a model. Add a no-positive task to verify missing/insufficient-support policy; normalizing by zero entropy cannot produce evidence of transfer.

**Interface and cost gap.** “Three local programs” does not yet define three downstream columns. Either evaluate all three programs globally on every row, or declare task gating and charge every extra mask/support/task-membership column. Overlapping category/history tasks, missing task state and whether the pooled learner can identify the task affect behavior. Freeze one choice. A shared selector with category slices afterwards remains duplicate administration; different initialization followed by actual local mutation is the novelty.

Nine task-program evaluations can be fair: two initial programs×three tasks=6, then three local candidates=3. Every score used for task normalization, shrinkage, support pruning, mutation selection or task projection must appear in that ledger. Shared caches may save CPU but cannot provide independent search with less information. Two pooled fits prevent six hidden per-task learner fits, as FA correctly notes.

**Minimal proposal.**≤20 literal rows,0 fits,≤5 CPU minutes/256MiB for the repaired tasks, exact nine-score trace and column schema. Defer real source work until task definitions, support cutoff and gated/global output are frozen. The subsequent two-arm90 CPU-minute/6GiB ceiling is a proposal only. Worst-task loss needs a prespecified threshold and uncertainty treatment; dependent tasks and existing inspected dates cannot become independent confirmation.

## FA04 — induced typed macros

**Defer to symbolic gate; novelty survives only as altered search prior.** Library induction differs from hand-written templates and physical DAG sharing. Macro expansion introduces no new representable primitive function when the original grammar already contains every expanded AST. The potential benefit is discovery probability or reuse, not additional information per scalar column. This distinction is already mostly present in FA and should govern reporting.

Freeze primitive grammar, expanded-node/depth caps, proposal law, archive provenance and one held compositional family before induction. A successful macro cannot be credited with one cheap proposal if its hidden expansion consumes many primitive opportunities; failures, duplicate aliases and archive generation consume attempts. At equal expanded-node effort compare discovery probability over prespecified seeds or enumerate the small finite proposal spaces analytically. One lucky target hit is mechanics evidence. The current eight bundles are insufficient grounds for assuming a useful learned library.

**Minimal proposal.** Keep FA's≤20 literal ASTs/≤4 macros/5 CPU minutes/256MiB/0 fits gate. Use a minimal local symbolic implementation if a later implementation is authorized; importing the full LILO environment does not inherit that small resource bound. Test expansion equality for NULL, temporal endpoints, fitted constants and units, and reject renamed B/retrieval aliases after expansion. Only a nontrivial held-family result can motivate the later≤30-program/two-fit/60 CPU-minute/6GiB proposal, including all archive and meta-training costs.
