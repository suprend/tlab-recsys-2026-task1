## Проверка первоисточников

- **DFS:** авторы, год, название и relational composition подтверждены. §III описывает filters/time bounds, а §VI — дополнительные time-interval features/categorical filters в опытах. Осторожная интерпретация round соответствует статье; результат соревнований не превращён в обещание автономного strict-past поиска. [Авторский PDF, §§III/VI](https://groups.csail.mit.edu/EVO-DesignOpt/groupWebSite/uploads/Site/DSAA_DSM_2015.pdf).
- **ExploreKit:** название/авторы совпадают; §IV-B действительно обучает ranking classifier на ранее исследованных datasets и создаёт его labels через feature trials. Отклонение готового meta-ranker из-за отсутствующего versioned corpus/model обосновано. Статья не поставляет наш temporal ranking protocol. [Авторский PDF, §IV-B](https://people.eecs.berkeley.edu/~dawnsong/papers/icdm-2016.pdf).
- **OpenFE:** metadata авторов/2023 совпадает с PMLR, включая необычное написание имени Zheyu Aqa Zhang. Algorithm 2 задаёт correction к baseline predictions, Algorithm 3 — random data blocks, Algorithm 4 — отдельную attribution; transductive theoretical setting действительно указан. HYP-013 честно называется адаптацией, не воспроизведением. [PMLR metadata](https://proceedings.mlr.press/v202/zhang23ay.html), [официальный PDF, Algorithms 2–4/§4](https://proceedings.mlr.press/v202/zhang23ay/zhang23ay.pdf).
- **CAAFE:** авторы/название и описание code+explanations корректны; §3 использует validation feedback и random validation splits, Appendix E.1 скрывает feature names/dataset description. Semantic-blinding control имеет первичное основание, но его результат не подтверждает наш DSL proposer. [Официальный NeurIPS PDF, §3/E.1](https://proceedings.neurips.cc/paper_files/paper/2023/file/8c2df4c35cdbee764ebb9e9d0acd5197-Paper-Conference.pdf).
- **Featuretools:** утверждение о `include_cutoff_time=False` подтверждено: в примере нижняя граница включена, cutoff исключён. Это документационное поведение конкретного времени/window API, а не проверка всех nested joins и fitted transforms. Round правильно оставляет ответственность адаптеру. [Официальная документация Handling Time](https://docs.featuretools.com/en/stable/getting_started/handling_time.html).
- **Online Retail:** официальная карточка подтверждает Daqing Chen/2015, DOI, 541 909 строк, даты 2010-12-01–2011-12-09, XLSX 22,6 MB и CC BY 4.0. Перечисленные invoice/customer/product поля присутствуют. Cancellation определяется **префиксом** `c` InvoiceNo; InvoiceDate описывает дату/время, точность/timezone не обещаны. Карточка говорит «no missing values», но корректно не подменять этим будущую проверку файла. [UCI: schema, file, citation, license](https://archive.ics.uci.edu/dataset/352/online%2Bretail).

Фальсифицированных источников или существенного искажения их результатов не найдено. Содержательные выводы об их применимости к REES46 — inference/proposal round, а не измеренная переносимость.

## Material finding: confirmation может оказаться уже использованной validation

**Место:** общий контракт round: «B — уже проверенный strong manual TLAB-008/009» и разделение четырёх development-дней на selection/confirmation. В backlog TLAB-008 выбирает loss на validation 22–25 октября, TLAB-009 выбирает feature blocks на validation без reservation поздних двух дней.

**Точное воспроизведение ошибки в плане:** сначала выбрать B/PairLogit-versus-BCE/блоки по метрике всех четырёх дней 22–25, затем назвать 24–25 confirmation для B+G, заморозив только модели текущего round. Поздние дни уже влияли на baseline и связанные решения. Отсутствие refit и закрытый final test не возвращают им независимость. Bootstrap interval описывает разность после такого выбора и не делает её подтверждающим доказательством механизма.

**Минимальное исправление:** до первого TLAB-008/009 fit зарезервировать поздние development-дни для confirmation **всех** связанных решений: baseline/loss, ручные блоки, grammar/selector, budgets и thresholds. Общий manifest фиксирует доступность метрик и maturity границы, единственного кандидата, правило selection и используемые контрольные модели. Либо честно назвать эти дни reused development и оставить вывод screening-only без confirmatory promotion. Уже просмотренный confirmation повторно не открывать следующим paper round; нужен новый заранее закрытый временной блок либо отдельная запланированная final оценка после lock. Не переносить test в development ради исправления.

Это плановая коллизия, не утверждение о состоявшейся утечке: upstream fits ещё не доказаны выполненными. Сейчас она исправляется reservation policy без дополнительных вычислений.

## Проверка гипотез и границ оператора

**HYP-011 — accepted-for-pilot как конкретизация HYP-002, не новая независимая search-программа.** Отличается от ItemCF HYP-001, lexical HYP-003 и retrieval HYP-004: текущая популярность прошлых товаров агрегируется в user reference. Общий t и `[t−w,t)` для всех вложенных item states корректны; использование актуального past-only состояния старого товара не является утечкой само по себе. Самовклад пользователя тоже не требует автоматического удаления: это отдельная семантическая sensitivity.

Существенное ограничение интерпретации уже признаётся round: reference одинаков для всех кандидатов query, поэтому вычитание само по себе не меняет popularity ordering. Приоритет результата — interaction/context feature для boosting, не улучшенный самостоятельный ranker. Tiny oracle должен проверить distinct weighting, пустой D, обе границы и изменение глобального item state между двумя anchors; future suffix не меняет прошлые values. Не вводить history cap незаметно при дорогом heavy user: cap означает новую AST/policy. Прошедший 100-query pilot не доказывает стоимость полного global scan/state.

**HYP-012 — deferred, design-only; refinement HYP-002.** DSL-only, отсутствие validation feedback и raw rows, aliases и штраф за invalid proposals поддерживают честный proposer-control. До потенциального запуска сохранять exact prompts, разрешённый источник вызова, version/seed/settings, alias mapping, все invalid/duplicate attempts и фактическое число delivered columns. Семантические имена не должны сохраняться в скрытых DSL аргументах blinded prompt. Один запуск S/G/A даёт case study, не превосходство search strategy. Никакого API-вызова настоящим review не разрешено.

**HYP-013 — deferred, альтернативная замена HYP-012.** Train-only supervised selector не обязан быть strict-past feature: его outputs — frozen feature choices, а не backward-injected predictions. Поэтому in-sample residuals B здесь риск качества отбора, не автоматическая temporal leak. Перед снятием deferred нужны точные selector loss, group/query weights, baseline score scale/offset и importance/tie rule. Иначе flat rowwise probe может отбирать признаки по массе negatives/head queries вместо объявленного ranking estimand. Joint probe на восьми новых колонках моделирует их взаимные interactions; для утверждения interactions с исходными manual columns те должны явно входить в probe. OOF fits нельзя добавлять бесплатно ради исправления in-sample риска.

**HYP-014 — rejected в текущем cap.** Причина — отсутствующие пригодные pretrained inputs и стоимость их получения, а не опровержение метода ExploreKit. Возобновление требует нового evidence и явной замены бюджетного плана.

## Ledger и generalization gates

Общий потолок **12 новых scalar columns / 4 fits / 2 CPU-часа** относится к одному TLAB-016: G/S/A либо residual-selector branch, не сумма ветвей. Baseline уже должен быть пригоден; любой его новый fit, proxy, failed run, repair и preprocessing расходует общий лимит. Supports/masks считаются колонками; cached identical AST не пополняют proposal attempts. Manifest должен различать columns, attempts и fits, определить CPU-time versus wall-time и фиксировать выбранную ветвь до запуска. Confirmation scoring также учитывается во времени.

UCI пригоден для будущей schema-compatibility проверки, но view grammar переносится только после явной замены event semantics. Invoice lines, distinct invoices и quantity — разные grains; cancellation не следует превращать в purchase или задним числом удалять покупку по будущей отмене. Missing customer нельзя объединять в одного «пользователя»; меняющиеся descriptions/prices требуют as-of. Пока файл не проверен, stable-user coverage, timestamp resolution и пригодный horizon остаются неизвестными. Это adapter gates будущего pilot, не требование скачивать данные сейчас. Успешная компиляция operators подтверждает schema portability, а измеренный gain на REES46 не подтверждает качество на UCI.

**Promotion recommendation:** перенести round вместе с этим review, связать HYP-011–013 с HYP-002/TLAB-016, разрешить HYP-011 bounded screening после upstream gates. Подтверждающее принятие результата требует исправления reservation коллизии, неизменных manifests и полного ledger. Новые задачи сверх указанных не нужны.
