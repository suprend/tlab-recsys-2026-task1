# Wave046: helper и будущий consumer

Root принял оба независимых FIRST и отдельный critique как исследовательское уточнение существующих TLAB-019/014. **Новый CLI отложен до конкретного будущего consumer и семейства входов.** Действующий adaptive study CLI уже выбирает validation prefixes; наличие callable helper само по себе не создаёт обязанности написать ещё одну команду. Новых ID, задач, обязательных gates, grants, проверок или runtime в этом раунде нет.

Предложения авторов — разные будущие adapters: authenticated split exports публичного reproducer и accepted collection lineage старого v1 loader не взаимозаменяемы. В v1 требуется `label_available_before == fit_data_cutoff`, одинаковый model_timing фаз и затем `fit < ready <= selection_start`. Допустим явный числовой `max_queries <= 6000` либо `None`; `max_rows <= 1320000`. Полный study с 5 317 058 строками этот loader всё равно не поддерживает.

Сохранён барьер принятого adaptive study: **оба fits завершаются до validation feedback**. Atomic per-arm fit→select helper не заменяет этот порядок автоматически. Для отдельно выбранного consumer будущая проверка должна связывать реальные входы, один helper call на arm, сохранённые counts/models и отказ без fallback; spies не доказывают native fit/shrink/serialization.

Полная будущая стоимость включает обе resident матрицы, подготовку, Pool/weights, полную и выбранную копии модели, все зависимые prefix evaluations, сохранение, аутентификацию, ошибки, startup и tail. Cooperative check и engine limits не задают полный RSS/lifetime. Никакие предлагаемые test caps не выданы; старые workflow/final/закрытые budgets не меняются.
