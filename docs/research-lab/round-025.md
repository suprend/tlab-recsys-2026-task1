## Что первичные источники действительно поддерживают

[Autofeat, Horn–Pack–Rieger, §2.1](https://arxiv.org/html/1901.07329v2) использует SymPy для simplification и Pint для ограничения физически бессмысленных выражений **когда units предоставлены**. Авторы не заявляют автоматическое восстановление currency, exposure или population subset из названий колонок. Их scientific flat-table transformations/selection не реализованы в005 и не получают дополнительный budget.

[Featuretools primitives](https://docs.featuretools.com/en/stable/getting_started/primitives.html) задают input/output types и допускают stacking; aggregation сворачивает связанные rows. Это полезный типовой интерфейс, но одинаковый numeric dtype не доказывает одинаковую единицу счёта, causal role или denominator domain. [DuckDB aggregates](https://duckdb.org/docs/current/sql/functions/aggregates) различают count rows, count non-NULL и DISTINCT; их SQL semantics не разрешает складывать overlapping unique sets. [Boyd–Vandenberghe, Jensen](https://web.stanford.edu/~boyd/cvxbook/bv_cvxslides.pdf) даёт основание не переставлять нелинейную функцию и averaging. [NumPy log1p](https://numpy.org/doc/stable/reference/generated/numpy.log1p.html) определяет log(1+x), real domain/NaN и особую численную точность около0; это не утверждение, что current009 SQL `ln(1+CAST(price AS DOUBLE))` численно тождественен NumPy implementation.

## Минимальный proposed signature

До common pool freeze каждый AST связывает `grain/keys`, physical dtype, **semantic unit**, domain/population ID, bag/set и distinct projection, event predicate/window/endpoints, source/adapter/context, metadata/availability policy, operands, defined-value bounds, NULL stages и arithmetic/encoding stage. Аннотации задаёт reviewed schema contract: ID номинален даже при BIGINT; raw-line-count, distinct-user-count, seconds и price-in-source-unit различаются. Unknown unit не угадывается из column name. Допустимость temperature/volume operations в Pint не доказывает корректность event probability.

Для exact share нужны counts одной raw bag population с одинаковыми source interval, event/window и multiplicity; numerator domain должен быть подмножеством denominator domain. Тогда `0≤N≤D`, а приD>0 отношение в[0,1]. Grain reduction должен быть many-to-one без join fanout. СрезC не имеет права заменить ALL-category denominator. Current005 валидирует matching count operands/event/window и поддерживает только user-category/user и item-category/category shares; independent source checks удостоверяют конкретные значения. Наличие numeric outputs и успешный bounds check не является самостоятельным proof правильной population.

Historical event category в counts и current clean candidate category выбирают разные роли одной context expression. Category ID и readable code не взаимозаменяемы: объединение нескольких IDs под code требует такого же domain у numerator/denominator. Taxonomy membership может намеренно размножить одно событие по ancestors; это не partition. Distinct union требует объединения projected keys или доказанной disjointness, а не суммы scalar cardinalities.

## Четыре literal counterexamples

**1. Ratio и denominator.** В одном admissible окне bag содержит `view(U,X,c)`, `view(U,Y,c)` и три `purchase(U,X,c)`. Pair purchase/view=3/1=3: это action ratio, не вероятность и не ошибка, требующая clamp. ItemX view-share категории равен1/2. ПриC={X} ошибочный C-only denominator даёт1/1=1, тоже внутри[0,1]. Значит, bounds test пропускает неверную формулу. Подмена7d numerator на24h denominator также уничтожает subset proof, даже при совпадении physical units. Beta–Binomial не получает обоснования из этих counts.

**2. Membership и uniques.** Два события одного пользователя: itemX вA.B, itemY вA.C. Expansion вroot/A/leaf даёт root2,A2,B1,C1; сумма всех node counts6 при event mass2. Корректная root partition mass2; STOP нужен для прямых событий внутренних узлов. Distinct users вB=1,C=1, их sum2, но distinct union уA=1. Разные legitimate units — event memberships, events и users — нельзя выровнять одним названием count.

**3. Возраст и NULL.** Source начинается за7d доt; первый observed event пользователяA — purchase за1h. Source coverage7d, observed age1h, настоящая exposure неизвестна; эти величины не равны. View countA=0, view-recency=NULL, rate по нулевому denominator=NULL. Другой пользовательB имеет пять views вне известной категорииc: sharec=0/5=0. При неизвестной candidate category conditional count/share=NULL даже с тем же denominator5. All-NULL latest metadata bucket не разрешает older-clean backoff. Known-key count0 при coverage0 остаётся0 с unobserved flag по accepted005, а не доказанным отсутствием событий за всю неделю.

**4. Transform order и scale.** Две admissible peer prices в одной source unit:1 и3. `mean(log1p(p))=(ln2+ln4)/2=ln√8`, а `log1p(mean(p))=ln3`; они различны. Current009 считает среднее логов по distinct eligible past products, не по raw events и не толькоC, с membership-conditioned leave-one-out. При числовой смене единицы1→100,3→300 log-price difference становится `ln301−ln101` вместо `ln4−ln2`: cross-unit invariance отсутствует. Явный reference scalep₀ с согласованным conversion мог бы определить log(1+p/p₀), но это **новый contract**, не current005 operator и не автоматическая правка009. Currency в source не установлена этим исследованием; mixing currencies нельзя объявить исправленным логарифмом.

## NULL stages и conservative rewrites

SourceNULL/ambiguous/unsupported, aggregate-empty, denominator0, transform-domain-invalid и model NaN различаются до encoding. Numeric price0 математически допускает log1p, но009 policy требует positive clean price; zero/negative flags сохраняются, value missing. Нет peers — peer meanNULL, known category support0; unknown category — supportNULL. Ошибка domain или overflow не должна молча становиться «таким же missing», как отсутствие наблюдений. Supports/masks/coverage остаются в closure и column budget.

Rewrites разрешаются только с preconditions: `n/n=1` неверно при0/NULL; cancellation плавающей арифметики и transform/cast ordering не гарантированы. Float32 collision не доказывает semantic equality AST. Нелегальные sum/log/price/arbitrary ratio operators не становятся legal005 от наличия правильного mathematical example. Такой запрос отклоняется доpool, одинаково для intelligent/random arms; postmetric pruning/replacement не разрешены.
