## Что первичные источники действительно устанавливают

**Amazon Reviews 2023.** Provider определяет время отзыва и purchase-verification flag; это не время покупки. Parent ASIN задаёт группировку вариантов и metadata join. Цена относится к crawl, у части reviewed items нет metadata. Поэтому полный purchase target за следующие 24 часа не идентифицируется даже при точной нормализации времени. Snapshot metadata не удостоверяет historical category/price. Это ограничение наблюдаемости задачи, а не утверждение о плохих значениях конкретных строк. [Provider fields](https://amazon-reviews-2023.github.io/main.html#data-fields).

Авторский `kcore_filtering.py`, прочитанный на mutable main с blob `52b9dacc4d3c183f20dcc98e0440acae840bb5eb`, сортирует reviews пользователя, сохраняет первое вхождение parent item, затем итеративно применяет core threshold. Точный grain — `(user_id,parent_asin)`. Уже 0-core не сохраняет raw multiplicity. Будущая зависимость whole-file 5-core membership — логическое следствие этой процедуры, не обнаруженная утечка в проверенном corpus. Код требует `sortTimestamp`, тогда как field table называет `timestamp`, а пример сайта — `sort_timestamp`. Нужен versioned schema mapping; этот mismatch не доказывает неисправность выпущенных файлов. [Author preprocessing](https://github.com/hyp1231/AmazonReviews2023/blob/main/benchmark_scripts/kcore_filtering.py).

Формулировка «data license unresolved» обоснована: maintainer 8 марта 2024 сообщил, что не может назначить dataset license, при исследовательском распространении. Более позднее согласие на конкретную thesis не устанавливает общий corpus redistribution grant. MIT software license и publication license не заменяют dataset terms. Это запись provenance, а не юридическое заключение или запрет текущего чтения документации. [Maintainer reply](https://huggingface.co/datasets/McAuley-Lab/Amazon-Reviews-2023/discussions/1).

**RelBench требует материального уточнения.** Нынешняя HF card действительно описывает двухлетние purchase-labelled review tasks и review-rating autocomplete. В pinned v1.1.0 три user-item класса объявляют `365 // 4` дней: 91 день, используют review_time, правую включённую границу и исключают customers без подходящих future review IDs. Отдельные варианты добавляют rating=5 или text length>300; verified-purchase predicate отсутствует. Это source facts о конфигурации/SQL, а не проверенный runtime horizon или содержимое cached labels. Current card и v1.1.0 registry принадлежат разным версиям; последний не содержит review-rating. [Current card](https://huggingface.co/datasets/stanford-star/relbench-v1/blob/main/rel-amazon/README.md), [v1.1.0 task source](https://github.com/stanford-star/relbench/blob/v1.1.0/relbench/tasks/amazon.py#L222), [versioned registry](https://github.com/stanford-star/relbench/blob/v1.1.0/relbench/tasks/__init__.py#L92).

Pinned builder также использует amazon_v2, seconds и Books/5-core по умолчанию, статические product/customer tables и фильтрацию по пригодному price/product intersection. Его нельзя представлять как Amazon Reviews 2023 adapter или источник исторической metadata availability. [v1.1.0 builder](https://github.com/stanford-star/relbench/blob/v1.1.0/relbench/datasets/amazon.py#L10). Авторский draft корректно цитирует двухлетнюю card, но финальная интеграция обязана сохранить это docs/code/version расхождение; эквивалентность двухлетнему исполнению отвергнута.

**RetailRocket.** В отличие от reviews, объявленный transaction channel даёт подходящий наблюдаемый event type для source-local purchase target. Это ещё не доказательство полной записи покупок либо зрелости каждого горизонта. Weekly property snapshots, compressed unchanged values, global metadata coverage и min/max event timestamps не устанавливают ingestion clock, непрерывное состояние stock, историческую taxonomy availability или полные окна. Current-property state и last-observed-event category — разные законные policies, если заранее объявлены; их нельзя менять после scores.

Текущий reader не вернул тело Kaggle card. Размеры, weekly compression и CC BY-NC-SA 4.0 сохраняются как явно помеченные publisher claims из прежнего primary-source record и frozen author draft, без новой независимой сертификации файла/лицензии здесь. Не заменяю это вторичными notebooks и не объявляю лицензию неизвестной только из-за пустого parser result. [Publisher URL](https://www.kaggle.com/datasets/retailrocket/ecommerce-dataset/home), [прежний record036](../../docs/research-lab/round-036.md#L5).

Pinned session-rec commit `5dcd583cbd8d44703a5248b9a308945f24b91390`, blob `7489134964099d0b783d47a131f67fa5aeaf0139`, подтверждает обработку native time как milliseconds, но переводит его в integer seconds. Он строит synthetic sessions, оставляет views и возвращает carts в объект, экспортируемый как buys; transaction outcome этим путём не сохраняется. Следовательно, название buys не удостоверяет покупки, а event за 1ms до целой секунды теряет исходную давность. Видимое удаление не созданного в этой функции TimeTmp дополнительно исключает утверждение о доказанном успешном runtime. [Pinned author code](https://github.com/rn5l/session-rec/blob/5dcd583cbd8d44703a5248b9a308945f24b91390/preprocessing/session_based/preprocess_retailrocket.py#L80).

DBInfer pinned loader только читает заранее созданные table/task splits; из него не выводится, чем построен cvr outcome. Неизвестная construction остаётся неизвестной. RecPack documentation подтверждает view-only defaults и support filters, но pinned adapter не удалось повторно получить; его конкретные conversion internals не приняты как доказательство. [DBInfer loader](https://github.com/awslabs/multi-table-benchmark/blob/bd58e8de2bce98005c04eedaa6b4a914821f26b9/dbinfer_bench/rdb_dataset.py#L71), [RecPack 0.3.0 docs](https://recpack.froomle.ai/generated/recpack.datasets.RetailRocket.html).

## Первый проверенный исполняемый transfer gate

Выполнен один stdlib-only script: [literal-gate.py](brainstorm-wave004-literal-gate.py), [results](brainstorm-wave004-literal-results.json). Он извлекает неизменённые AST definitions symbolic generator/registry validator, без импорта project modules или DuckDB. Восемь cases PASS; process CPU0.01064s, source/config bytes до/после одинаковы. RSS/весь wall-clock исследовательского чтения не измерялись; это не dataset runtime estimate. Независимый reviewer прочитал script/results без повторного запуска и не нашёл замечаний.

Доказано в этом ограниченном срезе: canonical declaration порождает8 bundles и original L02/L06/L01/L05 slots с execution_approved=false; честный review-only источник и raw RetailRocket field names отказаны; reduced12 база не наследует frozen pool. Копия ожидаемой декларации проходит независимо от того, есть ли за ней реальные purchase logs. Это ожидаемый раздел ответственности, а не найденная ошибка генератора: source evidence подаётся извне. [Actual guards](../../scripts/feature_programs.py#L70), [base guard](../../scripts/feature_programs.py#L105).

Дополнительно сверены только собственные literal arithmetic/property/identifiability witnesses. Production EventFact enrichment, Amazon F2, реальные loader outputs, SQL, источник/покрытие и quality не проверены. Один выполненный source-only gate не делает внешний benchmark ready.

## Что остаётся до любого внешнего качества

Для RetailRocket надо заранее выбрать last-event enrichment либо новый query-property protocol; установить units и offline availability assumption; независимо принять raw-preserving adapter, source coverage/maturity и fullY; затем определить source-local Q/C/control. Event-only route требует нового полного model schema, dedup/closure и allocation identity на обоих event datasets. Совпадение individual AST definitions не наследует current8pool/41base/control approval.

Для Amazon оригинальный purchase24h experiment отвергнут структурно. Нужен отдельно названный observed-review task, если вообще продолжать; он не станет purchase replication. Amazon и RetailRocket нельзя объединять как одинаковую задачу только потому, что оба дают(user,item,time).

Fairness означает identical Q/C/fullY и training rule внутри каждого source, независимые source-local model fits и reservation, заранее заданный contrast и полный учёт preprocessing/failed attempts. Raw NDCG между sources не paired; разные purchase rates/coverage нельзя исправлять outcome-dependent sampling. Same seed не доказывает одинаковое пространство search, если изменилась legal pool. Текущие source reads и literal gate не выдают новых fit opportunities, data access либо бюджета. Следующий разрешаемый root шаг — конкретный versioned capability/adapter contract; actual external quality остаётся отдельной задачей.

Итог: оба draft полезны как source-transfer contracts после указанной RelBench qualification. Прямой перенос B41/full purchase-fullY на Amazon отклонён; полный B41 на RetailRocket остаётся условным. Первый проверенный runnable slice подтверждает только symbolic refusal/identity boundaries. Code compatibility не является external dataset quality.
