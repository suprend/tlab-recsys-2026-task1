# Conditional tabular synthesis: independent source check

Checked 2026-10-15 against original ICLR papers and current author `main` code. Static reading only: no project data, live brainstorm reports, SQL, model fitting, downloads, installs, or external jobs. Source links are mutable upstream snapshots, not pinned releases.

## Verdict

**TabDiff (ICLR 2025) supports a plausible label-conditioned wrapper through executable author sampler code, but does not ship a documented rare-class augmentation command.** Its shipped CLI trains joint synthesis and imputes the target **from** features, which is the opposite direction from generating features **given** a positive label. Treat B41 augmentation as an unvalidated adaptation, not an already supported experiment. TabSyn (ICLR 2024) is a weaker implementation starting point here.

## What the sources actually establish

- TabDiff jointly corrupts numerical columns with Gaussian noise and categorical columns with absorbing masks, using learned per-column schedules and a shared transformer/MLP denoiser. Conditional missing-column sampling is part of the paper, but downstream evidence concerns synthetic-table replacement and target imputation, not rare-purchase augmentation or grouped ranking. The reported hardware is one RTX A4000 with 16 GB. [Paper, §§2.5, 4.3, App. D](https://proceedings.iclr.cc/paper_files/paper/2025/file/5c882988ce5fac487974ee4f415b96a9-Paper-Conference.pdf)
- Author `Trainer.test_impute` sets `cat_mask_idx=[0]` for binary classification, masks that target, and takes observed test features as its input. `--y_only` trains the missing-target marginal needed by their CFG path. This is **p(label | features)**, not a class-conditional data generator. [Trainer](https://github.com/MinkaiXu/TabDiff/blob/main/tabdiff/trainer.py), [entry point](https://github.com/MinkaiXu/TabDiff/blob/main/tabdiff/main.py), [README](https://github.com/MinkaiXu/TabDiff)
- The lower-level `sample_impute` accepts arbitrary numeric/category masks. With all 41 numerical columns missing and the sole categorical label known, it can generate a feature vector while preserving the positive category. Its default `x_t` path forward-noises known values at each reverse step and combines known/generated parts; `x_0` instead clamps known values but initializes missing numerical values from the supplied placeholders. This is an actual generic code primitive; binary augmentation behavior is **my static inference**, not an author-tested CLI or an executed result. [Sampler](https://github.com/MinkaiXu/TabDiff/blob/main/tabdiff/models/unified_ctime_diffusion.py)

Proposed minimal adapter contract, **not executed**: fit one joint model on permitted training rows; pass mean-filled normalized numeric placeholders, the **encoded** positive category, `num_mask_idx=range(41)`, `cat_mask_idx=[]`, `impute_condition="x_t"`, `resample_rounds=1`; construct with `y_only_model=None` and use zero guidance weights. Invert train-fitted transforms and audit constraints. The standard target-only CFG checkpoint has the wrong role for this direction: guided feature generation would require an additional marginal model over the missing feature block and interface validation. Do not silently reuse `--y_only`. [CFG and masking implementation](https://github.com/MinkaiXu/TabDiff/blob/main/tabdiff/models/unified_ctime_diffusion.py)

TabSyn uses a separately trained mixed-type VAE and then latent diffusion. Its generation script samples joint latent rows without a label argument; its README describes target-column inpainting and only multiple numerical/single categorical imputation. [Paper](https://proceedings.iclr.cc/paper_files/paper/2024/file/e9750610639c3e7a849cff746bf60dbd-Paper-Conference.pdf), [generation script](https://github.com/amazon-science/tabsyn/blob/main/tabsyn/sample.py), [README](https://github.com/amazon-science/tabsyn)

Current TabSyn `impute.py` also has static execution blockers: parser defines only `dataname/gpu`, then reads `args.epoch`; uses `bin_class` while preprocessing uses `binclass`; performs list `mask_idx += d_numerical`; and hard-codes a CUDA tensor. These were read, **not reproduced**. It is unsuitable evidence of turnkey binary conditioning. [Author demo](https://github.com/amazon-science/tabsyn/blob/main/impute.py)

## Cost and dependency gates

- No cross-dataset pretrained weights are required by either method. TabDiff trains a dataset-specific denoiser; TabSyn additionally trains its VAE. Existing author benchmark checkpoints would not remove B41 training requirements. [TabDiff main](https://github.com/MinkaiXu/TabDiff/blob/main/tabdiff/main.py), [TabSyn VAE](https://github.com/amazon-science/tabsyn/blob/main/tabsyn/vae/main.py)
- **Budget trap:** TabDiff config `steps=8000` means 8,000 **full epochs** in `run_loop`, hence `8000*ceil(N_train/4096)` gradient updates, plus loss/EMA evaluation. Sampling uses 50 diffusion steps, approximately 99 denoiser calls per sample batch with second-order correction, and default sample batches of 10,000. A bounded pilot must set explicit update/row/time caps and a checkpoint policy; shortening training can break automatic `best_ema_model` discovery because that checkpoint is saved only after epoch 4,000. Do not confuse 50 reverse steps with training cost. [Config](https://github.com/MinkaiXu/TabDiff/blob/main/tabdiff/configs/tabdiff_configs.toml), [training/checkpoint loop](https://github.com/MinkaiXu/TabDiff/blob/main/tabdiff/trainer.py)
- Author TabDiff environment pins Python 3.10, PyTorch 2.0.1/CUDA 11.7, NumPy <2 and includes sklearn/pandas, SDMetrics, XGBoost, wandb and several unrelated baseline packages. Synthcity fidelity evaluation uses a separate environment. CPU fallback exists, but source support is not a measured CPU runtime guarantee. Wandb defaults online; a future approved local pilot must disable it. [Environment](https://github.com/MinkaiXu/TabDiff/blob/main/tabdiff.yaml), [device/CLI](https://github.com/MinkaiXu/TabDiff/blob/main/main.py), [README](https://github.com/MinkaiXu/TabDiff)
- TabSyn code allows up to 4,000 VAE epochs and 10,001 latent-diffusion epochs with stopping logic; its paper used RTX 4090 24 GB. This is an extra training stage, not cheap off-the-shelf pretraining. [VAE](https://github.com/amazon-science/tabsyn/blob/main/tabsyn/vae/main.py), [diffusion](https://github.com/amazon-science/tabsyn/blob/main/tabsyn/main.py), [paper, App. E](https://proceedings.iclr.cc/paper_files/paper/2024/file/e9750610639c3e7a849cff746bf60dbd-Paper-Conference.pdf)

## B41 feasibility conditions (task-specific inference)

Only existing candidate-row training labels and strict-past numeric features may enter the generator. Fit imputation/quantiles/generator within each training time boundary; no validation/test/future rows in synthesis, checkpoint selection, nearest-neighbor filtering or transformation fitting. Keep real evaluation candidates unchanged. No generated impressions, texts, orderID, exposure denominators, users, purchase events or candidate groups. A generated `y=1` is an assumption inherited from training labels, not an independent observed purchase.

Generated features can violate integer/nonnegative counts, nested-window inequalities, zero/missing sentinels, ratios and shared user/context values. Quantile inversion is not a guarantee of cross-column or contextual validity. This route is coherent only as regularization/augmentation for a pointwise learner over candidate features. Inserting synthetic rows into listwise/query losses needs a defensible group/context generator, which the proposed row generator lacks. Popularity/availability and candidate support remain determined by the real pipeline. Rare labels may yield memorization or collapse; synthetic diversity does not establish effective sample size.

## Own tiny source-free falsifier and matched controls

**Analytic label-information check, no fitting:** invent four two-candidate queries; every row has the same all-zero feature vector, and the positive candidate is an independent fair coin in each query. Any feature-only scorer must tie: expected Hit@1 is 1/2 and AUC is 1/2. Add 100 conditional synthetic positive copies per real positive: the class prior changes, but expected ranking remains 1/2. Claiming extra independent labels, reduced uncertainty from a larger nominal synthetic N, or ranking lift on this construction fails immediately.

**Conditional-support check for a future source-free sampler smoke test:** define numeric columns `(a,b)` with legal relation `b=a²`; true positive support is `(1,1)` and `(3,9)`, true negatives `(2,4)`. Encode labels as a categorical column. Generation conditioned on positive must preserve that label **and** the two positive modes; merely preserving the output label is insufficient. Positive SMOTE midpoint `(2,5)` violates the relation; repairing it to `(2,4)` fabricates a positive at known negative support. This does not predict TabDiff's output; it gives an explicit failure witness and rules out treating interpolation or clipping as automatically label-valid.

If later authorized, compare fixed baseline; exact random positive oversampling; positive SMOTE; and TabDiff augmentation, with the **same number of added positives, total synthetic/duplicate weight, class prior, learner, preprocessing, update budget and seeds**. Include class-weighting as the oversampling-equivalent check. Keep natural-prior, chronological real evaluation and grouped top-20 metrics. Report invalid-row rate, mode coverage, label-conditional separation and duplicate/nearest-neighbor rates before utility. Stop if the wrapper ignores the label, violates declared support, consumes the cap, or shows no repeatable incremental ranking benefit over matched oversampling/SMOTE. All smoke/model work remains unperformed.

**Disposition:** keep as a gated augmentation hypothesis; TabDiff generic imputation supplies the mechanism, but neither source establishes benefit for B41, independent labels, or immediate feasibility within an unspecified budget.
