## 1. EDA: проверить, какие постановки поддерживают данные

Рассчитать по полному месяцу:

- Объём, временные границы, пропуски, фактические типы событий, некорректные значения, точные дубли. Дубли сначала измерить; правила их обработки не применять молча.
- Частоты событий по дням, наличие пропусков времени и изменения состава данных.
- Распределения событий и активных дней по пользователям, возвраты в другие дни, длины наблюдаемых историй.
- Популярность товаров, заполненность категорий/брендов, повторные user–item взаимодействия, изменения свойств одного товара.
- Долю покупок с наблюдаемой предшествующей активностью пользователя, отдельно — с прошлым взаимодействием с этим товаром; задержки от просмотра/корзины до покупки с явным правилом сопоставления.
- Объём и время вычислений, чтобы выбрать реалистичный бюджет последующих экспериментов.

Вывод каждого блока отделяет измеренные факты от возможных объяснений. Notebook показывает агрегаты и графики без отдельных пользовательских событий или идентификаторов. Если часть проверок не выполнена, она явно остаётся открытой.

## 2. Рабочая цель и окончательная заморозка протокола

Исходные альтернативы, рассмотренные в [target research](target-research/index.md):

- Конверсию после наблюдаемого просмотра товара: определить горизонт покупки, единицу прогноза и обработку повторных просмотров.
- Ранжирование следующего взаимодействия или покупки: определить момент прогноза, источник кандидатов, допустимые отрицательные примеры и критерий покрытия целевых товаров кандидатами.

До обучения зафиксировать границы накопления истории, train, validation и финального test, зрелость labels, обработку одинаковых timestamp и доступность свойств товаров. Случайное перемешивание событий не использовать как замену проверке будущего периода. Для одного месяца нельзя обещать полноценные длинные окна истории; при необходимости дополнительного месяца это отдельное решение.

Разбор схемы и качества может использовать весь месяц. Confirmation/final query-level targets и model metrics не использовались для выбора признаков, параметров или метода. Полный raw файл уже читался для ingestion/hash/EDA/source coverage; это ограничение exploratory дизайна раскрывается отдельно от strict-past feature contract.

## 3. Ручной baseline

Собрать простой ориентир и затем сильный CatBoost с ручными признаками на выбранной постановке. Измерять основную метрику, размер данных, время подготовки признаков и обучения, а также качество по группам с разной доступностью истории. Новые пользователи/товары определяются относительно доступной на момент прогноза истории, с оговоркой о начале наблюдения.

## 4. Выбрать исследовательскую гипотезу

Рабочая центральная ветвь016 — ограниченная типизированная grammar над проверенными агрегатами и автоматизация их расчёта. Её эксперимент ещё не выполнен и не подтвердил полезность. Альтернативы — LLM-guided search, затухание, последовательные и графовые представления — сохраняются в исследованиях, но не расширяют автоматически текущий бюджет. Основной контроль должен пройти bounded tuning019; два стартовых smoke-fit его не заменяют.

Для выбранного подхода записать проверяемую гипотезу, сильный контрольный метод, вычислительный бюджет, лимит попыток и критерий прекращения поиска. При заявлении пользы LLM нужен контроль без LLM при сопоставимом бюджете; при автоматическом подборе признаков их выбор выполняется на validation, а не на test.

## 5. Итоговый эксперимент

Зафиксировать решение до оценки на test. Сравнить с ручным baseline по одинаковым данным, целевым событиям, кандидатам и метрикам. Проверить, чем объясняется эффект, сколько ручной работы и вычислений потребовалось, где метод не работает. Отрицательный результат допустим, если протокол и выводы его поддерживают.

## Готовность первого этапа

EDA завершён, когда полный месяц обработан, результаты воспроизводятся командой из README, notebook валиден и его утверждения сверены с агрегатами. Техническая проверка успешного запуска не заменяет проверку смысла результатов. Обучение моделей и выбор метода не входят в этот этап.
