## В чём содержательная автоматизация и где ручной prior

Модуль действительно строит definitions, signatures, emitted schema и registries из parameterized template families; восемь готовых feature-JSON списков не являются его единственным входом. Opposite nominal entity projection выводится из grain role. Shared005 рассчитывает сгенерированные определения тем же reviewed vocabulary. Это реализуемая engineering contribution: автоматизация повторяемой операции schema/templates→legal programs→расчёт, с отделённым source verification.

При этом schema, semantics actions, event-time availability assumption,24/168h, bindings и static-I priorities заданы человеком; code отвергает изменённые bindings. Прочитанные008/009 development findings могли влиять на разработку гипотез. Поэтому корректно «numeric generation label-free при вручную зафиксированных priors», а не «метод разработан без знания outcomes». Dataset-specific bounded generator не становится generic relational framework от наличия typed AST. Минимальный пользовательский пример должен показывать настоящее API, один emitted registry, physical delta и существующий literal fixture без ignored approvals; fresh full rerun остаётся существующим018/reproduction gate.

[DFS2015](https://groups.csail.mit.edu/EVO-DesignOpt/groupWebSite/uploads/Site/DSAA_DSM_2015.pdf) разделяет relational feature synthesis и autotuned downstream modeling; текущая работа использует идею compositions/relationships, но не воспроизводит recursive DFS или всю Data Science Machine. [ExploreKit2016](https://people.eecs.berkeley.edu/~dawnsong/papers/icdm-2016.pdf), Figure1/Algorithm1, сочетает candidate generation, learned ranking по предыдущим datasets и wrapper evaluation/selection. [OpenFE2023](https://proceedings.mlr.press/v202/zhang23ay/zhang23ay.pdf) использует supervised FeatureBoost и candidate reduction. Эти primary mechanisms поддерживают разделение generation/selection/calculation, а не novelty или перенос опубликованных benchmark improvements на purchase ranking.

## Fairness, стоимость и ограниченная интерпретация

Fixed learner — осмысленный ablation: `fA=T(Dtrain,B∪A;λB)` сравнивается с `fB=T(Dtrain,B;λB)` при одинаковых population/weights/effective native parameters/trained iterations/scoring prefix/Q/C/fullY/ties. Это действие добавления конкретного representation при данном learner, не лучшая достижимая модель с этим набором. Негативный результат не опровергает возможность иного retuning; дополнительное tuning здесь не требуется и не разрешено. Одинаковые параметры также не обещают одинаковые learned splits или одинаковую fit RAM.

Два static-I и два random slots имеют одинаковый opportunity/physical-column cap, но не обязаны иметь одинаковый CPU: разные grains/distinct states и masks стоят по-разному. Collisions/recognized resource failures оплачиваются без refill. Поэтому «равный бюджет» означает одинаковые заранее ограниченные возможности и shared ceiling, а не тождественные actual CPU. На фактическом definition-only draw bundles различны; generic collision handling не является четырьмя дополнительно выполненными fits.

Shared source union рассчитывается один раз и его cost оплачивается один раз, вместе с independent oracle, failed attempts и owner SELF+reaped CHILDREN. Per-arm diagnostic costs не суммируются повторно поверх общего prefix. Стоимость ранее выбранного019 контроля — уже выполненная development history; её нужно раскрыть отдельно, не считать заново новым016 fit и не заявлять, что вся research procedure стоила только marginal016 time. Из existing ledger достаточно показать scope, known/censored/unknown cost и actual availability каждого arm. Ни wall×2, ни общий cache не доказывают CPU savings/human-hours. Нет основания добавлять timing experiment против intentionally naive SQL.

## Минимальная финальная формулировка без новой работы

«Мы реализовали ограниченную rule-based генерацию восьми legal feature bundles из вручную заданного typed contract. Заранее распределили четыре возможности между двумя static и двумя seeded-random bundles; рассчитали12 additions общим compiler и независимо проверили выбранные значения в указанном source scope. При неизменной bounded-tuned manual boosting procedure сравнили четыре B+3 модели и B, выбрав W по frozen development rule. Результаты относятся к этой процедуре, источнику и календарю; отдельная reporting-only heldout evaluation оценивает заранее frozen W−B».

Каждая завершённая часть предложения должна иметь собственный actual artifact/acceptance; пока source/model gates не завершены, используется будущее время. OldB row equality сохраняет ранее принятые значения, но не превращает sampled manual18 numeric proof в exhaustive B41 source proof.

Если completed valid comparison оставляет W=B, вывод — additions не вытеснили B по фиксированному правилу; generation/calculation evidence сохраняется. Это не equivalence/no-signal theorem. Если W=random, gain принадлежит mixed procedure; если W=I, выигрывает конкретный I, не семейство стратегий. При resource-incomplete comparison нельзя написать «все четыре проиграли», а integrity failure не является отрицательным качественным результатом. Winner на73 positive development queries и previous tuning history остаётся selected screening result: postselection bootstrap не удаляет этот bias. [Cawley–Talbot2010](https://www.jmlr.org/papers/v11/cawley10a.html). Reporting-only holdout может оценить frozen choice условно на моделях/датах, без adaptation/refit и без универсальной superiority.

**No-add outcome:** новых HYP, datasets, fits, metrics, operators или framework не требуется. В existing report/repro scope достаточно поправить union12→four B+3→W0/3 terminology, разделить evidence stages и complete/incomplete outcomes, раскрыть manual priors/development history и actual shared-cost accounting. Существующие source/model/external-lifetime/heldout-access gates не отменяются.
