# TLAB016: генерация типизированных программ до расчёта данных

15 октября 2026. Implemented **symbolic generator and tiny preflight only**; independent review pending. Реальные коллекции не читались, модели и native Pools не создавались. Это отдельный подготовительный этап центрального эксперимента016, а не его завершение.

[Новый модуль](../../scripts/feature_programs.py) имеет три функции: `generate_pool(contract, base_registry)`, `allocate_slots(pool)` и `registry_for_slot(pool, allocation, slot)`. Первая возвращает проверяемые программы и schema delta, вторая фиксирует выбор, третья выдаёт полный registry B+additions для разрешённого символического slot. Ни одна не выдаёт execution approval, не читает данные и не запускает SQL.

[Контракт](../../configs/features/automation-pool.json) содержит **вручную объявленные** роли и типы полей, наблюдаемые actions, causal policy, 24/168h windows, три parameterized template families и конкретные bindings. Шаблоны ActionVector, Breadth и CartTiming порождают восемь whole bundles L01–L08: создаются actual005 definitions и имена, opposite entity key выводится из typed user/item role. Восемь feature-JSON списков не хранятся готовыми. Это ограниченная rule-based генерация по schema/templates, без learned ranking, DFS recursion или inference смысла неизвестного поля. Новые action capabilities, произвольный SQL, operators и окна отвергаются до расчёта.

Typed/schema legality → semantic dedup against B/retrieval → emitted closure → pool digest → fixed allocation → full registry. Feature aliases сравниваются по grain/operator/action/window/projection, независимо от имени. `D(item,purchase,168h,user_id)` объявлен alias fixed v1 retrieval score, включая recent-only candidates. Category-mask и72h-coverage bundles отсутствуют: первый mask повторяет B, а второй coverage требует отдельного context/projection решения. Все24/168coverage уже имеются в B.

Для каждого bundle registry сохраняет все18base definitions и добавляет два или три core definitions. Символическое описание физических model columns повторяет публичный005 emission contract: core values, coverage, ratio supports/values и automatic missing flags. Delta относительно full41-model-input B равна ровно3. Для recency bundle это value+companion count/distinct+automatic missing; physical SQL order может отличаться от человекочитаемого `(recency, missing, companion)`. Выдаваемый model order сохраняет B41 первым, additions последними; будущий training loader обязан закрепить и проверить именно этот порядок, а не полагаться на порядок SQL `SELECT *`.

Static I1=L02, I2=L06. Random R1/R2 — `python.random.Random(2026).choices(sorted pool,k=2)`, with replacement; actual definition-only draw дал L01/L05. Python version и state hashes входят в allocation identity. Whole-bundle collision среди **всех** I/R slots сохраняет consumed opportunity без redraw/refill, native fits при allocation равны0. На текущем draw четыре bundles различны:11newcores+1autoBOOLEANmask =12newphysical columns. Алгоритм не тратит бесплатный proxy fit и не перезапускает random seed после результата.

`pool_id` связывает declared schema/context/base registry/bindings/generated closure. Это **не полный execution identity**: источник, versioned protocol, actual Q/C/Y/feature lineage, final019 training population/settings/trained_iterations/scoringprefix и две decision clocks должны быть отдельно закреплены внешним reviewed runner. Current symbolic base41/v1 policy не является adapter для переименованной raw source schema или разрешением применять unsupported018 verifier к новым definitions.

Восемь targeted tests проходят: generation без SQL, unsupported capability/type/operator/window rejection, semantic alias после rename, digest/allocation tampering, collision/no-refill, exact selected12-column compiler delta, literal handgold+independent row-list oracle, NULL/non-NULL projected distinct, lower boundary, pre-source/future/global peers, old8d recency, emptyC и emptyQ typed schema. Base fixture9events+4Q+5C=18rows; расширенный fixture25rows. Численно рассчитываются только frozen selected L02/L06/L01/L05; остальные четыре closures проверяются символически. Y table отсутствует, native fits и Pools0. Numeric B18 verification этим тестом не становится exhaustive: assertions относятся к новым выбранным additions и physical/key boundary.
