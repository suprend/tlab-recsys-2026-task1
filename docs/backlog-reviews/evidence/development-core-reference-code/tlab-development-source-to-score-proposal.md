# Minimal018 additive development replay — concrete API proposal

**One Oct22 anchor,2000 past-sampled queries, full fixed C, B45 plus selected R2 extra3, and fixed B41/W44 raw scores.** No fit, metric/evaluator, query-level Y relation, dummy labels, reserved25–31 scope or439 consumer. This is mechanical post-selection development replay; selected models used22–23 feedback, so it is not a new deployable-at-Oct22/generalization claim.

## Proposed repository files and callable

- `scripts/reproduce_development_slice.py`: sole new implementation file, lazy native imports, pure exact-request/schema checks, one fixed one-day core adapter, exclusive failure/report/export namespace. Existing accepted cores/configs/015 pins stay unchanged.
- `tests/test_reproduce_development_slice.py`: focused pure/mock orchestration/admission tests first; a separately bounded tiny SQL fixture only after Root decides its exact scope.
- `docs/experiments/development-source-to-score.md`: real implemented callable/command only after implementation and review; input/output/limits and reproduction gap. No CLI command is claimed available by this proposal.

Planned API: `run_slice(request_path, expected_request_sha, *, started_monotonic)` performs one future externally reviewed operation and returns an unaccepted report; it grants nothing. A smaller `build_and_score(con, request, *, cores, load_model, check, stage)` boundary permits pure/mock tests and a later tiny fixture without opening the actual DB or models. The final external driver reuses accepted generic V6 supervision rather than adding a framework. Exact once namespace and future resource request are decided by Root; candidate180CPU/360wall/4GiB is a proposal, not authority.

## Portable request and output schema

Request vocabulary: `version, scope, execution_id, source, protocol, manual_registry, pool_contract, models, fingerprints, resources, output_directory`. All file references are normalized project-relative `{path,sha256}`. `source` binds the explicit staged external prefix receipt plus new DB and canonical-input manifest; source DB SHA4168068b05a5f7033876c05427037732322abe77fd2f97eef3ceca59d42ba786 and canonicalCSV SHAe58ae129792ed9ce848644343d75698a506c0c2bcc5b2da6a30db283e85db4c2 remain distinct. The current Root receipt is TMP-only; an eventual portable staged copy is an external preparation operation, not a writer/approval action here. Do not reinterpret new DB as byte/logically equal to old DB.

`models` holds exact B/W modelrefs, feature_names,300 trained/300 scored,26000 population and effective parameters, bound to existing accepted model metadata; it is an external supplied replay binding, not a new439/heldout acceptance. Code closure includes the final new runner plus transitive imported project scripts, uv.lock/pyproject/interpreter environment and fixed configs. Conservative AST-only import closure currently has14 project modules; its pinned proposal lists them. Uncalled training helpers may be imported transitively but are never invoked.

Outputs: `request-snapshot.json`, `consumed.json`, `queries.parquet`, `candidates.parquet`, `base-features.parquet`, `extra-features.parquet`, `B-scores.parquet`, `W-scores.parquet`, `report.json`, exact output/manifest refs and failure file on error. Score schema is `(query_id VARCHAR, product_id BIGINT, raw_score DOUBLE)`; no targets/metrics. Report includes actual Q/C/feature counts, complete declared source/model/code identity, stage wall/CPU/RSS/spill observations, actual native-call counter, fit0/metric0/Y0, original bounds and pending-independent-acceptance status. Failed namespace cannot retry under a new directory or silently shrink2000Q.

## Critical limits and comparison

Existing `anchor_pilot.run` assumes unavailable `ingest_metadata`; use the lower-level API. Existing training/model_data loaders open Y; do not use them or dummy Y. Existing heldout convenience APIs are intentionally unavailable for Oct22; do not patch or relabel them. Loader paths must be project-relative and source outputs must retain exact integer types and explicit nullable fields. Engine memory and sampled process RSS are different limits; stage callbacks alone cannot stop a blocked native call, so existing external supervision remains required.

If Root adds an independently bounded mechanical comparison with old predictions, join by(query_id,product_id). Old NPZ groups refer to all4000 selection queries canonically sorted byquery_id before filteringOct22; fresh groups refer only to2000 Q. Never zip group indexes or compare arrays positionally. Old Q/F/NPZ loads and any all-row comparison are paid additional work requiring exact inputs/scope; no metric/look/refit follows. Differences are retained rather than retuned away. This one-day existing-runtime slice does not establish a clean-environment/full retraining reproduction or complete018/015.
