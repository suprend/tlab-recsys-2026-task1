# Wave035 FIRST B: ограничить обещание ускорения полным маршрутом

**Результат: 0 новых механизмов; refine HYP046/round073, не новый ID.** Public `build_day` уже один раз на anchor создаёт48 физических колонок и экспортирует B45/extra. Поэтому повторное использование автоматических агрегатов между B/W нельзя повторно записать в экономию. Наблюдаемая статическая повторность другая: `compare_two` вызывает `prepare_matrix` отдельно для train/selection каждого arm; B41-prefix реконструируется, а освобождение матрицы/Pool/model между ветвями ограничивает совместный lifetime. Это кодовый факт, не измеренная дороговизна.

**Механизм.** Будущее сохранение общего canonical float32 B41/key/label/weight transport один раз с последующей именованной проекцией B41/W44 — частный paid-materialization вариант существующего HYP046. Source/manifest authentication, strict-past semantics, fullY, NULL/NaN masks, exact order, два свежих fit и все конечные outputs сохраняются. Дополнительные запись/чтение, копирование в W и проверка могут стоить больше повторного SQL; удержание обеих матриц может проиграть по RSS. Предложение не меняет текущий маршрут.

**Prediction.** Экономия возможна только если полная цена build+verification+reads+projection+cleanup меньше заменяемой подготовки. Для неперекрывающихся CPU-частей одного законченного запуска `T_new=T−d+K+R`; даже бесплатное устранение всей части d даёт максимум `T/(T−d)`. Нельзя оценить d/T из source609.92CPU и исторических B344.824/W351.779CPU: это разные операции/запуски. CPU-bound также не доказывает wall speedup или capacity. Новых timings/результата Root-run здесь нет.

Strong control — нынешний optimized loader; treatment — paid shared transport. Несовпадение отвергает адаптацию; отсутствие экономии/RSS-регрессия прекращает её. Это дешёвое отсеивание duplicate optimization, не prerequisite018/015, не quality/human-hours claim.
