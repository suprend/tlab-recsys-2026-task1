**1. REFINE → MERGE: потолок выбранной top-K метрики, TLAB-004/006/007; диагностика HYP-004/053/061–062.** Формулы автора корректны для бинарного distinct полного Y при y>0: oracle Recall@K=min(K,h)/y; oracle NDCG@K=D(min(K,h))/D(min(K,y)). Они ограничивают фактический ranker на том же C, но не предсказывают причинную пользу изменения retrieval. Веса и population должны совпадать с отчётной метрикой: conditional query-macro, all-mature zero-convention и user-macro нельзя смешивать. Mature empty-Y остаётся undefined на уровне query, censored вообще исключается; нулевое заполнение допускается только объявленным estimand (`ranking_metrics.py:111–178`).

Ближайший тест: literal y>20/h>20, off-C/cold miss, C=∅, mature empty-Y и отдельно censored. Исчерпывать лишь действительно малые перестановки, а не 30!; большой-Y пример проверяется независимой формулой. Контргипотеза h≤K делает Recall-уточнение численно пустым; NDCG gap всё равно не является гарантированно устранимым. Принимать диагностический контракт только при совпадении двух независимых вычислений и сохранении исходного знаменателя; реальные outputs — отдельный UNRUN этап. Это уточнение измерения, не новый HYP.

**2. REFINE → MERGE: freshness внутри cutoff ties, HYP-031.** Механизм ограничен заменами среди равных buyer-count на границе P200; вне границы сохранение membership проверяемо. Нет ties, recent-overlap или шумная freshness способны полностью обнулить эффект.

Tiny quota2 контроль должен включать более высокий count, несколько равных count с разными strict-past timestamps и overlap с recent. Важная граница: неизменный C позволяет остановить **coverage-screen**, но не доказывает равенство downstream features — `popular_source_rank` может измениться у сохранившихся товаров (`candidate_pilot.py:66–97`). Новый источник требует версии; прежняя fixed-C feature ablation остаётся отдельной. Не выбирать удачный tie-rule на уже открытом final. UNKNOWN scans/RSS не превращать в «дешёвый» факт.
