## Новая development-модель с выбором числа деревьев

Отдельная [development-команда](docs/experiments/development-training.md#обычная-команда-нового-development-training) `python -B -m scripts.train_development` принимает явно принятые train/validation collections, обязательный `--max-iterations` и ресурсные параметры. Каждый запуск обучает одну новую модель и выбирает её собственный лучший наблюдаемый validation prefix внутри потолка; сохраняет полную/выбранную модели, кривую и reload/prefix parity. Это source implementation обычного caller; на TMP-байтах прошли [12 CODE-unit проверок](docs/backlog-reviews/development-cli-code-acceptance.md) с FakeML/selector/accepted-data I/O. Один [native helper normal-path toy запуск](docs/backlog-reviews/native-helper-engineering-result.md) принят: один fit обучил 8 деревьев; отдельная выбранная копия с 1 деревом прошла save/reload с сохранением score parity, исходная модель сохранила 8 деревьев. Один [обычный warm-backend native CLI E2E запуск](docs/backlog-reviews/post-audit-native-result.md) принят на синтетическом примере: один исходный fit на 8 деревьях, первый префикс плоской кривой, save/reload parity с максимальной разницей 0. Два [инструментированных случая из свежих Python-интерпретаторов](docs/backlog-reviews/cold-cli-lifecycle-result.md) приняты: успешный CLI fit8/selected1/save-reload parity0 и остановка первого реального native callback с ожидаемым failed report. Это не OS cold cache или полный fault coverage; неплоские/почти равные native-кривые остаются UNRUN. Пользователь разрешил необходимое локальное обучение без отдельного вопроса на каждый запуск; для каждой операции сохраняются выбранные конечные ресурсные границы. Команда не меняет исторический fixed-300 replay и не выдаёт ML разрешения.

Скрипт читает архив непосредственно: предварительная распаковка в CSV не требуется. Исходный файл остаётся неизменным. Локальная DuckDB и результаты расчёта исключены из Git. Открыть [notebooks/01_eda.ipynb](notebooks/01_eda.ipynb) можно в Jupyter-совместимом редакторе с окружением `.venv`; notebook предназначен для просмотра агрегатов, графиков и интерпретации EDA.

Для первого запуска используем Mac с 36 ГБ RAM. Будущие серии обучения можно перенести на Windows-ПК с 32 ГБ RAM и RTX 3070 после замера времени; GPU для этого EDA не нужен. Размер архива не равен объёму оперативной памяти, необходимому анализу: запросы используют промежуточные данные на диске.

## Границы исследования

Одна строка датасета — наблюдаемое действие, а не показ товара в рекомендательной выдаче. Отсутствие покупки нельзя автоматически считать отрицательным показом. История ограничена одним месяцем; отсутствие более ранних событий не доказывает, что пользователь новый.

В Git сохраняем код, notebook с агрегированными выводами, протокол и зависимости. Исходные события, отдельные пользовательские истории, идентификаторы пользователей и сессий в выводах, модели, локальные пути и секреты не публикуем. Данные восстанавливаются из авторского источника; репозиторий их не распространяет.

Рабочая постановка и следующие решения описаны в [плане экспериментов](docs/experiment-plan.md); protocol/model locks приняты до [неизменённой отложенной проверки](docs/backlog-reviews/real015-heldout-results.md). Контекст выбора курсовой и личные заметки остаются отдельно от этого репозитория.
