# T-Lab RecSys 2026: автоматизация признаков и кандидатов

**[Читать актуальный отчёт в PDF](docs/writeup/latex-report/main.pdf).** Исходник: [main.tex](docs/writeup/latex-report/main.tex), сборка по [инструкции](docs/writeup/latex-report/README.md). Файлы с именем `REPORT.pdf` содержат предыдущие редакции.

[Карта отчёта и проверок](docs/writeup/README.md) помогает найти актуальные материалы и отличить их от истории.

## Что исследовали

**REES46: контролируемое сравнение признаков.** Для новых пользователю товаров подготовлена база CatBoost с признаками активности, популярности, конверсии и предпочтений. Совместный набор LLM-агента и автоматических агрегатов DFS улучшил её примерно на 2% по NDCG@20 на новом тестовом периоде 2020 года. Отобранное предложение агента не достигло практического порога, отобранный DFS не улучшил базу. В [дополнительном разборе уже просмотренного теста](docs/writeup/agent-test-ablation-2026-10-25/README.md) весь набор агента без DFS также дал около 2%; интервалы добавочного эффекта DFS включают ноль. Этот разбор не является новым независимым тестом.

**OTTO: развитие агентного решения.** В трёх продолжениях агент улучшал уже созданную им систему: сначала менял кандидатов и признаки, затем только признаки. Способ обучения ранкера сохранялся; оценка на части теста Kaggle (private) выросла суммарно примерно на 2.7%. Это адаптивный поиск с повторным просмотром оценок, а не независимый итоговый тест. Доступная информация и кандидаты отличаются от строгой постановки REES46.

Победа над бустингом не обязательна по [условию задачи](docs/task1-requirements.md): важны корректное сравнение и анализ ограничений.

## Проверить выводы без данных

Для сверки сохранённых таблиц, планов, контрольных сумм кода и последующих проверок достаточно стандартной библиотеки Python:

```bash
python3 -I scripts/check_report.py
python3 -I -m unittest discover -s tests -p test_check_report.py
```

Эти же команды включены в [автоматическую проверку GitHub](.github/workflows/checks.yml).

Скрипт не читает локальные данные и не повторяет обучение или bootstrap. Он проверяет, согласуются ли сохранённые материалы между собой. Как повторить вычисления, описано ниже.

[Маршрут личной проверки](docs/writeup/human-review.md) связывает ключевые утверждения с конкретными источниками и поясняет, что в них проверить.

## Воспроизвести

Нужен Python 3.12. Из корня репозитория:

```bash
uv sync --locked
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
```

Тесты используют небольшие синтетические данные. Они проверяют реализацию, но не воспроизводят качество на полном датасете.

- [REES46: данные, признаки, обучение и тест 2020](docs/task1-reproduce.md).
- [OTTO: замороженные наборы, историческая сборка F4 и финальные модели](docs/otto-reproduce.md).
- [Ручные признаки REES46 и их назначение](docs/task1-baseline-features.md).

Сырые данные и тяжёлые артефакты не входят в Git. Главную таблицу REES46 повторяют в отдельном клоне, сохраняя результаты автора. Дополнительные разборы требуют сохранённых локальных артефактов; ограничения указаны в [маршрутах REES46](docs/task1-reproduce.md#выберите-маршрут). Повтор LLM-генерации даёт новый эксперимент и требует платного CLI; замороженные SQL-наборы позволяют проверить уже найденные признаки без новых вызовов LLM. Полный прогон на чистом клоне не проверен. В инструкциях отмечены проверенные этапы и ограничения ресурсов.

| `scripts/otto*.py` | подготовка OTTO, агент, обучение, три продолжения |

| `scripts/rees_sensitivity.py`, `scripts/rees_secondary.py` | последующие проверки устойчивости и дополнительных метрик |
