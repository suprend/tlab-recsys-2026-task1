# T-Lab RecSys 2026, задача 1: обыгрывает ли автоматическая генерация признаков ручной бустинг

**Сдача:** [отчёт в PDF](docs/writeup/REPORT.pdf) (7 страниц) и [в Markdown](docs/writeup/REPORT.md).

**Ответ.** Мы выбрали постановку: рекомендовать в интернет-магазине REES46 товары, новые для пользователя. Ручную базу (CatBoost на 80 признаках, настроенный по одному гиперпараметру за раз) мы сравнили с двумя способами строить признаки автоматически: LLM-агентом, который пишет SQL, и сеткой оконных агрегатов DFS. Из вариантов с автоматическими признаками базу обыграла только вся автоматика без отбора: все колонки агента и DFS поверх ручных признаков. На свежем тесте 2020 она дала +2.0% NDCG@20 к базе (+0.0030), доверительный интервал (CI) выше нуля в обоих запусках с разным зерном [по протоколу]. Гипотезу о ней мы записали после теста 2019 и проверили один раз. Прирост лучшего признака агента ниже порога шума ≈0.001, у лучших колонок DFS прироста нет, а замена ручных признаков автоматикой при настройках базы дала −0.77% на тесте 2020 [по протоколу]. На других наборах колонки агента подняли базу на отложенных неделях Tinkoff и СберМаркета [holdout с отклонением], но на Kaggle у Tinkoff оказались ниже базы, а у H&M не различены [описательно]. Метка стоит у каждого вывода.

## Как воспроизвести

Работу можно проверить на трёх уровнях, от быстрого к полному.

**Без данных.** Числа тестов REES46 можно сверить по итогам в Git: `task1/runs/test.json` (2019) и `task1/runs/replication-2020/test.json` (2020). Путь от каждого числа к файлу указан в [сводке чисел](docs/writeup/facts.md). У остальных чисел источник тоже указан в сводке, часть источников лежит в локальных файлах вне Git.

**Юнит-тесты.** Нужен Python 3.12, зависимости закреплены в `uv.lock`:

```bash
uv sync --locked
```

Тесты запускаются из корня репозитория. Совету нужна переменная периода, его прогон идёт около 5 минут.

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
```

```bash
TASK1_PERIOD=2020 .venv/bin/python -m unittest discover -s council/tests -t .
```

Два модуля совета относятся к периоду 2019 и в этом прогоне пропускаются. Их запуск:

```bash
.venv/bin/python -m unittest council.tests.test_side_task1 council.tests.test_side_task1_b
```

**Прогон REES46.** Сырые данные и артефакты в Git не входят. Прогону нужны сырые данные (откуда их брать и как сверить файлы, сказано в [docs/data.md](docs/data.md)), ≈25 ГиБ диска, до 29.6 ГБ памяти и CLI `claude` для агента. Вызовы `claude` платные. Шаги прогона, переноса на H&M, Tinkoff и СберМаркет и совета агентов описаны в [docs/task1-reproduce.md](docs/task1-reproduce.md), там же [время шагов](docs/task1-reproduce.md#время-шагов). OTTO-1, OTTO-2 и OTTO-3 воспроизводятся по [docs/otto-reproduce.md](docs/otto-reproduce.md), ручная база H&M по [docs/hm-reproduce.md](docs/hm-reproduce.md).
